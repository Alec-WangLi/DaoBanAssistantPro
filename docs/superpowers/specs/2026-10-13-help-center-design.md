# 使用帮助改成两层（设计）

- 日期：2026-10-13
- 起因：用户 v0.11.16 真机测完之后提的。原话：
  「随着咱们 APP 不断更新，加了这么多新功能……单靠使用帮助界面的那个功能简介，好像不足以覆盖
  我们 APP 里面每一个界面、每一个窗口里的功能说明。所以我的想法是，能不能把『使用帮助』这一页
  再做成一个功能块？也就是说，点进去后，一开始是一个整体的功能简介。下面还有入口，进到二级
  页面里去看每一个功能块的详细用法。」
- **用户拍板（2026-10-13，五轮）**：
  1. 用户是**带着一句话来**的，不是带着模块名来的。原话：「用户问我的，说不知道从哪下手，
     比如说他们每个月的排班表不一样，他不知道怎么弄了……**其实根本不需要加什么新功能，
     我们本来的排班就能实现啊。**」——所以缺的是**找得着**，不是功能。
  2. 卡住那一刻的场景：「对着某一节发呆」。
  3. 但再问一层，发呆的性质是：「**我想干的事不知道去哪一节办**」——不是看不懂某个词。
  4. 一级页结构：「点开使用帮助，首先是 APP 的整体简介。下面还有一个二级入口按钮，说明你可能
     会遇到的一些问题，可以进这里找一下如何解决。」**九条功能块说明留在第一级**，原话：
     「一级界面，你对各个功能块也是一个简介嘛，又不是让你给它详细化。」
  5. **编辑页不加任何入口**。原话：「编辑页标题栏那个『?』应该取消掉，所有使用上的问题，
     应该都来这个使用帮助里找就对了。**防止我们其他页面越来越臃肿，功能乱七八糟的。**」
  6. 形态：**改成整页**（不再是弹窗）。
- 影响版本：从 v0.11.17 起。

---

## 1. 现状与它为什么不够

`使用帮助` 今天是一个 `GlassDialog`（`features/profile/app_dialogs.dart:363`），里面九条
按功能块写的条目（日历 / 排班管理 / 闹钟 / 待办 / 桌面小组件 / 外观 / 横竖屏 / 权限 / 更新），
每条 2~6 个圆点，入口只有「我的 → 使用帮助」一处。

**它有三个问题，其中第三个是这一版真正的理由。**

### 1.1 它是按模块名组织的，用户不是这么想的

九条的标题是模块名（「日历」「排班管理」「闹钟」）。用户手里那句话是「我这个月跟下个月不一样」
「明天交班要提醒我」——他没有「排班管理」这个词，也不会去那儿翻。

### 1.2 有些答案根本不在同一个模块里

「每月排班不一样」的答案是**跨模块**的：一半在编辑页「周期设置」那张卡的分段器上（周期 / 按月），
一半在**排班管理页**的「排班时段」里（哪段日子归哪套）。按模块分的目录，天然装不下这类问题。

### 1.3 它已经落后于 App 了（这一条是量出来的，不是推的）

| 帮助里写的 | 实际 | 出处 |
|---|---|---|
| 「一个班次最多挂 **6** 条闹钟」 | **10** 条 | v0.11.1 提的上限，`maxAlarmsPerShift = 10`；文案没跟 |
| （没有「重复待办」） | v0.9.11 就有 | `guideTodoDesc` 四条里一个字都没有 |
| （没有「字体大小」） | v0.11.12 就有 | `guideAppearanceDesc` 三条里没有它 |
| （没有「按月排班」） | v0.11.15 就有 | `guideSchedDesc` 提到了时段与法定节假日，没提按月 |
| （没有「待办自动归档」） | v0.11.3 / v0.11.4 就有 | 同上 |
| 「零点班的响铃排在上班前 1 小时」 | 只是三档落点里的**一档** | v0.11.1 之后是前一天 / 当天 / 次日，判据是 `alarmDayAnchor` |

「一个班次最多挂 10 个闹钟」那句本身有护栏（`l10n.dart:559` 的注释点名要跟
`maxAlarmsPerShift` 一致），**但那条护栏只管告警文案 `alarmLimitReached`，没管帮助**。

## 2. 这一版要什么 / 不要什么

**要**：用户带着「我想办一件事」或「它不对劲」进来时，能在**一到两屏之内**找到那一条，
并且那条告诉他**去哪一页、点什么**。

**不要**（用户明确否掉的）：

- ❌ **不在编辑页/日历页上加任何「?」或节级入口**。所有使用上的问题只从「使用帮助」一处进。
  理由是他自己给的：防止其他页面越来越臃肿。
- ❌ **不把九条功能块说明挪进第二层**。它们留在第一级，且**保持简介粒度**，不许趁机写厚。
- ❌ 不趁这一版重做「使用帮助」的视觉（玻璃配方、令牌、排版规格照旧，只是从弹窗变成整页）。
- ⚠️ **代码里那个「编辑页标题栏的『?』」根本不存在** —— 它是 2026-10-13 讨论时我用视觉工装
  临时渲出来给他挑的一版草图（`work/mock/A_page_level.png`，gitignored），渲完就还原了，仓库里从来
  没有过这东西。他那句话的正确读法是**「不要加」**。这一版不新增任何页内帮助入口。

**反目标**（做成了也算失败）：

- 第二层变成又一份「按功能块排列的说明书」。它必须**按用户的诉求排列**。
- 第二层条目**互相指路**（「详见『临时改班』那一条」这种）。每一条自己把话说完 ——
  互相指路会把一份清单变成一张网，用户点两下就迷路。
  **注意这条只管第二层内部**：一条两级通用的话（比如「横屏下日历是左右两栏」）只要
  自己说完整，就不算指路。

## 3. 结构

### 3.1 第一级：使用帮助（整页）

从「我的 → 使用帮助」`Navigator.push` 一个整页（`Scaffold` + `AppBar`），页内三段：

1. **整体简介**（新写）：这个 App 是干什么的、由哪几块组成。**一小段，不是目录**。
2. **九条功能块简介**：内容搬过来，排版沿用现有的图标 + 标题 + 圆点条目。
   **这一版要做两类补正（用户 2026-10-13 拍板：两类都做）**：
   - **改事实错**：「一个班次最多挂 6 条闹钟」→ 10 条；零点班那句从「只讲一档」改准（见 §1.3）。
   - **补缺席的功能**：「重复待办」「字体大小」「按月排班」「待办自动归档」这四个功能
     现在在帮助里**一个字都没有**，各补一行。
   **仍然保持简介粒度**：补的是「有这么个功能、在哪儿」，**不是「怎么用」** ——
   怎么用归第二层。比如补的是「待办可以设成每周三自动出现」，不是整套重复规则怎么定。
3. **入口**：一个显眼的按钮，进第二层。文案要说清「里面是什么」而不是「点我」——
   例如「不知道怎么做？进来找一找」。**具体措辞是 builder 的事（中英各一份）。**

### 3.2 第二级：遇到问题怎么解决（整页）

在第一级之上再 `Navigator.push` 一个整页。页内是**两组**，组内再用小标题分段
（清单二十多条，不分段一屏扫不完）：

- **我想办一件事**（用户带着诉求来的）——小标题按 `排班 / 临时改班 / 闹钟 / 待办 / 外观与设置` 分。
  §4 草案里那个「其他」组**不单独立组**：「字太小」「想省电」「想从头来一遍」本来就是
  「我要改成别的样子」，姿态与这一组一致，归进来即可。
- **它不对劲**（用户带着症状来的）

**两组分开摆是有理由的**：前者要的是「去哪一步」，后者要的是「逐条对症状」；混在一起会互相冲淡。

### 3.3 二级页里那一条长什么样

一条 = **一句用户的话（用他的说法，不是我们的术语）** + **几句话说清怎么做** + **「在哪一页、点什么」**。

### 3.4 不做「一键跳过去」——**这是本设计里最需要复核的一条判断**

「这条点一下直接带我过去」看着更好，代价不成比例：帮助是压在栈上的页，要先 pop 再 push 到目标页；
目标还常常不是一整页而是一个需要额外参数的弹层（「调整班次」要知道改哪一天、「排班时段」要知道
是哪套方案）；用户跳走之后回不来，反而更晕。

**所以这一版只写清「去哪一页、点什么」**，条目本身不可点（或点了只是展开/收起）。
如果用户看完仍然找不到，那是文案的问题，不是缺跳转。

### 3.5 不做搜索——同上，先摆出来给用户复核

二十来条分两组、一屏能扫完。搜索要求用户先想出一个词，而他正是**想不出词**才来这儿的。

## 4. 第二层的内容草案

> 这一份是 2026-10-13 与用户逐条对过的：他给了两条真实的（「每月不一样」「不知道在哪调班」），
> 我按 App 现有能力倒推补了其余的，他的回复是「基本对」。**最终条目由 builder 定稿**，
> 下面这一份是下限（不许比它少），加条要按 §5 的规矩核事实。

**我想办一件事**

*排班*
- 我这个月跟下个月不一样 → 编辑页「周期设置」上方的分段器切到「按月」；或者 排班管理 →「排班时段」
- 我们跟着法定节假日休、没有固定轮转 → 编辑页「跟随法定节假日（无班次）」
- 我们上 12 休 24 这种不规则的 → 「周期设置」，一天一天排
- 我们班组从哪天开始、怎么跟别的班组错开 → 「班组设置」；对不上会提示撞班、能一键均分
- 我想看别的班组那天上什么班 → 「班组设置」里填班组名
- 我这套排班只用一段时间，之后换另一套 → 排班管理 →「排班时段」
- 这套排班我以后还要用 → 编辑页右上角「存为模板」

*临时改班*
- 这天我请假、或者跟同事换了班 → 日历上点底栏信息卡那行班次，或长按格子拖选一段
- 改错了想改回去 → 那个选择层里有「恢复轮转」

*闹钟*
- 一个班想响两次（起床一次、出门一次）→ 班次里的「联动闹钟」，一个班最多 10 条
- 夜班要提前叫我 → 也是在班次的「联动闹钟」里，把响铃钟点填成你要的时间
- 零点班配 23:00，到底响在哪天 → 列表里写着「前一天」/「次日」，那是算出来的
- 哪天我不想被吵 → 闹钟页单独关那一天
- 早上想多躺十分钟 → 我的 → 闹钟 → 贪睡时长
- 想用自己手机里的歌、或者只想要震动 → 我的 → 闹钟 → 铃声
- 睡前想确认明天几点响 → 闹钟页「未来 30 天」

*待办*
- 明天交班要提醒我 → 新建待办，时间 + 「提醒」
- 每周三开会，不想每周手填一遍 → 新建待办时把「重复」选上
- 到点只想要通知、不要全屏闹钟 → 那条待办的「联动闹钟」关掉
- 做完的不想在列表里碍眼 → 它会自己收进底部「已完成 N 条」

*外观与设置*
- 字太小 → 我的 → 外观 → 字体大小
- 想换深色 / 主题色 / 想用英文 → 我的 → 外观
- 手机发热、费电 → 我的 → 外观 → 关掉「液态玻璃」
- 想从头来一遍 → 我的 → 清空重置
- 换了手机，怎么把排班搬过去 → **实话：目前不支持**。数据只存在这台手机上
  （没有云同步、也没有导出），换机要重新排一遍。

**它不对劲**

- 闹钟到点只响、不弹响铃界面 → 我的 → 权限；小米还要单独开「后台弹出界面」与「锁屏显示」
- 重启手机后闹钟没恢复 → 权限里的「自启动」
- 桌面小组件还是升级前的样子 → 先打开一次 App
- 小米桌面找不到小组件在哪加 → 长按桌面空白处 → 支持小部件的应用 → 安卓小部件
- 日历上整月没有班次 / 某几天突然没了 → 排班管理 →「排班时段」，看那几天归哪套（也可能是「无」）
- 横屏、平板、车机上日历变成了左右两栏 → **这是正常的**：宽屏下左边是日期网格、
  右边是当天详情；窗口很矮（高不到 480dp）时只显示当天那张卡，因为那个尺寸下网格看不清

## 5. 约束

1. **中英双语**，照旧只有 `core/l10n.dart` 一处写文案。
2. **事实必须与实现一致**。这一版的起因之一就是文案漂了（§1.3）。凡条目里出现**数字**
   （10 条闹钟 / 30 天 / 5 种主色调 / 30 分钟贪睡 / 100 条归档上限 / ±3 个月），
   一律对着实现核一遍。
3. **新增一条护栏**（与仓库既有的 `changelog_window_test.dart` 同一套路，扫源码）：
   帮助文案里的上限数字与实现常量一致 —— 至少覆盖「每个班次最多 N 条闹钟」这一条
   （它就是实际漂过的那一条）。**护栏必须反向验证过**（把帮助改回 6，它得红）。
4. **设计语言照旧**：令牌、玻璃配方、排版角色全部沿用，不新造。整页的骨架照抄仓库里
   已有的整页（`schedule_management_screen.dart` 一类）而不是自创。
5. **新界面必须进视觉工装的屏单**（`app/tool/visual/visual_screens.dart`）：第一级、第二级
   各至少一屏，含浅色 / 深色 / 英文 / 小窗。
6. 「我的」页那一行「使用帮助」的副标题（`L10n.usageGuideSubtitle`）要跟着改：
   点开之后是整页了，副标题不该再暗示是个弹窗。
7. 首启那份「开始使用」末尾指路那句（`L10n.gettingStartedMore`）写的路径仍然成立，不必改；
   但如果第一级的入口措辞变了，两处要一起读一遍。

## 6. 留给 builder 的（我的判断，可推翻）

- **不做搜索**（§3.5）——判断依据：二十来条分组后一屏可扫，而搜索要求用户先有词。
- **不做一键跳转**（§3.4）——理由同上。
- **第二级是整页而不是弹窗**：弹窗叠弹窗的层级会乱，而且清单要滚。
- 二级页每条**默认展开**（不折叠）：一屏能扫完的前提下，折叠只会多一次点击。
  若条目写长之后一屏放不下，再考虑「标题 + 点开看详情」。
- 一级页的九条**保持现有图标 + 圆点的配方**，不换形态。

## 7. 复核过的问题与结论（2026-10-13）

一份全新的 builder 复核（另一个上下文读完本文档 + 核过代码）报了六条，逐条落定：

1. **第一级的「补正」补到什么程度** → **用户拍板：两类都做**（既有事实错 + 四个缺席功能各补一行），
   但**仍是简介粒度**。见 §3.1 第 2 条。
2. **第二层的骨架** → **两组**，组内用小标题分段；草案里那个「其他」不单独立组，
   归进「我想办一件事」的「外观与设置」段（见 §3.2 / §4）。
3. **「我的」页那行「桌面小组件」留不留** → **用户拍板：留着，但改成跳进使用帮助**
   （不再各弹一份）。于是 `showWidgetGuideDialog` 不再有自己的内容，
   `guideWidgetDesc` 只剩「使用帮助」一个消费者，`35_widget_guide` 那条屏单也要跟着改。
4. **§2 反目标与草案里那条「横屏…见第一级那一条」打架** → 已改：反目标只管
   **第二层内部互相指路**；那条本身重写成一句自洽的话，挪进「它不对劲」（见 §4）。
5. **「换了手机怎么搬过去」写不写** → **用户拍板：写，明说暂不支持**（见 §4）。
6. **「编辑页标题栏那个『?』」在代码里不存在** → 已澄清：那是讨论时的临时出图，不是现存代码；
   正确读法是「不要加」。见 §2。

**仍然留给 builder 定的**（都是可以自己拍、且推翻成本很低的）：搜索不做、一键跳转不做、
第二级是整页、条目默认展开、第一级九条保持现有图标 + 圆点的配方。
