# 可编辑与可点文字的可见性统一（设计）

- 日期：2026-10-26
- 影响版本：下一测试版 `0.12.4+179`（X.Y 由用户定；本轮只动末位与 build）
- 起因：用户 v0.12.3 真机测完反馈的第一条，原话：
  「班表里面的多个班组，现在默认都是一班、二班、三班、四班，能不能改成甲、乙、丙、丁，
  或者自定义之类的？多几个模板嘛。」
  用户自己随后定位到真正的病根：
  「主要是为什么之前感觉好像一班、二班、三班、四班是固定的？因为你这个就不像个编辑框，
  所以用户跟我都没有发现，其实班组名字是可以编辑的。
  你看一下是不是可以优化一下。另外，你再检查一下我们 APP 还有没有其他地方类似这样的：
  文字是可以编辑的，但是视觉上感觉好像不能编辑，就是这种容易让人误会的地方。都统一优化」
- **用户拍板（2026-10-26）**：按方案 A（下文的统一规则）全部收一遍。
- **待用户确认（唯一未决项）**：默认班组名要不要沿用「一班…八班」。本稿按
  **不改默认值** 写（用户随后把问题定位成「看不出能改」，而不是「默认值不对」）；
  若确认要改，那是另一小步（改 `defaultTeamNames` 的默认命名，或给一排命名预设），
  不并进本轮的「可见性」改动。

---

## 1. 目标 / 非目标

### 目标

1. 全 app 建立一条**可辨认的交互暗示规则**，并把它写进 AGENTS，防止再长歪。
2. 让「能改的文字」看起来能改：输入框有框有标签；点开编辑的行有铅笔；点开选择器 /
   去别处的行有箭头。
3. 清掉审计发现的全部同类隐患（见 §3），一处不漏。
4. 把此前**从未进过视觉屏单**的「班组设置展开态」补进去。

### 非目标

- **不改任何点击结果**：每处的点击行为、弹层、页面跳转一个字都不变。
- **本轮不改默认班组名**，也不加「甲乙丙丁」预设（见抬头「待用户确认」；若用户要，
  另开一小步，不并进本轮的可见性改动）。
- 不给纯展示内容加装饰（农历、「其他班组」胶囊、信息卡时间行等）。
- 不引入第二种输入框样式；**不恢复 Material 浮动标签**（v0.11.20 真机教训）。
- 不动桌面小组件（原生 `RemoteViews`，与 Flutter 侧无共享渲染）。
- 不重做信息卡定高模型，不改 `GlassDialog` / `GlassPill` / `GlassTile` 的既有配方。

### 反目标（做到这些算失败）

- 加了图标但把窄窗（200dp）撑溢出，或把摘要文字挤成省略号。
- 信息卡因为多了一个图标而变高（「多条闹钟不该把卡片顶高」那类既有断言变红）。
- 用户点图标和点整行行为不一致（图标只是装饰，必须与整行同一命中区）。
- 为了「有暗示」把静止的纯文本也加上容器，页面变花。

## 2. 统一规则（本设计的核心决定）

全 app 只用三种视觉语言表达「这里能操作」：

| 语言 | 含义 | 已存在的先例 |
|---|---|---|
| **有框的输入框**（`GlassField` + `glassInputDecoration`） | 可以直接打字 | 方案名称、班次名称、简称、待办标题… |
| **铅笔**（`Icons.edit_outlined`，`iconSm`，`inkMuted`） | 点开进入**编辑这条内容**的表单（编辑弹窗 / 系列编辑器） | 待办编辑、闹钟编辑、模板重命名 |
| **箭头**（`Icons.chevron_right_outlined`） | 点开打开**另一个界面或层**（选择器 / 页面 / 说明或动作弹窗），但不进入「编辑这条内容」的表单 | 「我的」页导航行、排班管理页值行 |

**箭头尺寸随行高**：页面级行（`ListTile`、48dp 以上）沿用默认 24；密集行与手写行用
`iconSm`（16）+ `inkMuted`。这两档在仓库里**已经并存**（「我的」页 24、管理页值行 16），
本轮**不把 24 归一成 16** —— 那会改动一批没被反馈过的行，且页面级行用 16 会显得太轻。
写进 AGENTS 的规则句要带上这一档，否则下一个人会拿「统一」去把两边都改掉。

**判定口径**：打开的是「改这条内容」的表单 → 铅笔；打开的是「别的东西」（从一组值里挑
一个、跳去别页、看说明、做一次动作）→ 箭头。两者都不弹任何东西、只做展示的 →
什么都不加。

**动作行豁免**：文案本身是动词、且已有 leading 图标的行（「添加时段」「添加一段」
「均分各组起始日」「恢复轮转」「从文件中选择…」）不加箭头 —— 它们读起来就是按钮，
不是「显示一个值」。这一条与「显示值」的行要分开看。

**两条既有铅笔要归位**（它们打开的是选择器，按本规则属于箭头）：
- 编辑页「我这组从这个周期开始」行（`Icons.today` + 铅笔）→ 铅笔换箭头。
- 按月段「每月第 N 天起」（铅笔）→ 铅笔换箭头。

这样「铅笔」从此只表示「编辑这条内容」，语义不再二义。

### 例外（明确不做，理由记档）

1. **重复待办面板行**：不加铅笔、不加箭头。用户 v0.12.3 明确要求去掉那支铅笔
   （「重复待办的编辑笔图标去掉」）；整行本来就可点，不加回。
2. **取色圆点**（编辑页班次卡，24dp 色点 + 描边）：不加铅笔 / 箭头。它太小，
   叠一个 16dp 图标会盖住颜色本身；它紧邻「名称 / 简称」两个有标签的输入框，
   上下文已经表明这一组都在编辑。保留描边作为唯一暗示。
3. **日历长按拖选**：手势入口，不加可见提示（会破坏网格密度）；也不在
   《使用帮助》之外新增文案。
4. **顶栏年月胶囊不加箭头（量过之后否掉）**：360dp 标准档下，`_oneRowFits`
   的预算只剩 **19.59dp**（一次性探针实测：年月 87.906 + 今天 28.5，固定件合计
   224），而 16dp 箭头 + 4dp 间距要 **20dp** —— 差 0.41dp 就会把「一行档」翻成
   两行，白占一行顶栏高度。`calendar_header_fit_test` 明确钉着「标准档 360dp
   必须一行」，不能为弱提示牺牲它。玻璃胶囊 + 两侧 `‹ ›` 已是这一处的既有暗示；
   如需加强，另开一版把胶囊内边距与图标一起重排，不在本轮做。
5. **动作行不加箭头**：见 §2「动作行豁免」。

## 3. 审计结果与逐处处置

审计范围 `app/lib/features/**`（排除 `.g.dart`）。结论：**12 个 `TextField`，
11 个已经是带标签的 `GlassField`；唯一的裸输入框是班组名。** 其余问题都是
「可点但没有暗示」的行。

### 3.1 输入框（唯一一处）

| 位置 | 现状 | 处置 |
|---|---|---|
| 编辑排班页 · 班组行 · 班组名（`_crewRow`，`schedule_editor_screen.dart`） | 裸 `TextField`，`InputBorder.none`，无标签；有值时就是一行加粗正文，所在行还有描边和「设为我」chip，读起来像静态名单 | 换成 `GlassField(label: L10n.teamName, isDense: true)` + `glassInputDecoration(context, isDense: true)`；去掉原来的 `hintText`（标签已经有了）；「设为我」chip 与输入框**底对齐**（`CrossAxisAlignment.end`），保证在窄窗里仍是一行 |

### 3.2 「点整行编辑」的列表行

| 位置 | 现状 | 处置 |
|---|---|---|
| 待办行（`schedule_screen.dart` `_eventTile`） | 勾选框 + 标题 + 副标题 + 删除钮；点正文打开编辑弹窗，无任何暗示 | 删除钮**之前**加铅笔（整行可点，铅笔是装饰，不单独接点击） |
| 自定义闹钟行（`alarm_screen.dart` `_alarmTile`） | 开关 + 时间 + 重复规则 + 删除钮；点正文打开编辑弹窗 | 同上 |
| 「我的模板」管理弹窗的模板行（`shift_template_picker_screen.dart`） | 名称 + 副标题 + 删除钮；点行 = 重命名 | 同上 |
| 重复待办面板行（`recurring_panel.dart`） | 开关 + 文本 + 删除钮；点行 = 系列编辑器 | **不动**（见 §2 例外 1） |

### 3.3 打开选择器 / 去别处的行（补箭头）

| 位置 | 现状 | 处置 |
|---|---|---|
| 待办弹窗「日期 / 开始于」行（`schedule_screen.dart`） | `ListTile` + 右侧日期，无箭头 | 换成共享件 `GlassValueRow`（§4），行尾箭头 |
| 重复字段「时间（可选）」「提前提醒（可选）」（`recurring_fields.dart`） | `ListTile` + 右侧值，无箭头 | 同上 |
| 闹钟弹窗「时间」「日期」（`alarm_screen.dart`） | `ListTile` + 右侧值，无箭头 | 同上 |
| 编辑页班组「周期起始日」「从第 N 段入场」（`schedule_editor_screen.dart`） | 左侧语义图标 + 标签 + 值，无箭头 | 行尾补箭头（保留左侧图标）；不做成 `GlassValueRow`，版式不同 |
| 编辑页「我这组从这个周期开始」（`_headerCard`） | 日历图标 + 标题 + 日期 + **铅笔** | 铅笔 → 箭头 |
| 编辑页按月段「每月第 N 天起」 | 文本 + **铅笔** | 铅笔 → 箭头 |
| 排班管理页 · 已保存方案行 | 勾/日历图标 + 标题 + 副标题 + 删除钮；点行进编辑器 | 删除钮**之前**加箭头（进入编辑页 = 去别处） |
| 日历信息卡「班次名 + 时间 + 闹钟」行 | 色点 + 富文本 +（可选）「已调班」徽章；点开「调整班次」选择层 | 行尾最外侧（徽章之后）加箭头 |
| 小窗 / 短屏紧凑信息卡 | 整卡可点，静止态零暗示；禁用态与可点态外观相同 | 班次行右侧加箭头；时间那行改成 `SizedBox` 钉高 + `FittedBox(scaleDown)`（见 §5.2） |
| 排班时段弹层「管理排班时段」 | 纯 `ListTile`，无箭头，像分节标题 | 补箭头 |
| 「我的」页「检查更新 / 更新日志 / 使用帮助 / 查看日志 / 清除并重置数据」五行 | 同页其它行有箭头，这五行没有 | 补箭头（**页面级行沿用默认 24**；版本行保持无箭头，正是「静态 vs 可点」的对照） |
| 模板选择页 · 窄窗堆叠卡片 | 宽布局有箭头，堆叠分支（`inner < 色条 + 12 + 箭头 + 96`）把箭头整个丢掉，卡片退化成纯信息卡 | 堆叠分支补箭头（阈值本来就给它留了宽度） |

- 「其他班组」胶囊、农历、本月统计、待办副标题等纯展示内容。
- 班次时间块（开始 / 结束 / 响铃）：已有主色淡底 + 时钟图标，符合规则。
- 「我的」页铃声 / 贪睡时长：已有箭头。

## 4. 新共享件：`GlassValueRow`

从排班管理页现有的私有 `_labelValueRow` 提取，放到
`app/lib/core/widgets/glass_value_row.dart`。

```dart
GlassValueRow(
  label: '日期',
  value: '10月26日',
  mutedValue: false,
  onTap: ...,
  valueStyle: null,    // 默认 AppTokens.labelStrong；闹钟弹窗的时间传 sectionTitle
  trailing: null,      // 默认行尾箭头；传了就用自己的（如「清空」钮）
)
```

- 布局照现有实现：`GlassPressable` + `GestureDetector(opaque)` + `Row`，
  左 `Expanded` 标签（最多两行），右 `Flexible` + `FittedBox(scaleDown)` 值，
  行尾箭头 `iconSm` / `inkMuted`。
- **为什么不用 `ListTile`**：`ListTile.trailing` 在窄窗口里会吃掉整行宽度并抛
  `Trailing widget consumes the entire tile width`（v0.9.14 / v0.9.18 两次踩过，
  管理页那段注释有完整记录）。200dp 宽的弹窗里「提前提醒（可选）」+「提前30分钟」
  + 箭头必然超宽。
- 管理页的私有实现改为调用这个共享件，删除私有副本；既有行为逐像素保持
  （它是纯搬运，先验收「搬完逐像素不变」再改调用点 —— v0.11.18 的流水线）。
- 弹窗里的四行从 `ListTile` 换过来会**失去 Material 水波纹**，改为玻璃 Q 弹按压。
  这是有意统一：AGENTS 记录的水波纹只该属于「弹层里的 `ListTile`」，而这几处是
  居中弹窗。
- **字号会跟管理页对齐**：`ListTile` 的标题走 Material 默认（约 16），共享件用
  `AppTokens.rowPrimary`（14/w500）—— 换过来这几行会小一档、行高也矮一些。
  这是「统一」的应有之义（管理页那几行本来就是 14），且弹窗更矮对键盘更友好；
  出图确认不显得过小即可。
- 组件加稳定 key（如 `value-row-<label>` 或调用点自传），供用例断言箭头在场。
- **闹钟弹窗的「时间」保留 18/w700**：那是那个弹窗的主角，与闹钟列表的大号时间
  同一档。共享件因此要有 `valueStyle` 参数（默认 `labelStrong`，那一处传
  `sectionTitle`）—— 不许为了统一把主数字降到 14。

## 5. 逐处实现约束

1. **信息卡定高不许动**：箭头用 `iconSm`（16），行高仍由
   `_oneLineHeight(context, AppTokens.titleStrong)` 决定（约 21dp），图标矮于行高。
   `info_card_metrics.dart` 一个字不改；`calendar_screen_test.dart` 的
   「多条闹钟不该把卡片顶高」与 `info_card_fit_test.dart` 必须继续绿。
2. **紧凑卡**：箭头加在 `Row` 的 `Expanded` 之后，纵向居中。⚠️ 200×400 下这一行
   只剩约 118dp，而「20:30 – 次日08:30」实测约 103dp，加箭头 + 4dp 后只有约 96dp
   —— **直接加会让时间打省略号**，而「不许省略」是 §1 的反目标。所以时间那行
   同步改成与完整卡同一套：`SizedBox(height: 行高)` + `FittedBox(scaleDown)`
   （缩，不省略），并补一条 200×400 的**严格**断言（`text_fit_guard` 的小窗两档
   是「冒烟」、不判失败，兜不住这一处）。
3. **窄窗不溢出**：所有改动处补 200×400 的几何断言；`text_fit_guard_test` 的
   全部屏 × 四档 × 320/360 × 中英必须仍是 0 截断。
4. **顶栏预算保持原样**：年月胶囊不加箭头（见 §2 例外 4，已实测），
   `_oneRowFits` 与 `calendar_header_fit_test` 一个字不改。
5. **铅笔 / 箭头都是装饰**：不单独挂 `onTap`，不改变整行命中区；不新增触觉
   （`Haptics` 仍只在共享控件里发）。
6. **班组卡标题**：复用已存在但没人用的 `L10n.teamSettings`（「班组设置」/ `Teams`），
   删掉 `crewSettingsOptional`；折叠时副标题显示当前班组名
   `一班 · 二班 · 三班 · 四班` 与「点开可改名」；展开时不再显示副标题（字段已经写着）。
7. **视觉屏单**：新增 `67_editor_crew_expanded`（浅 / 深两档；59 已被 `59_help_faq`
   占用）。给 `ScheduleEditorScreen` 加一个 `@visibleForTesting initialCrewExpanded = false`
   —— 因为 `text_fit_guard_test` 是直接 `pumpScreen` 渲染屏单、**没有交互钩子**，
   不这么做的话「全矩阵 0 截断」会在一张永远收起的卡上通过，等于没验。新屏要进
   屏单，也随之进入字号护栏的矩阵。

## 7. 备选方案与取舍

- **方案 A（选定）**：建立「输入框 / 铅笔 / 箭头」三语言，全部收口。
  优点：一条规则可记、可守、可写进 AGENTS；改动都是小件，行为零变化。
  代价：动到十来处，视觉基线全量重比。
- **方案 B**：只修最像静态的三类（班组名、信息卡、列表行），弹窗值与一致性缺口不动。
  优点：改动少。代价：全 app 仍是两套语言，下一次还会有人问同一类问题。用户否。
- **方案 C**：给可点区域加淡底容器 / 胶囊。优点：暗示最强。
  代价：与极简玻璃语言冲突；信息卡是定高的，200dp 下加容器会挤掉内容；会让静态
  区块看起来也可点。否。
