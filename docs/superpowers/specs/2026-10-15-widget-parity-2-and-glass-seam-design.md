## 1. 三条的现状（全部是量出来的，不是看出来的）

### 1.1 底栏光晕的接缝 —— 正右方，一步跳 62°

沿透镜轮廓按角度采一圈色相（`work/adb-shots/navglow_2.png`，滑动中途那一帧）：

```
角度   -40°  -35°  -30°  …   -5°    0°     5°   …   30°
Δ色相  -3.2   0.0  -35.4 …    0.0  +62.0  +0.8  …   +0.0
```

别的地方每走 5° 只变 0～11°，**唯独 `0°`（正右方）那一步跳 62°**。

**成因在算式里，不在渲染里**（`app/lib/core/glass/liquid_lens.dart` 的 `spectralSweep()`）：

```dart
(base.hue + hueLag + 300 * t) % 360
```

色相走 300° 却**没有回到起点**。而 `SweepGradient` 的 `t = 0` 正是 **+x（正右方）**，于是 `t=1` 与 `t=0` 落在**同一个屏幕方位**上、颜色却差 60° —— 中间没有角度可以插值，就是一刀。这与用户「不管往哪边滑都只有右边」的观察一致（那圈颜色画在固定屏幕方位上）。

`spectralSweep()` 是**唯一一处**实现，四个 painter 共用（`liquid_lens.dart:847 / 1065 / 1082 / 1113`），所以底栏、分段器、开关、日历那枚块、拖选那条水带**一处修全都好** —— 用户说的「类似的还有其他共用了这个动态光晕的地方」正是它。

### 1.2 桌面卡不跟系统字号 —— 而且它会**切内容**

系统字号拨到 2.0 之后（`work/adb-shots/widget_font200.png`）：

| 卡 | 现象 |
|---|---|
| 今日卡 | 「20:30 – 次日08:30」**下半截被切**、「其他班组」整行不见、「1 项待办」徽章右半截出界 |
| 周条 | 七列的「周四 / 周五」挤成一团、班次胶囊被切 |

根因：三张卡的布局里字号全写 `sp`（跟着系统字号走），而卡的**尺寸是编译期定死的**（`resizeMode="none"`）—— 尺寸钉死、字在长，装不下就切。App 那边不会这样，因为它在 v0.11.12 把字号改成了自管。

### 1.3 月历格的「今天」与 App 差在哪

并排图 `work/adb-shots/compare_month.png`（左 App、右桌面，同宽）。**结构其实已经对齐**（白卡 + 2dp 缝 + 浅灰页面底 + 12dp 圆角都是 v0.11.9 做的），差的是：

| 在哪 | App（`calendar_screen.dart`） | 桌面（`widget_month_card.xml` / `widget_month_cell.xml` / `WidgetRenderer.kt`） |
|---|---|---|

## 2. 目标 / 非目标 / 反目标

**目标**

- 那圈光谱**没有接缝**：绕一圈回到起点时颜色连续。
- 三张桌面卡的字号**与系统字号解耦**；系统字号 1.0 与 2.0 下渲染结果一致。
- 月历周的周标题与 App 同字（单字）。
- 月历的「今天」读起来像 App 那一格：半透明主色块 + 主色描边。
- 月历格的**胶囊与农历大到与 App 同一档**；同一个格子在格宽/格高变化时按比例自适应，而不是写死。
- 今日卡上下余量收到与 App 那张卡同一量级，并把 App 有的三样补齐。

**非目标**

- 不做真实的背景模糊（桌面这个媒介做不到，见 2026-10-11 那份规格 §3）。
- **不改**相邻月变暗（用户点名为特色）。
- **不改**周条（4×1）的「周一 周二 …」：它不是网格、两个字更好读，App 里也没有对应物可比。月历那一行改单字**只影响月历卡**——`snap.weekdays` 只喂 `wg_m_wd1..7`，周条与今日卡读的是 `days[].weekday`（`WidgetRenderer.kt:425 / 888`），两条路互不相干。
- 不动三张卡的尺寸与注册方式（仍 `resizeMode="none"`、编译期定死）。
- 不给桌面卡加动画、不改刷新粒度（仍是跨天 + 班次边界）。
- 不引入任何新依赖。

**反目标**（技术上做成了也算失败）

- 光谱改成「接得上」之后，**最暗那一侧没有颜色了** —— 那正是 v0.10.7 修过的坑（`floor` 的用处）。
- 为了消掉接缝把色相砍成一圈单色（那就没有「光谱」了）。
- 桌面卡为了不跟系统字号，把字号写死 dp —— 那会**换台机器就错位**，是拿一个 bug 换另一个。
- 深浅两档只做一档。
- 月历「今天」改成半透明之后，**那格的日期/胶囊/农历读不清**（App 里它是画在网格**之上**的，桌面这块要画在内容**之下**，见 §5）。
- 今日卡为了填满而把内容摊开成「一行一行之间空一大截」—— 那是把留白从边上挪到中间，不叫修好。

## 3. 第一条：那圈光谱的接缝

**做法：把色相走满 360°，而不是 300°。**

```dart
(base.hue + hueLag + 360 * t) % 360
```

`t = 1` 时色相 = `base.hue + 360` ≡ `base.hue` = `t = 0` 的色相 —— **接缝两侧颜色相同，边就不存在了**。色相序列、`floor` / `span`、亮度峰值的方向（`spectralSweepRestAnchor = 225°`、「光从左上来」）、`hueLag` 的用法**一个字都不动**。

**为什么不是别的写法**

- *「绕 300° 但把接缝挪到最暗处」*：接缝处的亮度是 `floor + span × 0.0214`（`toward = 0.146` 再平方），约满亮的 59% —— **不暗**，挪哪都一样看得见。挪解决不了。
- *「往复（0 → 300 → 0）」*：也接得上，但色相在轮廓上变成**镜像对称**的，读起来不像折射、像两半拼的，而且改动比 360° 大得多。留作备选。
- *「把接缝那 60° 用一段过渡补上」*：**没有角度可补** —— `t=1` 与 `t=0` 是同一个方位。

**侧效（要在出图上核）**：色相总行程 +60°，于是「离主色最远」那一点从 150°（叠加 `hueLag` 后实测约 179.6°）推到 180°（叠加后约 210°）。远景那一侧会略偏一点色。先按这个做，出图看；不够就把 `hueLag` 收一档（**那是唯一该动的旋钮，别去动 `floor`**）。

**护栏**（`app/test/liquid_lens_test.dart`）：

1. **`colors.first == colors.last`** —— 这才是唯一分得出 300 与 360 的那条判据，**反向验证：把 360 改回 300 立刻红**。
2. ⚠️ **别只写「相邻两步色相差 ≤ 20°」** —— 那是一条**没有鉴别力**的断言：接缝落在**列表尾 → 列表头**的**环绕**处，不在相邻两项之间，300° 版每一步也只有 12.5°，照样绿。要判就判环绕那一对（就是第 1 条），或者按 §7.3 沿**渲染出来的轮廓**采一圈。
3. 守住反目标：**最暗那一侧的 alpha 必须仍 ≥ `floor`**（把 `floor` 写错、或改成单色都会红）。

## 4. 第二条：桌面卡的字号，按尺寸算而不是写死

**两件事一起做，因为它们同一个根。**

**① 与系统字号解耦。** 三张卡的布局里 `android:textSize` 全部从 `sp` 换成 **`dp`**；渲染侧凡是要设字号的地方，一律走 `RemoteViews.setTextViewTextSize(id, TypedValue.COMPLEX_UNIT_DIP, v)` —— `COMPLEX_UNIT_DIP` 不乘 `fontScale`，`sp` 才乘。这样系统字号怎么调，桌面卡一个像素都不动。

**② 按真实格子尺寸缩放（照 App 那一套）。** 桌面的格宽/格高不是常数（不同启动器给的行高不同；月历 5 行月与 6 行月也不一样），而 App 的格子内容是 `s = (cellH − inset×2) / designH`（夹 `[1.0, 1.25]`）算出来的。桌面用同一个形状：

```
s = clamp((实际格高 − 2 × inset) / designH, 下限, 上限)
每个字号 = 基准字号 × s        （用 COMPLEX_UNIT_DIP 设进去）
```

- 基准字号与 `designH` 直接取 App 那一份：`cellDateSm` **13** / `cellShift` **12** / `tinyLabel` **11**，`_cellDesignH` **55**（`_cellInset` = `gapHair` = 2）。**别在 Kotlin 里另抄一套数** —— 要么把这三个数当作常量并在注释里点名出处，要么由 Dart 侧随快照下发（构建者择一，但**必须有一处说明它来自 `design_tokens.dart` 的哪三个令牌**，否则下次调令牌桌面就静默走样）。
- **这是「月历格」与「今日卡」共用的同一个机制** —— 今日卡那边把「格高」换成「卡内可用高」，于是 §6.2 的留白也一起被收掉（见 §6）。
- 具体上/下限与取整方式留给构建者，验收线见 §7。

**③ 盒子的尺寸也要跟着长 —— 而这条撞了一个 SDK 限制，必须绕。**
`RemoteViews.setTextViewTextSize` 只改**文字**；能改**容器**尺寸的 `setViewLayoutWidth/Height` 是 **API 31** 才有的，而本仓 **minSdk 26** —— 26~30 上盒子尺寸**根本改不了**。所以：

- **胶囊盒子改成由文字撑开**：`FrameLayout(wrap_content × wrap_content)` 里放 `ImageView(match_parent)`（贴胶囊位图）+ `TextView(wrap_content)`（简称）。`FrameLayout` 量到最大的那个 `wrap_content` 子件 = `TextView`，`match_parent` 的 `ImageView`（没有 src 就没有固有尺寸）不参与定尺 —— 于是**盒子跟着字号长，一个 API 31 的调用都不用**。
- 顺带把「宽度写死 40dp」去掉：App 那格的胶囊本来就是**内容宽**（「白」窄、「大休」宽），写死 40dp 是另一处不像。若实测在窄格上溢出，退回「定尺 + 只缩字」并在这里记一笔。
- **今日卡那三枚徽章（今天 / N 项待办 / 已调班）的写死宽高本轮不动** —— 它们是「一行里三个东西并排」的定宽槽，跟着缩放会牵动那一行的整体排版；差距记进 §8。

**护栏**：一条 Dart 侧的源码扫描（与 `widget_fixed_cards_guard_test.dart` 同一套路）——**所有会渲染真数据的小组件布局里不许再出现 `sp`**。

- **扫描面**：`res/layout/widget_*.xml` **减去** `widget_preview_*` 那三张（静态缩略图，永不渲染数据）—— 即 **9 张**：`month_card` / `month_cell` / `today_card` / `today_standalone` / `strip_cell` / `week_strip` / `crew_chip` / `empty` / `placeholder`。**容器壳（`today_standalone` / `week_strip`）也要进名单**，哪怕它们今天一个 `sp` 都没有 —— 名单是为了拦住**以后**加进去的那一个。
- **今天实际要改的是 7 张、26 处**：`month_card` 10 / `today_card` 7 / `month_cell` 3 / `strip_cell` 3 / `crew_chip` 1 / `empty` 1 / `placeholder` 1。**`crew_chip` 与 `empty` / `placeholder` 必须在里面** —— 只改那几张「看起来像卡」的，今日卡里的班组胶囊与三张卡的空态 / 占位态照旧跟着系统字号放大，用户报的那条在这些地方会原样复现。
- 再补一条自证：**扫到的文件数 == 预期数（9）**，免得正则写歪之后「一个都没扫到」也报绿。

## 5. 第三条：月历的「今天」改回半透明块（**推翻 v0.11.9 的一处决定**）

### 5.1 为什么可以推翻：当初那条理由的前提已经没了

2026-10-11 那份规格 §1 末尾写着「**所以这是有意的偏离，不是抄错了** …… **不要去「修正」成半透明**」，理由是：

> 桌面**没有实时模糊**，半透明的主色块压在**任意壁纸**上会直接消失。

**那条推理的前提是「面板底是半透明的」** —— 而**同一轮（v0.11.9）**把月历卡的面板底换成了**不透明**的页面色（`widget_page_light` = `#FFF5F6FA → #FFF2F4F9`，两端 alpha 均为 `FF`，那个不透明是**为了周几行过 AA 才定的**），格子也换回了**白卡**（`widget_cell_light` = 纯白 + 6% 黑描边）。

于是今天那格现在是：**不透明页面底 → 白卡 → 主色块**，与 App 里（`#F5F6FA` 页面 → 白 92% 卡 → 主色块）**结构完全同构**。半透明块压在**不透明的白卡**上，不会「压在任意壁纸上消失」。

**另一条独立理由也不成立**：App 那枚块**自己不带模糊** —— 液态档是 `LiquidLens` 的 `fill: [accent 22%, accent 10%]` 加一圈描边（`calendar_lens.dart:313-325`），标准档是 `14% 淡染 + 2px 主色描边`（`calendar_screen.dart:2387`）。模糊在页面背景那一层，不在块上。所以「桌面没有模糊 ⟹ 块做不了」这条因果是错的。

**用户 2026-10-11 当时选的 A 版、今天要改回来 —— 这是用户的判断变了，不是当初选错。** 本文件即是那次反转的记录，`AGENTS.md` 里「别再修正回去」那条要一并改写。

### 5.2 做法

1. **今天那格的卡底不再置 0**（`WidgetRenderer.kt:656-662` 的 `isToday -> 0` 去掉）—— 半透明块需要底下那张白卡。
2. 块改成**烤一张半透明位图**：圆角 = 格子卡底那 12dp，填充 = **主色 22%→10% 的对角渐变**（与 App 液态档同一个配方），外圈一圈**实心主色描边 2dp × 该格尺寸**。
   - ⚠️ **`WidgetChip.block()` 是三处共用的**（月历「今天」格 / 周条「今天」列 / 今日卡的「今天」药丸，`WidgetRenderer.kt:672 / 464 / 841`）。**不要就地替换它** —— 那样会连周条与今日卡药丸一起改掉：前者违反 §2 的非目标，后者更糟，那枚药丸是**实心主色 + 白字**，半透明会让白字压在浅色上读不出来。**给月历单开一支（新方法或加参数），另两处保持实心。**
   - 颜色是用户选的主色，所以只能烤位图 —— 走 `WidgetChip` 的 LruCache（按 (颜色, 尺寸) 复用；同尺寸同色共一张，**别按格子造唯一颜色**，那会把缓存打掉）。
3. **块的层级在内容之下**（`widget_month_cell.xml` 现在的 FrameLayout 顺序正好就是它）。App 那边块在内容**之上**、会把字洗一层 14% —— 桌面**有意不跟这一条**：桌面的块是一格自己的、不需要「压过整张网格」，把字洗掉只损可读性、不加还原度。**这是本轮第二处有意偏离，写在这里免得后来的人「修正」它。**
4. **今天那格的字色：除胶囊外，全部回到中性色。** 现在那格有**三处**走 `onSolidInk` —— 日数字（`WidgetRenderer.kt:694`）、胶囊简称（`:746`）、农历（`:731`）。半透明块是**浅底**，`onSolidInk` 对 teal / orange 会给**白字** → 白压浅底读不出来（**静默**：默认那颗蓝选出来是对的，只有换到浅主色才现形 —— 与 2026-10-11 踩过的同一个坑）。所以：
   - 日数字 → `ink`（相邻月仍 `muted`）
   - 农历 → 回到 `d.lunarIsHoliday ? holiday : muted`。**顺带赚回一件事**：那个 `when` 现在把「今天且是法定节假日」的红字整个吃掉了（注释写着「可读性优先，代价是这一天看不出是节假日」），浅底之后它自然回来。
5. 那格的胶囊**回到普通配方**（`tintedChip` 14% 淡染 + 45% 描边 + 中性字），**不再是实心块**（现在 `isToday` 那一支烤的是 `WidgetChip.block`）。淡染压在浅色半透明块上完全没有原来那条理由（「淡染压在实心主色块上会糊成一片」）。
6. **先不动** App 里「选中那格的胶囊翻成实心」（`_shiftChip(solid: true)`）这件事：块先做完、出图看，若「今天」还不够跳，**下一步**再单独试 —— 一次只改一件，才分得清是哪一件在起作用。

> **顺带一条要改的既有守卫**：`widget_cell_block_guard_test.dart` 里「块必须排在内容之前」那条覆盖 month + strip 两处、「今天那格的字都走 `onSolidInk`」那条是本轮 §5.2.4 要**推翻**的 —— 后者要改成「今天那格的字**不许**走 `onSolidInk`」。守卫跟着实现改是正常的，但**改之前先反向验证一遍**（把实现改回旧的，新守卫要红）。

### 5.3 深浅两档

深色下页面底是 `widget_page_dark`、格子是 `#FF1B1B22`，块是同一份主色渐变 —— 两边都要出图核一遍（**先算对比度**：块上的日期字压在「白卡 + 22% 主色」上，要过 AA；这是「可读性优先于观感」那条的下限）。

## 6. 第四条：今日卡补三行 + 把留白收掉

### 6.1 补哪三样，数据从哪来

按仓库既有纪律 —— **「桌面小组件的用户可见文案全部来自 Dart 侧快照」**（`widget_snapshot.dart`，Kotlin 里不许出现用户可见的中文字面量）：

**放在快照的哪一层 —— 这一条决定它们过零点会不会消失。**

`todayCard` 里的东西只要 `todayCard.day != 今天` 就**整块留空**（v0.11.9 定的「跨天降级而不是硬撑」），而小组件跨天刷新时**只重渲染旧快照、不跑 Dart** —— 挂进 `todayCard` 就等于「每天过零点这三样消失，直到用户打开一次 App」，恰好与「补齐今日卡」的目标相反。所以：

| 补什么 | 放哪 | 怎么算 |
|---|---|---|
| 班次备注（休班「休息日 · 不响闹钟」；工作日「闹钟 07:00」/「…等 N 个」/「未开启」） | **`days[]` 每条按日烘焙** | 调**与日历信息卡完全相同的那份判据**（`_alarmText`，`calendar_screen.dart:2968`，含 `alarmDayAnchor` 的「前一天 / 次日」标记）—— 两处各写一遍必然分岔 |
| 「本月 大休13 · 白7 · 上夜6 · 下夜5」 | **`months[]` 每条带一个 `tally`**（按月，只有 7 条） | 整串在 Dart 侧算好（规则同信息卡：按 `shortLabel` **累加**、不是按班次下标 —— v0.9.12 修过这条）。**不逐日烘**：它是按月的量，逐日烘会让快照多背 231 份同样的串；原生拿当天的 `day` 反算年月再查 `months[]`，零点与翻月都自动是对的 |
| 「其他班组」标签 | **顶层**（与既有的 `weekdays` / `months` 同一层） | 用既有的 `L10n.otherCrews`（⚠️ **不是 `otherTeams`，那个标识符不存在**）。Kotlin 侧不许写用户可见的中文字面量，所以它必须由 Dart 侧下发 |

**降级**：旧快照没有这些字段 → 那三样**不画**，卡照常可用。**协议版本不动**（v2 不变；旧读新忽略多出来的字段、新读旧挖空，两边都能降级 —— 与 v0.9.17 放宽快照窗口时的做法一致）。

### 6.2 留白怎么收

顺序是「先补内容、再让缩放吃掉余量」，**不是**「把行距拉大摊平」：

1. 补上三样（内容从实测 **168dp** 长到约 205dp）；
2. §4 的缩放机制把内容按**卡内可用高**放大（上限与 App 同一档 1.25）；
3. 若仍有富余，**先调间距、不调字号** —— 参考 App 那张卡：363dp 宽、227dp 高，内容几乎顶到上下各留约 20dp。

⚠️ **外壳是定尺寸的 `wrap_content` + `center_vertical`，内容超出就被裁、没有滚动。** 所以第 1 步补完之后**必须先在真机上量一次**再决定放大到多少 —— 不能按「还有 88dp 富余」一路推下去。

**验收线**：真机上今日卡上下余量**各自 ≤ 30dp**（现状 43.0 / 44.7）。达不到就把差距写进「本轮不做的」，不要靠拉大行距凑数。

## 7. 验收

1. **真机**（Redmi K90 Pro Max，adb）：三张卡 + 底栏都出图，浅色与深色各一遍。
2. **系统字号 1.0 与 2.0 两张截图逐像素比**：三张卡的**内容区必须一致**（允许状态栏等系统区域不同）。这是第 1 条的唯一硬判据。
3. **光谱接缝**：真机上滑着截一帧，沿透镜轮廓采一圈色相 —— **采样点必须跨过正右方那一处**（`t = 0` / `t = 1` 的接口），任意相邻 5° 的色相差 ≤ 20°（现状：那一步 **62°**）。另断言最暗那一侧 alpha 仍 ≥ `floor`。
4. **并排比**：月历卡与 App 日历页同宽并排 —— 周标题同字、胶囊与农历的字号落在同一档；今日卡与 App 信息卡同宽并排 —— 三样补齐、上下余量同量级。
5. **单测全绿**（当前 1063，只增不减）；`flutter analyze` 0 error / 0 warning；视觉工装（`app/tool/visual/`）全跑 + 逐张比基线，差异逐条解释。
6. 新增护栏至少三条，且**每条都反向验证过**（把实现改回旧写法看它红）。

## 8. 本轮不做（记一笔，免得下次重新发现）

- **周条（4×1）的周标题仍是「周一 …」** —— 见 §2 非目标。
- **周条「今天」那一列与今日卡的「今天」药丸仍是实心块**（`WidgetChip.block` 原样）—— 见 §5.2 第 2 条：药丸是白字压主色，半透明会读不出来；周条那一列是另一类对象（整列高亮），App 里没有对应物。**三处从此不一致，这是有意的。**
- **月历「今天」那格的胶囊暂不翻实心** —— 见 §5.2 第 6 条，看块做完的效果再定。
- **今日卡那三枚徽章的写死宽高不跟着缩放**（`FrameLayout` 定宽 52 / 84 / 96dp + 块位图）—— `setViewLayoutWidth` 要 API 31，且它们是一行里三个并排的定宽槽，跟着缩放会牵动整行排版。@720p 真机核对过没有截字，记在这里。
- **桌面小组件的字体大小仍不跟 App 的「字体大小」设置走**，按格子尺寸算。App 那份四档设置是给**界面**的；桌面卡尺寸本来就由启动器定，跟着走会是两个变量相乘。
- **`widget_today_card.xml` 头注里那组过时的数（266 / 232 / 34）本轮顺手订正**为真机实测值并注明测量方法 —— 头注里的假数字比没有注释更坏，下一轮会拿它当基准。
- 今日卡若补完三行 + 缩放后仍达不到 §6.2 的验收线，**差距写在这里，不许靠拉行距凑**。
- `cancelAllNativeAlarms` 扫 ~1500 条那 600ms（v0.10.22 就记着的那条）仍然开着。
