# 支持者专属：自报解锁 + 第一封来信（设计）

- 日期：2026-11-10
- 起因：用户 v0.13.2 之后加的小功能 ——「在请我喝杯奶茶界面，如果有人支付金额之后，可以解锁元用户专属功能。目前还没有专属内容，先给它留个坑，第一个专属功能写一封简短的信。」
- 影响版本：v0.13.3 测试版（`X.Y` 由用户定，AI 只动 `Z` 与 `build`）

## 1. 目标 / 非目标 / 反目标

**目标**

- 打赏弹层里给一个「我已完成支付」的入口；确认后解锁「支持者专属」，下次打开还在。
- 「我的 → 支持」变成两行：打赏入口 + 支持者专属（未解锁显示锁，已解锁显示信）。
- 第一项专属内容是一封短信；页面结构给以后的专属内容留位置。
- 解锁后从打赏弹层返回，直接把信推到用户面前。
- 清空重置保留支持者状态。

**非目标**

- 不接支付宝 / 微信的支付回调、不做订单、不做服务端验签 —— 个人收款码没有这些。
- 不做付费墙：未支付不影响任何现有功能。
- 不做多档权益、不做兑换码、不做账号同步。

**反目标**

- 假装能验证支付（本地伪造一个「已支付」而不告诉用户这是自报）。
- 把支持者专属做成「只有付钱才能用某个功能」—— 用户明确说现在只是留坑。
- 重置后把支持者状态一起清掉。

## 2. 解锁机制

个人收款码没有支付回调，App 不可能知道钱到没到账。因此解锁是**自报式**：

1. 用户在打赏弹层点「我已完成支付」。
2. 弹一条确认：「打赏是自愿的，未支付也不影响使用。确认你已完成支付……」
3. 确认后写 `SharedPreferences['supporterUnlocked'] = true`，关掉弹层并回传 `true`。
4. 「我的」页收到 `true`，刷新状态，弹一条「已解锁支持者专属内容」，再推出信页。

这条取舍写在弹层与「支持」卡的注释里，也写进 v0.13.3 的更新日志 —— 不把自报说成验证。

## 3. 页面与状态

- `features/profile/supporter_store.dart`：键与读写。读失败按未解锁处理，不阻断渲染。
- `features/profile/supporter_screen.dart`：整页，`GlassTile` 里是「第一封支持者来信」；
  底部一行「以后的支持者专属内容会继续放在这一页」—— 这就是给未来留的坑。
- `features/profile/about_section.dart` 的 `SupportSection` 改为 Stateful：
  - 第一行「请我喝杯奶茶」永远在；
  - 第二行「支持者专属」：未解锁 → 锁图标 +「打赏后解锁 · 首期是一封信」，点开打赏弹层；
    已解锁 → 勋章图标 +「一封写给支持者的信」，点开信页。
- `profile_screen.dart` 的「清空重置」：清 prefs 前读一次 `supporterUnlocked`，清完写回。

## 4. 文案

- 解锁按钮 / 确认弹窗 / 成功提示 / 失败提示都在 `L10n`。
- 信的中英文都在 `L10n.supporterLetterBody`，四段，签名「—— Alec」。
- 信里明说「你的支持不会解锁更多功能」，与「未支付也不影响使用」一致。

## 5. 测试与验收

- `supporter_store_test`：默认未解锁，解锁后读回 true。
- `supporter_screen_test`：信页渲染出标题、正文、留坑说明。
- `support_section_test`：未解锁 / 已解锁两态。
- `donate_sheet_test`：点「我已完成支付」→ 确认 → 写入 prefs、弹层关闭。
- 视觉工装：`72_supporter`、`73_support_unlocked`；`70_profile_about_cards` 保持锁定态。
- `flutter analyze` 0 issue；全套测试与工装全绿；真机点一遍解锁 → 信页。

## 6. 风险

- 自报解锁可以被未支付的人点开 —— 这是有意接受的成本；打赏本来就是自愿的。
- 清空重置保留状态是「回到刚安装」的唯一例外，理由写在 `_confirmReset` 的注释里。
- 以后加真正的专属功能时，不要把「支持者专属」变成功能门槛；这一页的定位是感谢，不是付费墙。
