# 液态玻璃推广 · 第五轮（日历的选中块）设计

> 规格。实施计划见 `docs/superpowers/plans/2026-10-01-liquid-glass-rollout-5.md`（下一步写）。
>
> 上一轮（开关轨道色 / 弹窗凝聚 / 响铃页药丸）见
> `2026-10-01-liquid-glass-rollout-4-design.md`。版本：`0.10.14+138` → **`0.10.15+139`**。
>
> 这一轮的**决定过程**比结论值钱：先做了 A / B / B2 三套形状的对照图，再做了一版「头大尾轻」、
> 一版「折边」，**后两版都被用户看图否掉了**。被否掉的理由写在 §9，别照搬别处的做法。

## 1. 目标

日历网格上那枚**选中块**（`calendar-selection-block`）是全 app 每天被点最多次的控件，
却是**唯一一个一点液态档都没有**的 —— 底栏、分段器、开关、待办勾、响铃药丸都有。

它今天的样子：与格子**同 inset、同圆角**的圆角方，14% 主色淡染 + 2px 主色描边，
按下等比放大到 1.22，拖动 1:1 跟手、松手吸附到最近一格。

## 2. 用户拍板的（不可自行更改）

1. **形状 = A「透镜就是格子本身」**（圆角方，`radiusM` = 16）。
   B（格里一枚比格子小一圈的滴）与 B2（正圆滴）**都否掉了**：那两枚滴的边缘会**从字上切过去**
   ——B 那颗竖蛋切掉「国庆节」，B2 那个圆把日期与农历一起切。根因是格子的比例（**56.6 × 85**，
   又高又窄），不填满格子的形状在那个尺寸下没有立足之地。
2. **静止保留那 2px 主色描边**（它是「这一天被选中」最直接的识别符号）。
3. **二维拖动按速度分量各拉各的**（|vx| 拉宽、|vy| 拉高，垂直于运动方向收细）。
4. **被挤的内容是「整格那三行」**（日期 + 班次胶囊 + 农历），跟着透镜边缘被挤一下 ——
   与底栏 / 分段器同一条体验。
5. **头大尾轻不做**、**折边不做**（两条都是做出来之后被用户看图否掉的，理由见 §9）。
6. 「跟手折射光」依旧不做（第四轮就定过）。

## 3. 范围与档位

**只作用于液态档。标准档那棵树逐像素不动**（今天是 14% 淡染 + 2px 描边 + 1.22 放大，
一条都不改）。两棵树写在同一个 `_gridBody` 里（`_glassBlock` 与它外面那层 `AnimatedScale`
各分一次叉），判据只在那一个调用点读 —— `test/liquid_scope_guard_test.dart` 的名单
**6 处 → 7 处**（自证那条也一起改）。

⚠️ **一处改错就是「标准档也跟着变了」**：`AnimatedScale` 那层尤其要小心 ——
标准档靠它做按住放大，液态档必须把它的 `scale` 钉在 1.0（按住那个动作由升程承担），
分成两个值而不是删掉它。

探针里被否掉的两段（鼓边、折边）**不进入仓库**（见 §9）。

## 4. 几何与算式（逐条钉死）

### 4.1 透镜的盒子

| 参数 | 值 | 说明 |
|---|---|---|
| 盒子 | `cellW × cellH` | 与今天那枚块的 `AnimatedPositioned` 尺寸同一个 |
| 内盒 | 盒子内缩 `AppTokens.gapHair`（2） | 与卡片同 inset —— v0.7.3 那条「四个角露月牙」的教训 |
| `cornerR` | `AppTokens.radiusM`（16） | **新增的那一维**，见 §5.1 |
| `centerPage` | 0 | `centerX = pad + (centerPage + 0.5)·itemW`，A 底下正好落在格子正中 |
| `protrude` | 6（**每侧**） | 按住时四面各鼓 6px（卡片缝只有 4px，所以会压到邻居边上） |
| `liftWidth` | 12（**总**） | 与 `protrude` 同量级（纵横一起长才读得出体积） |
| `rimScale` | `cellH / AppTokens.lensRimRefCapsuleH` | 四层光谱与浮起阴影按控件尺寸缩 |
| `velocityRef` | 400 | 格子宽 56.6（比开关的 25 宽、比底栏的 88 窄），取中间 |

`protrude` 与 `liftWidth` 的约定不同（每侧 vs 总共），**别写反** ——
`LiquidLensMetrics` 的字段说明里写着这条。

**内盒与圆角必须与卡片同源**（同 `gapHair`、同 `radiusM`）：v0.7.3 真机反馈的「滑块没把格子
盖住、四个角各露一条月牙」就是这么来的，`calendar_screen_test` 里另有一条用例钉着两者相等。

### 4.2 形变与光谱环

- 速度：`vx` / `vy` 来自**帧间差分**（`lensVelocityStep`，带低通，按真实帧间隔算）。
  与响铃页那枚药丸同一套 —— 包括那条「**只在帧戳真的变了时才算**」（同一帧 rebuild 多次是常态）。
- 形变：`stretch = |vx| / 400`、`stretchY = |vy| / 400`（各自 clamp 到 1）。
- 环的门：`motion = max(|vx|, |vy|) / AppTokens.lensRingFullSpeed`（60px/s 封顶）。
- **环的门要过一条自己的渐入渐出弹簧**（亮起 ω=26/ζ=0.72、熄灭 ω=12/ζ=0.85，与底栏同一套）。
  直接拿速度当门的话，拖动启动那一帧彩边是「啪」地亮起来的 —— v0.10.8 的老毛病。
- 环熄到 0 之后**一个彩色像素都没有**（v0.10.7 为底栏定的规矩，这里照旧）。

### 4.3 升程（按住 / 松开）

- 按下 → `lift` 走 **Lift** 弹簧（`lensLiftOmega` / `lensLiftZeta`）；松开 → **Unlift**
  （`lensDropOmega` / `lensDropZeta`）。**不再用那个 1.22 的等比放大** ——
  「按住」这个动作由「四面鼓出 + 浮起阴影」承担，两个叠在一起就重了（图上看过，1.22 那版更糊）。
- 落定的过冲会让块短暂缩到**比格子小约 0.07px**（实测升程最低到 −0.006，即
  `2 × 6 × 0.006`）—— 比理论上的 0.095 小得多，因为 `LiquidLensSpring.isAtRest`
  的门（|位移| < 0.01）在真正的波谷之前就把它停了。**肉眼看不到「缩了一下」**，
  这里记下来是为了别拿 0.095 去估。
- ⚠️ **ticker 必须在静止时停掉**。日历页吃过大亏（v0.9.8）：常驻动画让帧队列永远非空，
  整套 widget 测试在 `pumpAndSettle` 上集体超时。升降两条弹簧 + 环那条弹簧**全部** `isAtRest`
  才许停（漏掉环那条，彩边会被冻在屏幕上 —— v0.10.8 记过）。

### 4.4 本体填充

- `fill: [accent 0.22, accent 0.10]`（斜向渐变，替掉今天的**平 14%**）。
  **不能用 `LiquidLens` 的默认填充**（`AppTokens.accentGradient`，0.85 → 0.50）：它会把选中那格的
  **实心班次胶囊洗掉色相**（代码里那条注释警告过，`橙 #FF9F0A` 会洗成棕）。
  实测（探针，胶囊中心像素）：标准档 `(230,149,41)` → 液态档 `(227,148,46)`，差 3~5/255。
- 2px 主色描边**照旧**画在透镜轮廓上（压在 `LiquidLens` 之上的一层 `CustomPaint`）。
- `showRefractedEdge: false`（折边不做，见 §9）、`showRingCore: true`、`restEdge: 0`。

## 5. 共享件要加的那一维（`liquid_lens.dart`）

这一轮给 `LiquidLensShape` 加**两样**东西（§5.1 / §5.2），**默认值全部保持今天的行为**，
于是四个既有调用点（底栏 / 分段器 / 开关 / 响铃药丸）**逐像素不变**。第三样（运动方向）
**不加**，理由在 §5.3。

### 5.1 `cornerR`：圆角半径

今天这一族**只会画「半径 = min(高, 宽)/2」的胶囊**。给一个比它小的 `cornerR`，
形状就变成一枚**圆角方**（四角是真正的圆，不是被纵向拉长的椭圆）。

实现上不是把两条既有分支改掉，而是**加第三条**：`2·cornerR < min(高, 宽)` 时走圆角方那一支
（四个角点 + 四段圆弧 + 四条直边），否则仍然是横向 / 竖直那两条老分支。
`cornerR` 默认 `double.infinity`，于是默认时那条新分支**永远不会进**。

⚠️ 圆角方这一支**不能复用竖直档的「先搭好再纵向拉伸」**：拉伸会把四个角一起拉成椭圆，
贴在 `radiusM` 的卡片上会差几个像素、读成「没对齐」。

⚠️ 圆角方那一支**四个角共用一个半径，不收后缘**（实施时订正）：胶囊那族的
`后缘半径 ×(1 − 0.35·stretch)` 是给**端头**用的（那里的半径就是半高，收一点就看得出来），
而圆角方上收半径只是把一个角磨尖 —— 且它必须与卡片的 `radiusM` **逐像素对齐**，
差一档就是那两个角各露出一条月牙（v0.7.3 真机反馈的那一类）。
反正 §9 已经把「头大尾轻」整个去掉了，这里没有方向可言。

### 5.2 `stretchY`：纵向那一份形变

`width` / `height` 改成对称的两条：

```
width  = itemW·(1 + lensStretch·sx − lensSquash·sy) + liftWidth·lift
height = (capsuleH − 2·pad)·(1 + lensStretch·sy − lensSquash·sx) + 2·protrude·lift
```

`sy` 不给时取 0，两条算式**逐字退回**今天的样子（今天只有横向拉伸 + 纵向压扁，没有纵向拉长）。
**这一条要有单元用例钉住**：同一组入参下，不给 `stretchY` 算出来的宽高与今天相等。

### 5.3 运动方向：**这一轮不加**

「头大尾轻」被否掉之后，**没有任何东西再消费「哪一头是前缘」** —— 形变按速度分量走、
挤字按几何距离走、环按合速度走。所以**不加 `dirX` / `dirY` 这两个入参**
（探针里加过，是为了那两版被否掉的形状）。

将来真要做需要方向的形变时再加 —— 那时它是新需求的一部分，而不是现在先占个位。

## 6. 内容被挤（2D 版）

今天只有一维版 `lensIconWarp`（只认 x，给底栏与分段器那种「一排」的控件用）。
日历的格子**四面八方都相邻**，要一个二维版：

- **距离换成椭圆归一化**：`t = √(((cx−lx)/hw)² + ((cy−ly)/hh)²)`，
  `t = 1` 仍然落在透镜轮廓上（与一维版同一个语义）。
- 权重仍然是那条钟形：`w = exp(−((t−1)/σ)²)`，`σ = AppTokens.lensIconRingSigma`；
  `w < 0.01` **一层 Transform 都不套**（恒等也要付代价）。
- `pinch = lensIconPinch·w`、`push = lensIconPush·w`：**沿径向**压扁、垂直方向拉长，再朝外推。
- `hw` / `hh` 取**满升程 + 满形变**时的半宽半高（一维版也是这么干的：它随升程只变一点点，
  而权重本来就是一条软的钟形）。
- **一维版是它在 `dy = 0` 时的特例** —— 这条要有用例直接比对两个纯函数
  （底栏那四处一个字都不改，靠的就是这条）。

作用对象是**每一格的内容**（日期 + 班次胶囊 + 农历那一列），不是卡片本身：
卡片不动（动了就成了「格子自己在扭」，而用户要的是**透镜压过去**）。

## 7. 交互（一处都不改）
- 静止 = `_selected`；拖动 1:1 跟手（`AnimatedPositioned` 的 `duration` 为 0）；松手吸附到最近一格。
- **位置吸附不改成弹簧**（沿用今天的 `easeOutCubic`）。过冲只出现在升程那两条弹簧上。
- 长按拖选（范围）、点按选日、触觉（`Haptics.select()` 在**吸附到的格子真的变了**时才发）——
  全部沿用，一行不改。
- 拖选一段那层淡染不动（它的液态版是下一轮的事，见 §9）。

## 9. 非目标（这一轮明确不做）

- **头大尾轻**。做了两版、都被用户看图否掉：
  - **后缘收窄**（每个角把「垂直于运动方向」的那一份缩掉）= 轮廓变成**梯形**，
    对边不平行 → 读起来是「这块玻璃被斜着怼进平面里」= **透视 / 立体感**。
    用户原话：「感觉好像不平行于当前二维平面了一样……四条边还是得互相平行」。
  - **每条边往外鼓**（轮廓仍是矩形、液体感由边的鼓动表达）—— 方向是对的，但在**方形格子**
    上不成立：斜着拖时四条边一起鼓，轮廓像变形虫；而且格子本身是「一天」的容器，
    变形一大就不再像格子了。用户原话：「感觉这效果还是不行，是不是方格子就不适合做？」
  - **结论：方格子不做头大尾轻。** 另：胶囊那一族的头大尾轻（收端头半径）在圆角方上
    **天然无效** —— 它的半径是 16、半高是 42，收半径只是把角磨尖一点，宽度 profile 一点不变。
    下次想捡，先看这一条。
- **折边（四条边在玻璃里弯进来）**。做出来之后用户一眼看出来：「那几条白弧飘在玻璃中间，
  而卡片自己的边还是直的，两套边缘对不上」。根因：底栏 / 开关能做，是因为那里的「边」
  **本身就是一条 1px 的描边**（`navBorder`），折它就是折同一根线；而日历格子的「边」是
  **一块填色面板的边界**（白卡 vs 灰底），要折它就得把**面板的轮廓真的画弯** ——
  42 个格子都要按透镜当前的场重画边界，还要跟卡片自身的圆角、阴影、选中态、按天改班小圆点
  打架。**代价与收益不成比例，不做。别照搬底栏那套 `refractedCapsuleEdge`。**
- **跟手折射光**（用户 2026-10-01 明说不做，第四轮已记）。

## 10. 风险与代价

- **每帧重建**：拖动时今天本来就是整棵网格 `setState` 重建，本轮新增的是
  42 次矩阵计算（挤字）+ 少数几个 `Transform`。**要量一次帧时间**，别靠估。
- **静止时也有一层 `ClipPath`**：`LiquidLens` 的本体挂着裁剪层，比今天的 `Container` 贵一点。
  这是常驻开销，**量一次**（底栏那枚本来就有，但底栏只有一枚、日历页还有 42 格 + 光晕背景）。
- **浅色档更含蓄、深色档更好看**（一路如此）。图上看过：浅色下按住那一下比原来那 1.22 弱一档。
- **`cornerR` 那条新分支只被一个调用点用**：泛化本身有回归风险（横向 / 竖直两条老分支
  不能碰），靠 §5.1 的默认值与 §8 第 1 条的逐像素比兜。
- **判据名单 6 → 7**：漏改自证那条，护栏会变成一句永远为真的空话（v0.10.13 踩过）。
