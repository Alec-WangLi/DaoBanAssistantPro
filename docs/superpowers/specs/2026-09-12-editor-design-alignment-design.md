# 排班编辑器设计语言对齐 · 设计规格

- 日期：2026-09-12
- 目标版本：`0.6.3+74`（测试版）
- 状态：待评审

---

## 1. 背景与目标

用户实测 v0.6.1 的「编辑排班」界面，指出三处与设计语言不合：

1. **字体比别的界面小一圈。**
2. **删除键跟设计理念不符。**
3. **周期设置里「选择班次」的下拉框与它弹出的二级界面与设计语言不符。**

### 1.1 排查：字号问题是真的，而且同一屏内就不自洽

`AppTokens` 定义了 `fontBody 14 / fontCaption 12 / fontMicro 11`，而全 App 其余页面走的是**字面量**：列表行主文字 16、次要文字 12–13。编辑器的 27 处字号全部引用令牌，于是系统性地比别处小 1–2pt。

更直接的一条证据：**同一张卡片里两个输入框字号就不一样**。

- 方案名称输入框（`schedule_editor_screen.dart:367`）**没有**显式 `style` → 用 M3 默认 `bodyLarge` = **16**。
- 班次名称与简称输入框（:482、:497）显式写了 `fontSize: AppTokens.fontBody` = **14**，把默认盖掉了。

所以「班次设置」里的输入框比它上面的「方案名称」小一号 —— 用户感觉到的「小一圈」不是错觉，是这行显式覆盖。

「我自己排」的模板选择页同样偏小：卡片标题 14、副标题 12、班组行 11，也都是字面量。

### 1.2 排查：选班次控件是 Material 默认件

周期行用的是裸 `DropdownButton<int>`（:831），`underline: SizedBox()`、`dropdownColor: colorScheme.surface`、方角 `borderRadius`。它与全 App 的三套玻璃底部弹层（时间 / 日期 / 月份）**完全不同源**：不透明、方角、系统蓝高亮、动画是 Material 默认曲线。这是三项里最「不像自己」的一处。

### 1.3 排查：删除键是常驻红色

班次行行尾是 `GlassDeleteButton(compact: true)` —— 去掉圆底后仍是一个**常驻的 danger 红色**垃圾桶图标。在一个 2–5 行的表单里，每行一个红点等于每行一个警报，与「简洁 + 玻璃」的克制基调冲突；而且删除会重排周期下标（不可逆），却没有任何确认。

### 1.4 目标

1. 编辑器与模板选择页的字号回到全 App 既有档位，同一屏内不再自相矛盾。
2. 选班次不再有二级界面，改为行内直接选择。
3. 删除动作降噪，并在真正执行前确认。

### 1.5 非目标

- **不动其他页面的字号**（用户已确认只统这两屏）。日历格子的 18/12/11/9 是密集网格的专门设计，不在本次范围。
- 不改 `AppTokens` 里**既有**令牌的值 —— 只新增两档，避免连带撑破其他页面。

## 2. 设计

### 2.1 字号：按全 App 既有档位对齐

全 App 的实际档位是 **16 / 14 / 13 / 12**（主文字 / 行文字 / 次要 / 微字）。`AppTokens` 现有 14（`fontBody`）、12（`fontCaption`）、11（`fontMicro`），缺 16 与 13 两档。

**令牌层**（`design_tokens.dart`，该文件明确要求「禁止在 feature 层内联 magic number」，所以必须走令牌）：

- 新增 `fontLead = 16` —— 输入框正文、卡片标题。
- 新增 `fontSupport = 13` —— 次要说明、行内标签。
- **删除 `fontMicro = 11`**：它全项目只有编辑器在用（已 grep 确认 5 处），提档后无人消费。设计语言那一轮已经确立了「删掉未消费的死令牌」的先例。

**编辑器**（`schedule_editor_screen.dart`）：

按**角色**对齐（27 处字号逐条列出在实现时对照，此处给规则）：

| 角色 | 现值 | 改为 | 编辑器中的位置 |
|---|---|---|---|
| 输入框正文 | 14（显式）/ 16（默认） | **16** | 班次名称、简称、方案名称 |
| 卡片标题 | 14 | **16** | 班次设置、周期设置、班组设置、跟随法定节假日、我这组从这个周期开始 |
| 行内主文字 | 14 | **14**（不变） | 时间块的值、「N 个班组」、班组名（走默认 16） |
| 行内次要标签 | 12 | **13** | 第 N 天、「设为我」按钮 |
| 次要说明与行内标签 | 12 | **13** | 班次设置提示、班组提示、周期起始日、顶部日期值、分段器标签 |
| 时间块的字段名 | 11 | **13** | 开始 / 结束 / 响铃时间 |
| 周期行右侧只读时间 | 11 | **13** | — |
| 微字 | 11 | **12** | 跨午夜提示、预览条的日期与班次简称 |
| 底部弹层标题 | 18 | **16** | 班次颜色（与 `showGlassTimePicker` / `showGlassMonthPicker` 的标题对齐） |

**两处特例**：

1. **未来 14 天预览条的日期与简称**提到 **12** 为止 —— 7 列网格每格可用宽度约 39px，再大就换行破版。这是「空间不够」的正当例外，写在此处备查。
2. **简称输入框宽度 `_abbrFieldWidth` 必须从 60 提到 68。** 它现在的 60 是**按 14 号字算出来的**（见该常量上方注释：46 装不下两个汉字，第二个字会被裁掉，而 widget 测试看不出这种截断）。字号提到 16 后两个汉字要 32px，加 `OutlineInputBorder` 的内边距，60 不再够 —— 这是一个**只有真机截图才能发现**的坑，所以连同尺寸一起改并写进验收。

**模板选择页**（`shift_template_picker_screen.dart`）：把字面量换成令牌，并与列表行惯例对齐 ——

| 位置 | 现值 | 改为 |
|---|---|---|
| 顶部说明文字 | 13 | **13**（`fontSupport`） |
| 分组标题 | 13 w700 | **13**（`fontSupport`） |
| 卡片主标题 | 14 w600 | **16**（`fontLead`） |
| 卡片副标题 | 12 | **13** |
| 「每天在岗 N 个班组」行 | 11 | **12** |
| 搜索框 | 默认 16 | **16**（不变） |

### 2.2 选班次：行内彩色 chip（去掉二级界面）

周期每一行不再有下拉，改为**把该方案的全部班次平铺成 chip**，点一下即选中。

```
第 1 天   ●白班  ○夜班  ○休班        08:30–20:30
第 2 天   ○白班  ●夜班  ○休班        20:30–次日 08:30
第 3 天   ○白班  ○夜班  ●休班        休息
```

**未选中 chip**：玻璃淡底（`colorScheme.primary` 6% 同款，与时间块同源）+ 描边 + 班次色圆点 + 班次名，文字用 `onSurface` 55%。

**选中 chip**：**班次色实心底 + 自动取白字或黑字**。

文字色不能用「恒定白字」：调色板里的浅色（橙 `#FF9F0A` 白字只有 2.23:1、绿 `#34C759` 与灰 `#9AA0B4` 同理）压上白字根本读不出来。也不能拿现成的 `AppTokens.inkFor` 代劳 —— 那个函数是「把一个前景色调到在给定背景上可读」，朝黑还是朝白由**背景**明暗决定；而这里是「在底色已定的前提下白黑二选一」，方向必须由底色本身决定。

新增 `AppTokens.onSolid(底色)`：算白、黑两侧的对比度，取高的一侧。**恒有 max(白, 黑) ≥ 4.58:1**（两条曲线在亮度 0.179 处交叉，交叉点上各是 4.58），所以对任何底色都能过 AA，不需要逐档逼近。

这与日历格子已经采用的「按底色算可读性」是同一条原则，只是格子是淡染底、这里是实心底。

**布局**：`第 N 天`（固定 56）｜ chip 组（`Expanded`，**横向可滑**）｜ 只读时间（自适应）。

- 班次多（五班四倒、六班四倒最多 5–6 个）或屏窄时，chip 组横向滚动，右侧露出半个 chip 作为可滑动的提示。
- 周期上限 60 天 → 最多 60 行 × 5–6 个 chip，是纯静态布局，无性能问题。
- 若该行时间在空间不足时被隐藏，**信息不丢**：时间属于班次定义，在「班次设置」里逐条列着。

**命中区**：chip 视觉高度 32，外层留白把命中区补到 ≥44 —— 这是为以后的**车机**（触控目标要更大）留的余量，本轮先把尺寸提上去。

**无障碍**：每个 chip 带 `Semantics(selected:)` 与班次名标签。

### 2.3 删除键：降噪 + 确认

**形态**：默认用中性色（`onSurface` 55%）的 outlined 垃圾桶，**按压时才转 danger 红**。不再常驻红色。

**范围**：这是 `GlassDeleteButton(compact: true)` 这**一个共享变体**的改动。全项目 `compact: true` 只有两处在用 —— 排班编辑器（班次行）与排班管理页（方案行尾）。所以本次一并覆盖这两处。

（原先写的是「闹钟页、待办页也受影响」，那是没核对调用点。这两个页面用的是**不带** `compact` 的完整红圆变体，本次不动。）

**确认**：编辑器的班次删除改为先弹 `GlassDialog` 确认（复用排班管理页 `_deleteSchedule` 已有的写法：取消 + 危险红删除两颗 `GlassActionButton`），确认才执行。

- 理由：删掉一个班次定义后，周期里所有比它大的下标会整体前移，删错了没法靠重加复原（时间、颜色、闹钟配置都丢了）。
- **仍被周期引用时保持现状**：直接拦下并弹「周期里还有 N 天在用这个班次」，不弹确认框 —— 那条路径本来就删不掉，再问一次是多余的。
- 排班管理页**不加确认框**（它已经有自己的确认），只换外观。

## 4. 边界与容错

| 场景 | 行为 |
|---|---|
| 班次定义只有 1 个 | chip 组只有 1 个 chip，默认选中，点它无效果 |
| 班次定义很多（5–6 个）且屏窄 | chip 组横向滚动，右侧露出半个 chip |
| 周期行的时间被隐藏 | 时间仍可在「班次设置」里逐条看到 |
| 删除被引用的班次 | 拦下 + 提示，不弹确认框 |
| 删除未被引用的班次 | 弹确认框，确认才删 |
| 大字号系统字体（用户把系统字号调大） | 字号全部走令牌，系统缩放照常生效；chip 组会换行/滚动而非溢出 |

## 5. 范围外（本次明确不做）

- 其他页面的字号统一（含日历格子的 18/12/11/9）。
- 撤销式删除（snackbar + 撤销按钮）。它比确认框更顺手，但需要保留被删班次与周期重映射的中间状态，本轮不做 —— 记在这里备查。
- 编辑器在宽屏下的双列布局（v0.6.4 处理）。
- 编辑器的信息层级重排（哪些卡片折叠、顺序调整）。

## 6. 验收标准

1. `flutter analyze` —— 0 error / 0 warning。
2. `flutter test` —— 全绿，且新增：
   - **同一屏字号自洽**：widget 测试断言编辑器里**每一个** `EditableText` 的生效字号都是 16（`EditableText.style.fontSize`）—— 这是「小一圈」那个抱怨的直接回归测试。
   - **档位落点**：断言几处关键文字的实际字号 —— 卡片标题（班次设置 / 周期设置 / 班组设置）16、第 N 天 13、时间块的字段名 13、预览条 12。
     不做「整棵树字号必须属于 {16,14,13,12}」那种全局断言：`GlassDialog` 的标题用的是共享令牌 `fontHeading`（18），它会出现在编辑器弹出的确认框里，全局断言会把共享组件一起判错。
   - **chip 选中态可读**：遍历调色板里的每个班次色，断言 `inkFor(Colors.white, 色)` 与该色的对比度 ≥ 4.5:1。
   - **删除需确认**：未被引用的班次点删除 → 出现确认弹窗；取消 → 班次仍在；确认 → 班次消失且周期下标正确前移。被引用的班次点删除 → 不弹确认，弹提示，班次仍在。
3. 手工验收：真机对比编辑器与「我的」页的字号观感；走一遍「加两个班次 → 改周期 → 删一个没用的班次」。
   - **重点看简称输入框**：填入两个汉字（如「大夜」），确认第二个字**没有被裁掉**。这一条 widget 测试看不出来（它只断言文本内容，不看排版），必须肉眼或视觉工装确认 —— 该输入框现在的 60px 宽度正是上一版为此踩过坑才定下的。
4. 视觉工装：出编辑器与模板页的浅色 / 深色 / 英文三套图，与 v0.6.1 的图逐屏比对。
5. 对比度审计脚本（`tool/visual/contrast_audit_test.dart`）跑一遍，确认没有因 chip 选中态引入新的不达标项。
