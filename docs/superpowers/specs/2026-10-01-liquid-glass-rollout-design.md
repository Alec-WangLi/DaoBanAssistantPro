# 液态玻璃推广 · 分段器与开关（设计）

> 规格。实施计划见 `docs/superpowers/plans/<date>-liquid-glass-rollout.md`（下一步写）。

## 1. 目标

把底栏那一档液态玻璃**抽成一个共享件**，然后铺到另外两个「长得像」的面上：

- **`GlassSegment`**（分段器，4 处用到：闹钟页 / 排班编辑器 / 我的页 / 待办页）
- **`GlassSwitch`**（开关，7 处用到）

**这一版只做这两个面。** 见 §8「明确不做的」。

## 2. 用户拍板的四条（不可自行更改）

1. **范围**：分段器 + 开关。（按钮 / 芯片 / 输入框 / 静态玻璃面都不在这一轮。）
2. **静止不带彩边**：`motion` 那道门照旧 —— **静止时一个彩色像素都不画**（2026-10-01 定的老规矩，本轮不动）。
3. **开关按住时钮纵向拉长**，参考 iOS 26：从 `20 × 22` 变成 `20 × 38`（上下各探出轨道 8），**宽度不变**。
4. **彩边仍然只跟「有没有在动」走**，与底栏**同一条**规矩。全 app 只有一条，不引入「按住就带彩」。
5. **开关的轨道也玻璃化**。它现在是「开 = 实心主色 + 白圆钮、关 = 灰 + 白圆钮」，那不是玻璃；而钮一旦变成玻璃滴，压在实心主色上就看不见了。所以轨道改成**磨砂玻璃胶囊**（与底栏同一套配方），**开的时候叠一层主色淡染**表示「已打开」。

## 3. 从底栏学到的三件事（抽共享件时必须原样保留）

### 3.1 它不是一种材质，是一种行为

那套效果需要三件事同时成立：**胶囊形**的容器、容器里有一枚**会滑动 / 会被按住**的指示块、四周**有空隙**可以凸出去。少了后两件的地方搬过去只会得到「按住时有个东西凸出来压在文字上」—— v0.10.2 在闹钟页与待办页各挨的一条「边缘有点丑」就是这么来的。

**推论：静态玻璃面（卡片 / 面板 / 胶囊）不加。** 不是因为不好看，而是因为静止时这套东西**一个像素都不画**，加了等于没加；要让它静止也带彩边，那是**另一条新规矩**（见 §8）。

### 3.2 三个量必须分家

这是六轮真机反馈沉淀下来的，**喂同一个量给两处就只能二选一**：

| 量 | 跟什么走 | 表现 |
|---|---|---|
| `stretch` | **速度** | 拖动时头大尾小 |
| `motion` | **有没有在动** | 彩边 / 光晕的亮度，一动就满、且渐入渐出 |
| `lift` | **有没有按住** | 凸出胶囊、放大、跟不跟手 |

### 3.3 手感只许有一处实现

弹簧参数（提起 / 落下、亮起 / 熄灭各两条）、帧率无关的速度算式（`lensVelocityStep`）、`lensMaxStep` 的步长封顶 —— 全部收在共享件里。**抄三份的话下次调参要改三处，而三处一定会走样**（这条在仓库里记过好几次）。

## 4. 三个面各自长什么样

### 4.1 底栏（作为第一个调用点，**渲染必须逐像素不变**）

参数取现在的值，效果一个字都不改。

### 4.2 分段器 `GlassSegment`

- **胶囊高按调用点实际传的值取**（现在各处是 **38 / 40**，不是一个常量），`protrude` / `liftWidth` 由 `forCapsule` 导出 → 38 → **约 5.9**、40 → **约 6.25**。**取整到 6 即可**，没必要让 38 和 40 差出半个像素。
- **保留**：追着滑块的光带、被折进来的胶囊边、内容层（文字）。
- 交互与现在一致：点按切换 + 拖动跟手。
- 选中项前景色沿用底栏那套（`navForeground`）。

### 4.3 开关 `GlassSwitch`

**现状**（必须先看清，因为它与底栏/分段器**不同构**）：轨道 46×28 用**纯色填充**——开 = 实心主色、关 = `glassBorder @ 0.6`；钮是**白色圆球** 22（`height - 6`）+ 投影；切换走 `AnimatedAlign` + `easeOutBack`。**它现在没有一处是玻璃**（连模糊都没有）。

**这一版把它改成**：

- **轨道玻璃化**：`GlassBlur` + `navFill` / `navBorder` 那套配方（与底栏同一份），圆角 `height/2`。**开的时候**在玻璃里叠一层主色淡染（`accent @ ~0.35`）表示「已打开」；关的时候就是中性玻璃。
- **钮是白玻璃球，不是主色玻璃滴**：底栏与分段器的透镜本体是 `accentGradient`，开关这一处必须是**白 / 浅色的玻璃**——否则白球变彩球，而且压在淡染轨道上会糊。所以 `LiquidLens` 的**本体填充要参数化**（见 §5.3）。
- **按住时钮纵向拉长**：`protrude: 8`、`liftWidth: 0` → `20 × 38`。宽度不变，只长个儿。彩边挂在钮上（钮是浅色的，所以彩边在它边缘看得见）。
- **关掉「追着滑块的光带」**：它是底栏特有的指向性提示（「药丸在哪儿」），在 46px 宽的轨道上横穿整个控件，读起来是一条**杂线**（样图里实测）。
- **关掉「被折进来的胶囊边」**：开关的几何里 `_cap = min(高, 宽) / 2 = 钮宽 / 2 ≈ 11`，小于轨道半高 14 —— 这条边**天然就画不出来**；但把 `protrude` / `liftWidth` 调大就会画出来（样图里 10 / 10 那档就画了），所以仍然做成**显式开关**，不靠几何巧合。
- 钮在静止时是圆的：胶囊几何在 **宽 == 高** 时精确退化成一个圆（走 `toPath()` 的退化分支，v0.10.4 加的那条，已有护栏）。
- 触觉、`enabled` 置灰的语义**一个字都不改**（`Haptics.select()`、`glass_switch_test.dart` 那条「置灰不跟着液态档回退」的护栏照旧）。

**⚠️ 这一处会改到七个界面的观感**（闹钟 / 排班编辑器 / 我的 / 重复待办面板 / 待办…）。「开」的读感会比现在的实心主色**弱一档** —— 那是这一条决定的代价，出图时逐个核。

## 5. 结构

### 5.1 新文件

| 文件 | 职责 |
|---|---|
| `lib/core/glass/liquid_lens_controller.dart` | 动画状态机：四条弹簧、速度与低通、ticker 起停、两棵树共用的手势回调。**纯逻辑，不含 widget**，可直接单测。 |
| `lib/core/widgets/liquid_track.dart` | 「胶囊 + 边光 + 透镜 + 内容」那棵树，参数化。 |

**判据**：这两个件都不读 `liquidGlassActive` —— 档位判据只出现在**调用点**，与 `core/glass/liquid_lens.dart` 现在这条纪律一致。

### 5.2 `LiquidLensMetrics`

```dart
class LiquidLensMetrics {
  const LiquidLensMetrics({
    required this.protrude,   // 满升程时纵向每侧探出多少
    required this.liftWidth,  // 满升程时横向总共外扩多少（**可为负 = 收窄**）
  });

  /// 按胶囊高度取默认值（底栏 64 → 10，即 0.156）。
  factory LiquidLensMetrics.forCapsule(double capsuleH);
}
```

- 底栏：**显式 `10 / 10`**，**两个高度都用它**。⚠️ 不能写成 `forCapsule(64)` 或让它跟着 `capsuleH` 走：矮屏那一档胶囊是 52 高，跟着取会变成 8.1/8.1 —— 那会**改到矮屏的渲染**（横屏 900×420 与小窗），破坏 §4.1 那条「逐像素不变」。底栏这两个数是**冻住的**。
- 分段器：`forCapsule(40)` → 6 / 6（38 高那处 → 5.9，**取整到 6**，没必要差半个像素）。
- 开关：**显式** `LiquidLensMetrics(protrude: 8, liftWidth: 0)` —— 它要的是「明显被抽出来」，不是等比例。

### 5.3 `LiquidLensShape.of` 与 `LiquidLens` 的签名变化

**几何**：`protrude` / `liftWidth` 从**读令牌**改成**收参数**。令牌 `navLensProtrude` 保留为「底栏那一档的默认值」的来源（`forCapsule` 的系数由它导出），不再被几何直接读。

**本体填充**：`LiquidLens` 现在写死 `AppTokens.accentGradient(accent)`。改成收一个 `fill`（`List<Color>` 或一个 builder），默认值仍是 `accentGradient`：

- 底栏 / 分段器：主色渐变（不变）；
- **开关：白色玻璃**（钮是白球）。

白芯（`lensRingCoreWidth` 那条）在**白色本体**上会消失 —— 开关那一档要么把白芯换成一层**极淡的暗边**，要么收掉它、靠彩边与投影给轮廓。**这一条在实施时用出图定**（不是现在能定的）。

### 5.4 `LiquidTrack` 的参数

```dart
LiquidTrack({
  required int slots,
  required double capsuleH,
  required double pad,
  required LiquidLensMetrics metrics,
  required Widget Function(BuildContext) contentBuilder,
  bool showGlowBand = true,        // 开关上 false
  bool showRefractedEdge = true,
  ...
})
```

## 6. 守门与工装

### 6.1 `test/liquid_scope_guard_test.dart`

允许出现 `liquidGlassActive` 的位置从 2 处扩到 4 处：

```
lib/core/glass/glass.dart           （定义处）
lib/features/home/                  （底栏）
lib/core/widgets/glass_segment.dart （分段器）
lib/core/widgets/glass_switch.dart  （开关）
```

**新抽出来的两个件不在名单里** —— 它们都不读档位，档位判据只出现在**调用点**（与 `core/glass/liquid_lens.dart` 现在这条纪律一致）。名单漏掉调用点会红、多写了不该有的位置也是一种错误，两者都由同一条用例照出来。

**第二条「自证」断言照旧保留** —— 只跑第一条的话，一次扫错目录就会让守门恒绿。

### 6.2 两棵树的硬要求

`GlassSegment` 与 `GlassSwitch` 各自也要**两条档位两棵树**：关掉液态玻璃时，它们必须与现在**逐像素相同**。这与底栏 v0.10.3 的验收是同一条。

### 6.3 新的护栏

- **底栏不变**：`00_home_shell_*`（标准档 5 张）与 `36_home_shell_liquid_*`（液态 5 张）与基线**逐像素相同**。这是「抽共享件」这条路的唯一验收。
- **分段器**：胶囊左右两条边同值（沿用底栏那条对称性判据）。
- **开关**：有升程时钮的轮廓高度 > 轨道高度（钉住「纵向拉长」），且宽度不变。
- **开关**：静止时钮的轮廓 `宽 ≈ 高`（钉住「圆钮」，不因共享件而变成胶囊）。

### 6.4 屏单与动图

- 屏单补：液态档的分段器与开关（各含静止 / 按住两态）。
- `tool/gif/` 补两条素材：分段器拖动、开关按住拉长。

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| 抽共享件动到**已经定稿的底栏** | 逐像素比对（§6.3 第一条）。渲染树相同则像素相同 —— 这条验收是可证的，不是「感觉没变」。 |
| 开关太小，几层效果互相打架 | 样图已经撞出来（光带成杂线）；§4.3 关掉那两层。**这是本轮实测得到的，不是推测。** |
| 分段器在**窄窗**（200×400）下的几何 | 底栏已经踩过「宽 <= 高 时透镜整个消失」的 Critical，`toPath()` 有退化分支；分段器在窄窗下同样会落进那一档，**屏单必须出窄窗那一张**。 |
| 分段器在排班编辑器里（那页布局本来就紧） | 出图核对；编辑器那页 v0.9.18/0.9.19 挨过两次布局反馈。 |
| **开关的「开」变弱**：从实心主色改成玻璃 + 淡染，一眼看出来的强度会掉一档 | 出图逐个核七个界面；淡染的 alpha 是一个数，不够就加。**这是拍板第 5 条已知的代价**，不是没想到。 |
| 白色钮 + 白芯 = 轮廓消失（§5.3） | 实施时用出图定（白芯换暗边 / 收掉）。**这一条留了出口，不是悬空的 TODO。** |

## 8. 明确不做的

- **静态玻璃面带彩边** —— 那要重新定义「静止什么都不画」这条地基，并且要重新想「关掉液态玻璃时那些面长什么样」。**另开一轮。**
- **按钮 / 胶囊 / 芯片 / 输入框**（「按得动但没有指示块」的那一类）—— 只有「按住鼓起 + 弹性」，没有滑动指示块，是**另一套设计**，不是搬。
- **给开关做新交互**（长按 = ？、双击 = ？）—— 本轮开关的交互与现在完全一致，只是按住时钮的形状变了。
- **选择器 / 弹层 / 提示条**。

## 9. 分期

一个计划，两条腿（先抽、再铺），因为共享件不抽出来就没法铺第二处：

1. **抽**：`LiquidLensController` + `LiquidTrack` + `LiquidLensMetrics`，并把**底栏**改成调用点。**验收：底栏逐像素不变**（这一步做完就应该能单独验证）。
2. **铺**：分段器、开关各接上去，各带自己的两棵树、护栏、屏单。

第 1 步做完如果底栏有任何像素变化，**停在那里解决**，不要往下走 —— 那是「共享件与原实现不等价」的信号，带着它继续会把问题扩散到另外两个面。
