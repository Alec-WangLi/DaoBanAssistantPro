# 周期排班编辑器 · 设计规格

- 日期：2026-09-11
- 目标版本：`0.6.0+0`（正式版）
- 状态：待评审

---

## 1. 背景与目标

### 1.1 现状

排班引擎（`domain/shift_rotation.dart`）本身是通用的：`若干天的周期表 + 班组数 + 相位`，某天的班次按下标取模算出。市面上有规律的倒班方式都能落进这个模型。

但**编辑器把它卡住了**，导致大量倒班方式在界面上根本建不出来：

1. **周期长度 = 班组数**。`schedule_editor_screen.dart::_setTeamCount` 会把班次列表增删到与班组数相等，班组数上限 8 —— 周期最多 8 天。而「上 12 休 12 一周一倒」要 14 天、「DuPont」要 28 天，全都做不出来。
2. **周期第几天与班次定义是同一行**。12 天周期里 4 个「白班」就是 4 条重复记录，颜色、时间、联动闹钟各配 4 遍，改一次要改四处。
3. **不知道填什么**。用户面对一个空白周期表，没有任何起点。

### 1.2 目标

1. **覆盖市面上所有有规律的倒班方式** —— 包括常见的和行业内的冷门模式（DuPont、五班四倒、六班三倒、上 24 休 48 等）。已知的一种结构性例外见 §2.2。
2. **新建排班通俗易懂** —— 不要求用户懂「四班三倒」这类行话，上来就能选对自己的班表。
3. **形成自己的特色**：单一入口 + 看图选班 + 可微调，不做并列的多种「排班模式」入口。
4. 日历等配套界面同步适配新增的班次形态。

### 1.3 非目标

- **不做「在日历上直接改某一天」**（也就顺带不做换班、请假、顶班覆盖）。这是本次明确排除的范围，设计上留好口子（某天的班次本就不落库，按锚点实时计算，见 §5.3），下次单独做。

## 2. 调研：市面上的倒班方式

按「每天开几个班」分家族。每一种都能拆成 `周期表 + 班组数 + 相位`：

**每天 2 个班（12 小时制）**

| 方式 | 周期 | 周期表 | 典型班组 |
|---|---|---|---|
| 两班倒「上 12 休 12」 | 14 / 30 天 | 一周白班 + 一周夜班 | 2 |
| 白夜休休 | 4 天 | 白 夜 休 休 | 4 |
| 白白夜夜休休 | 6 天 | 白 白 夜 夜 休 休 | 3 |
| 白白休休夜夜休休 | 8 天 | 白 白 休 休 夜 夜 休 休 | 4 |
| 2-2-3（Pitman）※ | 14 天 | 白 白 休 休 白 白 白 休 休 白 白 休 休 休 | 4 |
| DuPont | 28 天 | 4夜 3休 3白 1休 3夜 3休 4白 7休 | 4 |

**每天 3 个班（8 小时制）**

| 方式 | 周期 | 周期表 | 典型班组 |
|---|---|---|---|
| 四班三倒 / 四班三运转 | 8 天 | 早 早 中 中 夜 夜 休 休 | 4 |
| 五班三倒 | 5 天 | 早 中 夜 休 休 | 5 |
| 六班三倒 | 6 天 | 早 中 夜 休 休 休 | 6 |

**每天 4 个班（6 小时制）**

| 方式 | 周期 | 周期表 | 典型班组 |
|---|---|---|---|
| 五班四倒 | 5 天 | 早 中 晚 夜 休 | 5 |
| 六班四倒 | 6 天 | 早 中 晚 夜 休 休 | 6 |

**值班制（24 小时班）**

| 方式 | 周期 | 周期表 | 典型班组 |
|---|---|---|---|
| 上 24 休 24 | 2 天 | 班 休 | 2 |
| 上 24 休 48 | 3 天 | 班 休 休 | 3 |
| 上 24 休 72 | 4 天 | 班 休 休 休 | 4 |

**常白 / 非连续作业**

| 方式 | 周期 | 周期表 |
|---|---|---|
| 长白班双休 | 7 天 | 班 班 班 班 班 休 休 |
| 做六休一 | 7 天 | 班×6 休 |
| 大小周 | 14 天 | 5 班 2 休 + 6 班 1 休 |
| 做一休一 / 做二休二 / 做四休二 | 2 / 4 / 6 天 | 班休 / 班班休休 / … |

**无法用固定周期表达的**：护士 APN（按周手工排）、铁路乘务（跟车不规律）、综合工时制弹性排班。本次不做（见 §1.3）。

### 2.1 三个结论

1. **引擎不用改**。上表除 Pitman 外（§2.2）都是既有模型的实例，缺的是编辑器和模板。
2. **「几班几倒」与数据模型正交**。同一张「白白夜夜休休」周期表，3 组人跑叫三班两倒，4 组人跑就是四班两倒的变体。因此界面上**不能让用户先做术语题**——那是原版界面混乱的根源。
3. **周期必须放开到 28 天以上**。两班倒一周一倒是 14 天，DuPont 是 28 天，当前 8 天上限远远不够。

### 2.2 当前模型的表达边界

「所有班组共用一张周期表、各取不同天数偏移」这个模型能表达**班组之间只差相位**的模式——上表里除 Pitman 外全部属于此类。

它表达不了的是「**同相位、不同班次**」：两组人同一天上班同一天休息，只是组 A 上白班、组 B 上夜班。Pitman（2-2-3）就是这样，本次不覆盖，理由见 §10。这个边界要写清楚，避免以后误以为「周期表 = 万能」。

## 3. 已确认的设计决策

| # | 决策 | 取舍理由 |
|---|---|---|
| 1 | **持久层真正分成两层**：班次定义表 + 周期序列表 | 非显式签名（按字段全等隐式合并）会在新增字段时静默丢配置；显式引用把「改一次、全周期生效」的关系固定在数据里 |
| 2 | **每班组一个「周期起始日」** | 两层模型下周期里会出现多个同名单日，旧的「今天上什么班」下拉无法区分；起始日是倒班人本来就有的心智 |
| 3 | **时间挂在班次定义上，不逐天覆盖** | 同类型必然同时间；需要区分就建两个定义（如「白班(早)」「白班(晚)」）。换来周期表界面干净 |
| 4 | **模板是起点，不是类型** | 选中模板后生成的就是普通方案，数据库里没有「模板」概念，杜绝原版那种多套模式并存的混乱 |
| 5 | **不做日历改单天** | 见 §1.3 |

## 4. 数据模型（schemaVersion 6）

### 4.1 表结构

新增两张表，删除 `ShiftTypeRows`：

```dart
/// 班次定义表：一个班次只定义一次（属于某套方案）。
class ShiftClassRows extends Table {
  IntColumn  get id           => integer().autoIncrement()();
  IntColumn  get scheduleId   => integer()();
  IntColumn  get order        => integer()();          // 定义列表展示顺序
  TextColumn get name         => text()();             // 白班 / 早班 / 夜班 / 休班 …
  TextColumn get abbr         => text().nullable()();  // 日历格子里的 1~2 字简称，见 §9.1
  IntColumn  get startMinute  => integer().nullable()();
  IntColumn  get endMinute    => integer().nullable()();
  BoolColumn get isRest       => boolean().withDefault(const Constant(false))();
  IntColumn  get color        => integer().withDefault(const Constant(0xFF5B7FFF))();
  BoolColumn get alarmEnabled => boolean().withDefault(const Constant(false))();
  IntColumn  get alarmMinute  => integer().nullable()();
}

/// 周期序列表：第 N 天用哪个班次定义。
class ShiftCycleRows extends Table {
  IntColumn get id         => integer().autoIncrement()();
  IntColumn get scheduleId => integer()();
  IntColumn get order      => integer()();   // 0 起 = 第几天
  IntColumn get classId    => integer()();   // → ShiftClassRows.id
}
```

`ShiftScheduleRows` 不改动，`teamOffsets` 继续沿用（语义见 §5.2）。沿用项目现有约定，不加外键约束。

### 4.2 迁移 v5 → v6

在 `AppDatabase.migration` 增加 `if (from < 6)` 分支，用 `customStatement` 走原生 SQL（项目 v2 迁移已有同类先例）：

1. 建 `shift_class_rows`、`shift_cycle_rows` 两张表。
2. 对每套方案，按 `"order"` 读出旧 `shift_type_rows`。
3. 按签名 `(name, start_minute, end_minute, is_rest, color, alarm_enabled, alarm_minute)` 去重 → 生成班次定义行（保序，`abbr` 一律留空）。
4. 按原 `"order"` 依次写周期序列行，`class_id` 指向第 3 步命中的定义 id。
5. `DROP TABLE shift_type_rows`。

**等价性要求**：迁移后对任意日期 `shiftOn(date)` 的结果（名称、时间、颜色、是否休息、闹钟）必须与迁移前逐日相等。由自动化测试证明，见 §11。

**副作用（预期）**：用户手抄的 12 天里 4 个字段相同的「白班」会自动并成 1 个定义。空方案（跟随法定节假日、无班次行）迁完仍为空，语义不变。

## 5. 领域模型与对外接口

### 5.1 类型

```dart
/// 班次定义（解析后的班次，日历与闹钟消费的就是它）。
class ShiftClass {
  final String name;
  final String? abbr;
  final int? startMinute;
  final int? endMinute;
  final bool isRest;
  final int color;
  final bool alarmEnabled;
  final int? alarmMinute;
  bool get crossesMidnight;   // 沿用现有实现
}

class ShiftSchedule {
  final List<ShiftClass> classes;   // 班次定义
  final List<int> cycle;            // 长度 = 周期；元素是 classes 的下标
  final int teamCount, ourTeamIndex;
  final List<String> teamNames;
  final List<int> teamOffsets;

  int get cycleLength => cycle.length;
  bool get isBlank => cycle.isEmpty;
  ShiftClass? shiftOn(DateTime date);
  ShiftClass? teamShift(int teamIndex, DateTime date);
}
```

`teamShift` 内部：`idx = (daysBetween(anchorDate, date) + offset_i) mod cycle.length`，再 `classes[cycle[idx]]`。取模与负值回绕逻辑照旧。

### 5.2 班组相位

`teamOffsets[i]` 的既有语义本就是「相对基准日的**天数偏移**」（公式里加在天数上，不是当下标用），因此新交互无需改表：

- 我的班组起始日 = 基准日（保存时规范化为 `teamOffsets[我的组] == 0`）
- 某班组起始日 = 基准日 − `teamOffsets[某组]` 天
- 反向：`teamOffsets[某组] = −daysBetween(该组起始日, 基准日)`

保存时对 `anchorDate` 与 `teamOffsets` 做一次归一化（纯表示层等价变换，见 §5.1 公式，可证明不改变任何一天的排班）。效果：用户从此只需理解「我这组从哪天开始这个周期」。

**周期长度变化不影响相位**：增减周期长度时 `cycle` 长度变，但 `teamOffsets` 作为天数偏移仍成立；取模自动收敛越界值。

### 5.3 对外的稳定性

`shiftOn(date)` / `teamShift(i, date)` 的**签名与返回字段与今天完全一致**，仅类型名 `ShiftType` → `ShiftClass`。因此：

- `features/calendar/calendar_screen.dart`：只改类型名，渲染逻辑另行适配（§9）
- `features/alarm/alarm_service.dart`：只改类型名，排定逻辑不动（闹钟按天排，`_shiftBaseId + d`）
- `features/alarm/alarm_screen.dart`：只改类型名
- `ShiftAlarmOverrides` 按天覆盖表：**完全不动**

改动集中在 `domain/shift_rotation.dart`、`data/`、`features/calendar/schedule_editor_screen.dart`，以及新增的模板库与选择页。

## 6. 模板库

新增 `app/lib/domain/shift_templates.dart`：**纯 Dart 常量数据，无 Flutter 依赖，不入库**。

```dart
class ShiftTemplate {
  final String id;
  final String title;        // 人话主标题，如「上 12 小时，休 12 小时」
  final String subtitle;     // 行话副标题，如「白夜休休 · 四班两倒」
  final List<String> aliases;// 搜索词
  final String group;        // 分组：12 小时制 / 8 小时制 / 6 小时制 / 值班制 / 常白
  final List<ShiftClass> classes;
  final List<int> cycle;     // 元素为 classes 下标
  final int teamCount;
  final List<int> teamOffsets;
}
```

卡片预览**由数据生成**（`cycle` 每天对应的颜色渲成一排色块），不手绘，改数据预览自动跟随。

首批 19 个（即下表全部条目），分组陈列，顶部搜索框匹配 `title` / `subtitle` / `aliases`：

| 分组 | 模板（周期 / 班组数 / 相位偏移） |
|---|---|
| 12 小时制 | 白夜休休（4 / 4 / 0,1,2,3）· 白白夜夜休休（6 / 3 / 0,2,4）· 白白休休夜夜休休（8 / 4 / 0,2,4,6）· 白班夜班各一周（14 / 2 / 0,7）· DuPont（28 / 4 / 0,7,14,21） |
| 8 小时制 | 四班三倒（8 / 4 / 0,2,4,6）· 五班三倒（5 / 5 / 0,1,2,3,4）· 六班三倒（6 / 6 / 0,1,2,3,4,5） |
| 6 小时制 | 五班四倒（5 / 5 / 0,1,2,3,4）· 六班四倒（6 / 6 / 0,1,2,3,4,5） |
| 值班制 | 上 24 休 24（2 / 2 / 0,1）· 上 24 休 48（3 / 3 / 0,1,2）· 上 24 休 72（4 / 4 / 0,1,2,3） |
| 常白 / 非连续 | 长白班双休（7 / 1）· 做一休一（2 / 1）· 做二休二（4 / 1）· 做四休二（6 / 1）· 做六休一（7 / 1）· 大小周（14 / 1） |
| — | 我自己排（空白周期） |

相位偏移一栏是**自检基准**：`teamShift` 应保证每天恰好有「该模式应有的组数」在上班（如白白夜夜休休每天 2 组、四班三倒每天 3 组）。写模板时必须逐个验证这一点，不能只填名字。

各班组的时间随行业差异很大（早班有 6:30 起也有 8:00 起），模板填**常见值**即可，用户可改——模板负责把周期结构摆对，不负责精确到分钟。

### 6.1 模板的默认值约定

- **班次时间**：取各行业常见值，用户可改。
- **班次颜色**：从现有 8 色 `_palette` 中挑选，保证「早/中/夜/休」在不同主题下都易辨识。
- **班次简称 `abbr`**：模板显式填好（白/夜/休/早/中/晚/值），日历直接使用。
- **联动闹钟**：工作班次 `alarmEnabled = true`、`alarmMinute = 上班时间前 60 分钟`；休息班次关闭。与现有默认方案「四班两倒」的行为一致，保证用户体感连续。
- **班组数**：取该模式的典型值（见 §6 表格），但见 §7.3 —— 班组数只影响「看别的班组」，不影响用户自己的班表。
- **「我的班组」**：一律取第 0 组（`ourTeamIndex = 0`），相位偏移按 §6 表格填。用户改「我这组从哪天开始」时只动基准日，不改变班组间的相对错位。

## 7. 新建流程与编辑器界面

### 7.1 新建流程

```
排班管理 →「+ 新建排班」→ 选择你的倒班方式（独立一页）
                          → 排班编辑器（四个板块已填好）
```

选择页：卡片网格 + 搜索框 + 最后一张「我自己排」。

每张卡片 = 迷你周期表色块 + 人话主标题 + 行话副标题。设计意图：

- **只有一个入口** —— 不设「经典排班 / 自定义排班 / 扫码排班」这类并列模式。
- **说人话、行话当搜索词** —— 主标题给不懂术语的人看，副标题与 `aliases` 给会搜「四班三倒」的人用。
- **看图认班表** —— 用户扫一眼色块排列就能认出自己的班，不必读懂术语。

### 7.2 编辑器四个板块

1. **排班名称** —— 文本输入。
2. **班次设置** —— 定义列表，每条：色块、名称、简称、起止时间、是否休息、联动闹钟。可增可删。**删除仍被周期引用的定义会被拦下并提示「周期里还有 N 天在用它」。**
3. **周期设置** —— 顶部 `− N 天 +` 步进器；下面 N 行 `第 N 天 ｜ [班次下拉] ｜ 时间（只读）`。时间只读，归属定义。
   - 周期长度范围 **1–60 天**。下限 1 支持「常年白班」这类写法；上限 60 覆盖 DuPont(28) 与月度轮班。
   - 变长时新行默认引用最后一个班次；变短时截断并提示。
4. **班组**（默认折叠为一行「班组设置（可选）」）—— 班组数 **1–8**（下限从现行的 2 放宽到 1，以支持「做一休一」这类只有自己一个组的写法）、每组名称、每组周期起始日、「设为我」。

保留「跟随法定节假日」开关：打开即清空周期与定义，语义与现在的空白表一致（`isBlank`）。

### 7.3 班组数的定位

归一化后用户自己的班组永远是周期的第 1 天，因此**班组数不影响用户自己的班表**，它只决定「能不能看别的班组今天上什么」（交接班对照）。

据此，班组区默认折叠并标注「可选 · 用于查看其他班组」，避免用户纠结「我到底算几班」。

### 7.4 实时预览

编辑器顶部固定一条**未来 14 天的班次预览条**（日期 + 班次色块，色块里是班次简称）。改动任何设置实时重算。

这是原版最缺的即时反馈：用户在编辑器里就能确认「今天白班、明天休」，不必退出去翻日历再回来改。

## 8. 边界与容错

| 场景 | 行为 |
|---|---|
| 周期为空（跟随法定节假日） | `shiftOn` 返回 null，日历按 §9.4 显示「休/上班」 |
| 周期为 1 天 | 每天都取 `classes[cycle[0]]` |
| 更换周期长度后 `teamOffsets` 越界 | 取模自动收敛，不报错（§5.2） |
| 删除仍被引用的班次定义 | 拦下并提示引用天数 |
| 删除全部班次定义 | 做不到：被周期引用的定义点删除一律被拦下并提示引用天数，而周期至少引用一个定义。要清空整张表请用「跟随法定节假日」（打开即清空班次与周期，无需二次确认） |
| 班组数改为 1 | 隐藏「查看其他班组」入口 |
| 老数据迁移 | 逐日等价性由测试保证（§11） |

## 9. 日历与配套界面适配

新增的班次形态（5~6 个班组、6 小时班、24 小时值班、更长的周期）暴露出日历现有的几处硬编码，本次一并适配。

### 9.1 格子简称改为显式字段

现状 `calendar_screen.dart::_shortLabel` 靠**猜中文**取格子里的 1 个字：休息→「休」、含「白」或「早」→「白」、含「夜」→「夜」、否则取首字。

模板引入「早班」「中班」「晚班」「值班」后这套规则开始出错——例如「早班」会被显示成「白」。

改为：`ShiftClass.abbr` 显式字段（1~2 字），模板与默认配置都填好，编辑器可编辑。

- `abbr` 为空时**回退到现有猜测逻辑**，因此老数据迁移后（`abbr` 一律为空）日历显示与迁移前完全一致。
- 用户自定义的冷门班次名（「大夜」「后夜」「小夜」「卡班」）从此也能正确显示。

### 9.2 「其他班组」改为色块列表

现状 `_otherTeamsText` 把所有其他班组拼成一整行文字（`A班·白班　B班·夜班　…`）。班组数到 5~6（五班三倒、六班三倒、六班四倒）时会折行甚至溢出。

改为：横向 `Wrap` 排列的「色点 + 组名 + 简称」小标签，用班次颜色区分，6 组也能排下。

### 9.3 跨午夜与 24 小时班

「上 24 休 48」的班次是 `08:00 – 次日 08:00`，跨午夜 24 小时。

**约定保持不变**（与现有「上夜班记在开始那天」一致，见 PRODUCT_SPEC §3）：一个班次记在它**开始**的那天。因此 24 小时班次的后一天在格子里显示为「休」，这是预期行为——日详情里的时间范围会写明「08:00 – 次日 08:00」，用户能看清早上才下班。

本次不改这个模型（改了会牵动闹钟排定），仅在日详情里确保跨午夜提示清晰。

### 9.4 空白表与节假日

「跟随法定节假日」方案的日历行为不变：`shiftOn` 返回 null 时按 `isBlank` 分支显示「休 / 上班」。

### 9.5 配色

模板里各分组的班次配色从现有 8 色调色板中统一挑选，保证：

- 同一周期内不同班次颜色可区分（8 色足够，单周期最多 6 个定义）；
- 深浅两套主题下都保持可读；
- 与现有日历配色语言一致，不引入新色系。

## 10. 范围外（本次明确不做）

- **日历上直接改某一天**（含换班、请假、顶班覆盖）——§1.3。
- **2-2-3（Pitman）等「固定日班组 / 夜班组」型模式**。这类模式的四组里，日班组与夜班组处在**同一相位**（同一天上班、同一天休息），只差班次类型。而当前公式是「所有班组共用一张周期表、各取不同偏移」，相位差异最多只有 `cycleLength` 种，做不出「同相位、不同班次」。要支持需改成每班组一张周期表，成本与收益不成比例（该模式在国内少见）。
  §2 的调研表保留 Pitman 仅作为调研记录，不进模板库。
- 周期中间插入/删除某一天（用周期长度步进器 + 逐天下拉调整即可覆盖）。
- 护士 APN、铁路乘务这类无固定周期的排班。
- 班次定义跨方案复用、独立的「班次库」管理页。
- 工资 / 补贴 / 工时统计。
- 节假日顺延（`cycle` 遇法定节假日暂停推进）——保留现有「跟随法定节假日」的空白表方案即可。
