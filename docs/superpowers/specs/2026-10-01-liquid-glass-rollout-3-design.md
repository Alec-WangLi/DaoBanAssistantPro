## 1. 目标

v0.10.10 真机反馈的三件事：

- **A. 彩边「穿到滑块里边、不规则、不贴边」** —— 用户原话：「你不觉得这个彩边贴错位置了吗？
  我们要求的是彩边只在滑块的边缘……它已经穿到滑块里边了，而且还不规则，也不贴边。
  你参考一下底部导航栏那个滑块，人家的彩边是怎么贴在边缘的……该缩小就缩小」。
- **B. 开关的头大尾轻没出现** —— 原话：「这个滑块怎么还没有加入头大尾轻这个特效啊？」
- **C. 长按滑块再竖直滑走页面，滑块冻在放大那一刻**，要再点一下才恢复。

## 2. 用户拍板的（不可自行更改）

1. **「跟随滑块的亮带」三处都关掉，滴自己的白边保留。**
   底栏、分段器、开关一视同仁（开关自 v0.10.9 起就关着）。
2. **开关的钮按住时纵向拉长** —— 本轮候选样图里的「右」（`protrude 9`；横向那个数见 §4.2：
   真机反馈「上下有点尖尖的」之后定成 `+2`）。
   原话是「右，拖动的时候还要加上头大尾轻的效果（左右）」。
3. **头大尾轻是左右**，跟着拖动方向走，与底栏同一套。原话：「特效肯定要跟着拖动走，
   就跟底部导航栏那个液态玻璃滑块一样……头重脚轻肯定不能是上下的，肯定要左右」。
4. **彩边该缩小就缩小**：开关取与底栏**同一占比**的数（≈ `0.25`，推导见 §3.4）。

## 3. 这一轮量出来的四条（写进地基，别只当这一版的做法）

### 3.1 `toPath()` 的竖直档是「三个子路径并起来」——描边会把内部接缝画出来

⚠️ **这是真机上正在发生的缺陷，不是本轮引入的。**

`宽 ≤ 高` 时 `toPath()` 走一条兜底分支（v0.10.3 为窄窗加的）：

```dart
..addOval(上圆) ..addOval(下圆) ..addRect(中间那块)
```

**填色**是对的（nonzero 绕数出来就是一枚竖直胶囊），但**描边不是** —— 描边会把三个子路径的
**每一段边界**都画出来，包括它们互相重叠的**内部接缝**：

- 两个圆的**内侧弧**（各自朝里的那半圈）；
- 两个圆心那两条**水平弦** + 矩形上下沿。

而四层光谱**全部是描边**（`_paintSpectralRing` / `_paintHalo` 两层 / `_LensGlowPainter`）。
于是钮的内部出现横线与弧线 —— 正是用户说的「穿到里面、不规则、不贴边」。

**对照实验**（把 `rimScale` 置成 `0.001`，四层光谱一起不画，几何与位置一字不差）：
彩边一关，钮里**一条线都没有**。所以那些线是彩边画的，不是轨道轮廓透出来的。

**它现在就在用户手机上**：v0.10.10 的开关按住时 `宽 29.69 / 高 33.38`（宽 < 高）→
**正好落进这一档**。底栏在窄窗（200×400，`itemW 39`）按住时也一直中招，只是没人盯着那一档看。

### 3.2 同一条分支**不读** `_leading` / `_trailing` → 头大尾轻在纵向档里画不出来

竖直档用的是 `r = width / 2` 的**两个等半径**圆，`_leading` / `_trailing` 在那里是算了但没用。

**所以「纵向拉长」与「左右头重脚轻」在当前实现里互斥** —— 与速度门调多低无关。
（用户看到的现象：给了纵向拉长的候选那一档，尾巴就没了；没给的那一档，尾巴在。）

### 3.3 `lensVelocityRef` 是全局的 900px/s，而开关一格只有 25px

形变强度走「位置的真实帧间差分 ÷ `lensVelocityRef`」，再经过形变弹簧。同一个手指速度下，
钮能走的**帧数由格宽决定**：

| 一格多宽 | 手指速度 | 走几帧 | 峰值形变 |
|---|---|---|---|
| 88px（底栏） | 800 px/s | 7 | **0.77** |
| 88px | 1500 px/s | 4 | **0.81** |
| 25px（开关） | 400 px/s | 4 | **0.27** |
| 25px | 800 px/s | 2 | **0.22** |
| 25px | 1500 px/s | 2 | **0.28** |

**越快反而越短**（到得更早、走得更少帧）。后果：尾巴该收 35%、实际只收 10%
（实测前缘半径 15.3 / 后缘 14.3，只差 1px）——所以开关上「形状完全没变」。

### 3.4 `rimScale` 在开关上的**占比**是底栏的两倍

`rimScale` 同时乘着四层光谱的**宽度与模糊**。内晕往轮廓里伸进去约 `(10/2 + 3) × k`：

| | `k` | 内晕伸进去 | 滴宽 | 占比 |
|---|---|---|---|---|
| 底栏 | 1.0 | 8px | 98 | **8%** |
| 开关 | 0.469 | 3.75px | 23 | **16%** |

要跟底栏同一个占比，开关取 `k ≈ 0.23` —— 取整 **0.25**。

**一条注意**：`rimScale` **同时**乘着浮起阴影的偏移与模糊（v0.10.10 捆进来的，理由是「它也是
占满轨道的一半」）。收到 0.25 之后阴影模糊从 4.69px 掉到 2.5px。这一轮**先捆着走**，
理由与对策见 §8。

## 4. 改什么

### 4.1 `toPath()` 的竖直档改成同一套闭式解（一次修好 3.1 与 3.2）

不再并三个子路径，而是把**横着那套外公切线构造**拿来、按目标宽搭好，再**纵向拉伸**到目标高：

1. 先在局部坐标系里按**目标宽 `w`** 建一条两半径**横**胶囊路径 —— 闭式解照抄现有实现；
2. 再用 `Path.transform` 把它**纵向拉伸** `sy = 高 ÷ (2 × max(rl, rr))`、搬回透镜中心。

得到的是**一条闭合子路径**，而且**天然带两个半径** —— 竖直档因此也能头大尾轻。

⚠️ **收尾必须是「拉伸」，不是「整体转 90°」。** 转过去之后局部坐标的「左右两端」会落到
屏幕的**上下**两头，「头大尾轻」就变成「上大下小」—— 而那正是用户明确否掉的
（「头重脚轻肯定不能是上下的，肯定要左右」）。**拉伸**两样都保住：前后缘还在左右，
上下同时被拉长。落在屏幕上就是「两枚高低不同的椭圆 + 外公切线」。

- **选朝向**：`宽 ≥ 高` 走原来那条（横向，一个字都不改）；`宽 < 高` 走拉伸这条。
- **局部那两个圆的半径不能直接用 `_cap`（= 宽/2）。** 拉伸**不能**把两端的圆变回来：
  `rl + rr ≥ 宽` 时尾部整个落进头部圆里，轮廓退化成**一个圆**、尾巴消失 —— 而且 `mx`
  正好等于 1、踩 `arcTo` 扫 2π 那个坑。取 `capV = 宽/2 × (1 − 0.175 × stretch)`，
  把收缩的余量留出来。
- **圆心距 `d` 要钳一个正的下限。** 两个**等半径**的圆、圆心距又正好等于 `2r` 时
  （形状是个正圆）`d = 0`，`mx = (rl − rr) / d` 就是 `0 / 0`。钳住之后 `mx = 0`、
  `my = 1`、`theta = π/2`：外公切线是一条竖直线、两端圆弧各扫 π —— 精确、也不碰
  `arcTo` 扫 2π 那个坑。（`stretch = 0` 时余量归零、局部就是个正圆，正是靠这道钳位兜住。）
- **横向档（`宽 ≥ 高`）一个字都不改**：它的 `d = 宽 − 高 + 0.175 × stretch × 高` 恒为正，
  钳不到；`addOval×2 + addRect` 那版**整个删掉**。
- ⚠️ **竖直档「两半径相等 ⇒ 精确退化成胶囊」这条性质*不*成立** —— 等半径时局部是个正圆，
  纵向拉伸之后是一枚**竖着的椭圆**。（胶囊要求「长 = 直径」，而这一档的前提恰恰是 `高 > 宽`。）
  横向档那条性质不受影响，照旧由既有用例钉着。
- **`宽 = 高` 的边界**要在计划里显式验一次：路径非空、面积 > 0、`getBounds()` 不退化成 `Rect.zero`。

**代价（写清楚：这是取舍，不是疏漏）**：纵向拉伸会把端头从**半圆**变成**椭圆** —— 拉得越长，
上下两端看着越尖（顶点的曲率半径 = `宽² ÷ (2 × 高)`，不拉长时正好是 `宽/2`）。
**「上下圆头」与「左右不对称」在这个形状族里是互斥的**：圆头要求两端都是半径 `宽/2` 的
半圆，那就左右对称了。要同时做到得换一套几何（椭圆端头 + 贝塞尔），另开一轮。

### 4.2 开关的几何

| 项 | 现在（v0.10.10） | 改成 |
|---|---|---|
| `protrude` | `30 × 0.15625 = 4.69` | **9** |
| `liftWidth` | `4.69` | **+2**（真机反馈之后定的：满升程 27 × 42） |
| `rimScale` | `30 ÷ 64 = 0.469` | **0.25** |
| `velocityRef` | 全局 900 | **180** |

- 尺寸 56 × 30，以及拖动手势、触觉、`moveToSlot: false`、`followFinger: false` —— **都不动**。
- 按住满升程 ≈ **23 × 42**（纵向拉长）。
- 拖动时的头大尾轻靠两件事：4.1 让竖直档读 `_trailing`，4.3 让形变积得起来。

### 4.3 `velocityRef` 变成每面的数

`LiquidLensMetrics` 加一个字段（与 `protrude` / `liftWidth` / `rimScale` 同一个道理：**每面各自的观感**）：

```dart
const LiquidLensMetrics({..., this.velocityRef = AppTokens.lensVelocityRef});
```

`LiquidLensController` 构造时收它，`_onTick` 里 `_stretch.target` 用它。

| 调用点 | `velocityRef` |
|---|---|
| 底栏 | **900（全局，保持不变）** |
| 分段器 | **900（同上）** |
| 开关 | **180** |

### 4.4 关掉「跟随滑块的亮带」

- `LiquidTrack.showGlowBand`：**默认从 `true` 改成 `false`**（三处都不再画），开关那两个显式的
  `false` 一并去掉。
- `CapsuleRimPainter` 的 `sliderIndex` / `tabCount` / `trackPad` 若因此再无用处，**连同那段亮带
  一起删净** —— 不留死参数。
- ⚠️ **底栏与分段器的「方向性边光」必须留着**（那是「这是一块玻璃」的读法，任何一档都要有）。
  v0.10.9 踩过一次：拿这个开关包住整个 painter，轨道变成一块平色板。

### 4.5 升程冻死（用户报的第三条）

**根因**在 `LiquidLensController`：`_syncTicker()` 判断「还要不要推帧」用的是 `_lift.isAtRest`，
而它比的是弹簧的 `value` 与 `target` —— **`target` 只在 `_onTick` 里才被刷新**。
`tapCancel()`（竖直滑走时触发）把「按住」翻成 false 之后**立刻**调 `_syncTicker()`，
此时 `value == target == 1`，于是判定「已经静止」→ **把 ticker 停了** → `_onTick` 再也不跑 →
`target` 永远停在 1 → **升程冻死在满档**。

**实测**：按住 1.2 秒再竖直滑走 → 升程**一个数字都不动地卡在 1.0**，`hasScheduledFrame = false`。
再点一下会好，正是因为 `press()` 把 `_pressed` 翻回 true、ticker 被重新拉起来。

它是**临界**的：按住 400ms 就滑（那时弹簧速度还没落到 1 以下、不算静止）看不见 ——
所以它只在「按得够久、弹簧停稳之后再滑」时出现，而这正是真机上的常态。

**修法**：`_syncTicker()` 里**先按当前意图刷新 `_lift.target`**，再判静止。
抽成一处（`_retarget()`），`_onTick` 与 `_syncTicker` **共用** —— 两处各写一遍迟早走偏。

**同一个 `tapCancel()` 还漏了两样**（同类：取消之后没回到该有的样子）：

1. **`_previewIndex` 不清** → 分段器的高亮停在手指按下那一格；
2. **位置不回退** → `press(moveToSlot: true)` 已经把滴滑到手指那一格了，取消后它留在那儿，
   而页面并没有切。

第 2 条是**行为改动** —— 现有注释写着「点按结束触发的 cancel 不该回退位置」。本规格改成
**取消 = 当作没点过**：`tapCancel()` 返回「是否真的取消了」，由调用点 `snapTo(已提交那一格 + 0.5)`
（`_cancel()` 里已经是这个写法）。**底栏与分段器的观感会因此变**，这正是用户报的
「滑块定格」的另一半。

**开关不受第 2 条影响**：它 `press(moveToSlot: false)`，按下本来就不挪钮，没得回退
（`onTapCancel: _lens.tapCancel` 这个 tear-off 在返回类型改成 `bool` 之后照样合法）。

## 6. 守门与工装

### 6.1 逐像素

- **标准档（关掉液态玻璃）必须逐像素不变** —— 这条验收不变，覆盖全部 `00_home_shell_*`
  与各页的标准档。
- **液态档允许变**：底栏与分段器（亮带关了）、开关（几何与彩边）。**逐张看过再接受**，
  不接受「差异名单里没印出来」当结论。
- 已知假象照旧：`08_ringing_*` 的时钟跳字。

### 6.2 新的护栏

| 断言 | 反向验证（去掉修复必须变红） |
|---|---|
| 竖直档是**一条闭合子路径**：`shape.toPath().computeMetrics().length == 1` | 改回 `addOval×2 + addRect` |
| 竖直档**不画内部接缝**：光栅化，钮的竖直中轴上不出现横向彩色线 | 同上 |
| 竖直档**也能头大尾轻**：`stretch = 1` 时 `leftRadius != rightRadius` | 把 `_trailing` 换成 `_leading` |
| **两半径相等 ⇒ 精确胶囊**（**只有横向档成立**；竖直档等半径是一枚竖椭圆，见 §4.1） | —— |
| **升程不会冻死**：按住够久（弹簧停稳）→ 竖直滑走 → `lift` 回到 0 | 去掉 `_syncTicker` 里的 `_retarget()` |
| **`tapCancel` 之后**：`previewIndex == null`、`pressed == false` | —— |
| **`velocityRef` 是每面的数**：同一手势下开关的峰值形变显著高于全局那档 | 把开关的 `velocityRef` 换回 900 |

### 6.3 屏单与动图

- 屏单补 / 重出：`43_switch_liquid_*`（**按住**与**拖动中**两态，本轮两个都要）、
  底栏与分段器的液态档各一张（确认亮带关掉之后的观感）。
- 动图：开关「按住 → 拖动 → 松手」的完整过程，**浅 / 深各一条**；
  **16ms 一帧、`--fps 62`、裁剪宽度不缩放、`--colors 256`**（见 §7）。
  彩边只在**动**的时候才画，所以静帧样图结构性地看不见它 —— 这一轮的争议正出自这里。
- **窄窗（200×400）必须出** —— 底栏那一档本来就在踩同一条兜底分支。

## 7. 动图管线（沿用上一轮定死的）

`--width` 取裁剪宽度（**不缩放**）、`--colors 256`、`--fps 62`（16ms 出帧）。
彩边是两三个像素宽、低饱和、与背景反差小的东西，最经不起缩放与量化两道一起上。

**另记一条本轮踩到的判读陷阱**：GIF 只有 256 色，抖动会把一圈渐变彩虹抖成杂色斑点 ——
同一张四档对比图，肉眼看「四档差不多」，去数色相才发现 `.469` 铺满 149°→303°、
`.10` 只有 233°→252°。**判断彩边的量，用 PNG，不要用 GIF。**

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| 竖直档换构造之后形状有细微变化（那条兜底分支一直在用） | 三角对拍：`lift ∈ {0, 0.5, 1} × stretch ∈ {0, 0.5, 1}` 逐张出图比对新旧轮廓。**并集那版本来就有内部接缝，所以「像素不变」在这里不是目标，「外形相符」才是** |
| 关掉亮带让底栏观感变单薄 | 出图逐张看；亮带本来只剩溢出那半截，方向性边光还在 |
| `rimScale` 收到 0.25 后浮起阴影也变小（捆在一个数上） | 先捆着走（一个数）；出图时若「浮起来」的读感明显变弱，再拆成两个数 —— **拆之前先跟用户确认** |
| 位置回退是行为改动 | 底栏与分段器各出一条「滑走之后滴回到已提交那一格」的用例；出图确认没有跳变 |
| 删亮带时误伤方向性边光 | 见 §4.4；边光任何一档都要有 |
| `宽 = 高` 这个交界处没人验过 | 计划里显式造一个 `宽 == 高` 的几何，断言路径非空、面积 > 0、`getBounds()` 不退化成 `Rect.zero` |
| **纵向拉长把端头从半圆变成椭圆 → 上下看着尖**（拉得越长越尖，曲率半径 = `宽² ÷ (2×高)`） | 这是取舍不是疏漏（§4.1 末尾）：圆头要求两端都是半径 `宽/2` 的半圆，那就左右对称了。真要两样都要，得换一套几何（椭圆端头 + 贝塞尔）—— **先跟用户确认拉多长**，别自己调 `protrude` |

## 9. 明确不做的

- 按钮 / 胶囊 / 芯片 / 输入框的液态档（仍是另一套设计，另开一轮）。
- 把「跟随滑块的亮带」改成「压暗保留」—— 用户已选「三处都关」。
- 把端头从圆改成椭圆（本轮不需要：转了 90° 的闭式构造已经够用）。
- 改 `lensVelocityRef` 的**全局**值（底栏与分段器必须逐像素不变）。
- 重做 `08_ringing_*` 那个时钟跳字的假象。
