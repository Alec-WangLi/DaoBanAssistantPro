# 按月排班：每月重新归零的切段规则

- 日期：2026-10-13
- 起因：用户反馈（转述）——「我们现在的排班表好像都是按周期来的。这个用户想按月份来，比如每个月的前 10 天都是中班，接着再 10 天是白班，最后剩下的都是夜班。」
- 后续补充的证据：用户发来两张 App 内截图（2026 年 10 月 / 12 月）+ 实测结论
- 影响版本：下一个测试版（`0.11.15+162` 起；`X.Y` 由用户定，AI 只动末位 `Z`）
- 相关既有规格：`2026-09-29-multi-schedule-chaining-design.md`（时段衔接）、`2026-09-29-schedule-timeline-redesign-design.md`（段独立成表）、`2026-09-29-recurring-todos-design.md`（按月那条先例）

---

## 1. 要解决的事

### 1.1 现有模型装不下「按月归零」

引擎是**连续周期**：`方案.teamShift(i, 日期)` 取 `(目标日 − 基准日 + 班组错位) mod 周期长度`（`domain/shift_rotation.dart`）。它是「离基准日多少天」，与月份没有任何关系。

用户要的是**每月 1 号重新归零**：每月的第 1–10 天中班、11–20 天白班、21 号到月底夜班。两者的差别全在**月份长度不等**（28 / 29 / 30 / 31）上，所以没有任何固定周期长度能表达它。

**用户的截图把这件事钉死了。** 他库里那套现在是个 **31 天周期**、基准日落在 10 月 1 日：

| 月份 | 天数 | 结果 |
|---|---|---|
| 2026-10 | 31 | **完全正确**：中 1–10、白 11–20、夜 21–31 |
| 2026-11 | 30 | 看起来也对（1 号仍落在周期第 0 格），但周期已经欠了一天 |
| 2026-12 | 31 | **错的**：12/1 落在周期第 31 格 = 显示成**夜班**（应当是**中班**），从 12/2 起整张表晚一天（中 12/2–11、白 12/12–21、夜 12/22–31） |

也就是**每过一个 30 天的月就多欠一天、越走越偏**，而界面上完全看不出原因。

### 1.2 这个班表的真实形态（用户确认过）

- **一天不休**：整月每天都有班次，没有休班。
- 中班 15:30–23:30（闹钟 14:30）、白班 07:30–15:30（闹钟 06:30），夜班按同一套推是 23:30–07:30。
- 每段 10 天，第三段吃掉当月剩余（31 天的月里是 11 天）。

### 1.3 要做到什么程度（用户拍板）

- 不做成「照他这样固定三段」的专款，做成**通用件**：每月想切几段、每段从第几天起，都能自己设。
- **支持多班组**：他这种三班倒的厂里，别的班组就是按段错开在倒。

## 2. 目标 / 非目标 / 反目标

**目标**

- 一套方案可选两种模式：**按周期轮换**（现状，一字不动）或**按月排班**（新）。
- 按月排班 = 一张**有序段表**：「每月的第 N 天起 → 某个班次」，第一段恒从 1 日起，最后一段自动到月底。
- 每月 1 号重新归零。**月长不等是它的本职，不是要绕开的边角。**
- 多班组按**段**错开（见 §3.3）。
- 两个入口都要：新建排班的选择页一张卡 + 编辑器里的模式切换（用户拍板「两个都要」）。
- **闹钟、桌面小组件、按天改班、多套方案按日期衔接这四条链路零改动**（见 §7 的论证）。

**非目标**

- 不做「每个自然月各设一套」（那等于每月手排一张表，是本功能的另一种形态，且与「多套方案按日期衔接」重叠）。
- 不做按周 / 按年锚定。按月是这一轮唯一要的锚。
- **不给「按月」出内置模板**（沿用既有决定：有过自定义排班与「我的模板」之后，补内置模板目录不收敛）。
- 不改 `anchorDate` 列的形状（按月模式下它不再被读取，但保留原值，不做回填 / 不做清理）。
- 不碰桌面小组件的原生侧（`RemoteViews`）：快照仍然是「逐天算好再投递」，与今天一字不差。

**反目标**（技术上做成了也算失败）

- **把老库改坏**。没有任何一套既有方案会自动变成按月模式：`monthly` 的默认值是 `false`，从 v13 及更早升上来时恒为 `false`，行为与升级前逐字相同。
- **在月份边界上静默错一天**。判断这一条的标准是「12 月 1 日必须显示中班」——它就是用户报的那个现象。
- **让周期模式的行为有任何变化**。周期模式的读、算、显示、闹钟全部不得改动；`shift_rotation_test` 的既有用例一条都不许改绿。

## 3. 核心模型

### 3.1 一套「按月切法」

```
MonthlySegment { int startDay; int classIndex; }
```

一条**有序**列表，约束：

- `startDay[0] == 1`（第一段恒从 1 日起）。
- 严格递增：`startDay[i] < startDay[i + 1]`。
- `1 <= startDay[i] <= 31`，且 `startDay[i] <= 31 − (n − 1 − i)`（要给后面的段留出位置；最后一段的 `startDay <= 31` 自然满足）。

某一天的班次 = **最后一个 `startDay <= 当日号数` 的段**。

**只有起始日、没有结束日**，最后一段自动延伸到月底。这是本设计里唯一一处「少给一个字段」的地方，理由有两条：

1. **它让「空档」与「重叠」在结构上不可能出现** —— 任何把一个月切开的办法都是「从某天起换一个班」，而人一天不可能有半个班。
2. 它天然表达「最后剩下的都是夜班」：31 天的月里第三段是 11 天、30 天的月里是 10 天、2 月只有 8 天 —— **月份长度变化被算进语义里，而不是被当成例外去补**。

**一个连着来的后果（不是 bug，要在界面上说在明处）**：起始日填 29 / 30 / 31 的段，遇上 2 月就整月不出现。日历本身如此。

### 3.2 锚定方式

```
段下标 = 最后一个满足 startDay <= 当日号数 的段
```

**不读 `anchorDate`、不读「离基准日多少天」。** 这就是「每月 1 号归零」的全部实现 —— 1 号恒等于「当日号数 = 1」，而第一段的 `startDay` 恒为 1，于是每月 1 号必然落在第一段。

### 3.3 班组错位：**按段，不按天**

这一条是推演出来的、不是拍出来的，**实施时不要「优化」回按天**。

设段界在 1 / 11 / 21，三个班组。若按**天**错开（甲 0 天、乙 10 天、丙 20 天）：

| 日期 | 甲 | 乙 | 丙 | |
|---|---|---|---|---|
| 11 号 | 白 | **夜** | **夜** | ✗ 乙丙撞班 |
| 21 号 | 夜 | 夜 | 白 | ✗ 甲乙撞班 |

根因是**月份边界与「31 天」这套天数算式对不齐**：乙的段界落在 11 / 21 号，丙的落在 12 / 22 号 —— 取哪个偏移组合都有一处撞（`0/10/20` 撞 11 号，`0/10/21` 撞 31 号）。硬凑出来的是假象。

按**段**错开则是干净的：**甲从第 1 段入场、乙从第 2 段、丙从第 3 段** ——

```
组 i 在某天的班次 = 段[(当日段下标 + segOffset[i]) mod 段数].classIndex
```

三个班组因此**都在 1 / 11 / 21 号同时换班**，只是换到不同的班次上：

| 日期 | 甲 | 乙 | 丙 |
|---|---|---|---|
| 5 号 | 中 | 白 | 夜 |
| 15 号 | 白 | 夜 | 中 |
| 25 号 | 夜 | 中 | 白 |
| 31 号 | 夜 | 中 | 白 |

无撞班，且跨月归零对三组同时生效。这正好对上三班倒的现实：**每天三班都有人、一天不休**。

> **段的长短不跟着错位变** —— 错位转的是「这段分配哪个班次」，不是段的位置。所以乙在 11–20 号上夜班、丙在 11–20 号上中班，两组的段界是同一天。这也是它与周期模式在观感上最不一样的地方：周期模式下各组的段界本来就可能错开，按月模式下**所有组永远同一天换班**。

### 3.4 两种模式的关系

**一套方案二选一**，由 `ShiftSchedule.monthly` 决定读哪一边。两边**各存各的、切换不丢数据**（用户拍板）：切到按月再切回来，周期序列还在；反之亦然。

### 3.5 `monthly` 这个标志是**唯一**的模式判据

`isBlank`（「这套是不是跟随法定节假日的空白表」）当前等于 `cycle.isEmpty` —— 那个写法默认了「周期是唯一的规则」。既然两边各存各的，**判据必须落在「当前这一边有没有内容」上**：

```dart
bool get isBlank => monthly ? monthlySegments.isEmpty : cycle.isEmpty;
```

**不许在任何地方用 `monthlySegments.isEmpty` 或 `cycle.isEmpty` 去猜当前是哪种模式。** §3.4 的「切换不丢数据」决定了**两边可以同时非空**：用户切到按月、又切回按周期之后，段表还留在库里而 `monthly == false` —— 拿数据去猜就会让日历**无视用户的选择**继续按月算，不报错、只在月份边界上错一天（正是 §2 反目标要挡的那一类）。反方向（`monthly == true` 而段表为空，比如半配置或模板）同理。

读这个标志的完整清单（实施时逐处确认，别漏）：`teamShift` 的分叉（§5.1）、`isBlank`、编辑器那个分段器与 `_draftSchedule`、`saveSchedule`、`ScheduleChain.hasCycle`（§7）、桌面小组件那个 `!isBlank` 判据。

不改 `isBlank` 的后果同样是静默的：一套按月方案会被当成空白表 —— 日历上整月不画胶囊、桌面小组件写「还没有排班」。

## 4. 数据模型与迁移

**schemaVersion 13 → 14**，全部是**纯新增**（不重建既有表、不动既有数据）。

### 4.1 新表 `ScheduleMonthSegmentRows`

与 `ShiftCycleRows` 同形（表名带 `Rows` 后缀是必须的，drift 会按表名生成行类）：

| 列 | 说明 |
|---|---|
| `id` | 自增 |
| `scheduleId` | → `shift_schedule_rows.id` |
| `order` | 段序（界面上的顺序） |
| `startDay` | 每月第几天起（1..31） |
| `classId` | → `shift_class_rows.id` |

**存 `classId` 而不是下标**，与 `ShiftCycleRows` 同一个理由：`classes` 的下标会随编辑器里增删班次而挪动，而库里的行不能跟着挪。

### 4.2 `ShiftScheduleRows` 增两列

- `monthly` BOOL NOT NULL DEFAULT 0
- `teamSegOffsets` TEXT NOT NULL DEFAULT '' （逗号分隔的**段偏移**，见 §3.3）

**为什么另开一列而不是复用 `teamOffsets`**：那一列存的是**天数**偏移，这一列存的是**段**偏移，两者单位不同。让同一列的含义随 `monthly` 变化，正是这个仓库反复付过代价的那类静默错误（列名看不出单位、读代码的人要先去别处查标志位才知道自己读到的是什么）。**别合并。**

### 4.3 `CustomTemplates`（我的模板）增三列

- `monthly` BOOL NOT NULL DEFAULT 0
- `monthSegments` TEXT NOT NULL DEFAULT '' （`startDay:classIndex` 逗号分隔，**存下标** —— 模板里的班次没有稳定身份，与 `cycle` 那条约定一致）
- `teamSegOffsets` TEXT NOT NULL DEFAULT ''

模板是**只读快照**，继续整块存列、不拆表（既有决定，理由见 `AGENTS.md`）。

### 4.4 迁移分支

`onUpgrade` 新增一段，**放在最前**（`from < 13` 之前 —— 分支按倒序跑，最新的一版先跑，与既有写法一致）：

```dart
if (from < 14) {
  await m.createTable(scheduleMonthSegmentRows);
  await m.addColumn(shiftScheduleRows, shiftScheduleRows.monthly);
  await m.addColumn(shiftScheduleRows, shiftScheduleRows.teamSegOffsets);
  await m.addColumn(customTemplates, customTemplates.monthly);
  await m.addColumn(customTemplates, customTemplates.monthSegments);
  await m.addColumn(customTemplates, customTemplates.teamSegOffsets);
}
```

（`custom_templates` 是**三**列，见 §4.3 —— 别按 §4.2 那个「两列」的形状顺手少写一列。）

⚠️ **`from < 13` 那段会跑 `TableMigration(shiftScheduleRows)` 重建方案表**。放在它**之前**加列是安全的（`TableMigration` 按**当前 schema** 重建、按列名拷数据，新列会带着默认值过去）；放在它**之后**则要面对「刚重建完又 ALTER」的组合。**这一条必须由两条迁移测试兜住**：`migration_v13_to_v14_test.dart`（主力）与一条从 **v10** 直接升到 v14 的（盖住「新列加完之后还有好几段重建在跑」这条路径，照 `migration_v9_to_v10_test.dart` 的先例）。

### 4.5 连带删除

新表是方案行的子表，**三条路径都要带上它**：

- `saveSchedule` 的「删掉不在新列表里的班次定义」那一段（清理引用被删班次的段行，照它删 `shiftDayOverrides` 的写法）。
- `deleteSchedule`。
- `clearAll`。

漏任何一条的症状都是「库里攒着指向不存在班次的段行」—— 装配时得再兜一次底，且界面完全看不出来。

## 5. 领域层

### 5.1 `domain/shift_rotation.dart`

- 新增值类型 `MonthlySegment { startDay, classIndex }`（`==` / `hashCode` / `toString`）。
- `ShiftSchedule` 增三个字段：`monthly: bool`、`monthlySegments: List<MonthlySegment>`、`teamSegOffsets: List<int>`。
- `isBlank` 按 §3.5 改。
- 新增 `int get monthSegmentCount => monthlySegments.length;`（撞班提示、一键均分、界面上「第 N 段」都要它，别各写一遍 `.length`）。
- `teamShift(i, date)` 分叉。**判据是 `monthly` 标志，不是 `monthlySegments.isEmpty`**（理由见 §3.5）：

  ```dart
  if (!monthly) { /* 原周期算式，一字不动 */ return /* 原返回值 */; }
  // 段表为空（半配置 / 脏数据）与空白表同一条路
  if (monthlySegments.isEmpty) return null;
  final seg = _segmentIndexOn(date);        // 最后一个 startDay <= 当日号数
  final off = i < teamSegOffsets.length ? teamSegOffsets[i] : i - ourTeamIndex;
  final ci = monthlySegments[(seg + off) % monthlySegments.length].classIndex;
  if (ci < 0 || ci >= classes.length) return null;
  return classes[ci];
  ```

- 新增私有 helper `int _segmentIndexOn(DateTime date)`（线性扫 ≤31 项，够快）。

- **越界只有一条出路：返回 null**（与「空白表返回 null」同一条纪律）。按月模式下**没有周期可以退**，所以别写成「回退到轮转」—— 那句话在周期模式里成立、写在这里是句空话。不抛异常这条照旧。
- `shiftOn` 不动（先查 `dayOverrides`、再问 `teamShift`）—— 按天改班因此自动在按月模式上生效。

### 5.2 `crewClashes`

现在的实现是「扫**一个完整周期**就够」（班组错位是常数偏移，整张表以周期长度重复）。**按月模式下这句话不成立** —— 一个月的长度在 28~31 之间变，真正的周期是**四年**（1461 天，含闰年 2 月 29）。

做法：按模式分叉。

- 周期模式：**原样不动**（一个字都不改，既有护栏继续钉着）。
- 按月模式：从 `2020-01-01`（闰年，保证 2 月 29 日出现）起逐日扫 **1461 天**，按**当日号数**去重后报出来。

`CrewClash.cycleDay` 那条字段在按月模式下装的是**当日号数**（1..31），含义由模式决定 —— 所以**为它写一行注释**。

⚠️ **按月模式的提示句不带天数。** 四年扫下来按当日号数去重，得到的是**各种月长的并集**（某次撞班只在 31 天的月里发生在 5 号，也会进这个集合），所以那个数字说不清是「哪个月里的几天」—— 报出来是个偏大的假数。按月模式下的撞班本来就是「班组数比段数还多」这类配置错误，说清**是谁撞谁**就够：文案走一句**不带数字**的版本（见 §6.5），按月分支里连 `days` 都不算。

### 5.3 `evenTeamOffsets`

函数体是通的：`evenly[i] = round(i × n ÷ count)`，在按月模式下把 `n` 传**段数**（而不是周期长度）即可，得到的即「第 i 组从第几段入场」。`keepIndex` / `keepOffset` 的语义不变（我们班组原地不动）。

⚠️ **在注释里写明这一点**（「传段数就是按段均分」），否则下一个人会以为它只服务周期模式。

### 5.4 `ScheduleChain` 的两个指纹（**这一条最容易漏**）

`domain/schedule_chain.dart`：

- `_rotationOf(schedule)` **必须**加进：`monthly`、`monthlySegments` 的 `startDay:classIndex` 串、`teamSegOffsets`。
  不加的后果就是 v0.10.21 那两处同一个病：**「改完之后界面没跟上」，且完全静默** —— 换一次按月切法而桌面小组件不重推、信息卡「本月统计」显示旧数字。
- `_sourceKey(schedule)` 里的 `isBlank` 已经够了（信息卡高度只看组名 / 简称 / 是否空白表 / 时段），**不要顺手往里加切法** —— 那个键的职责是「会影响卡片高度」，加宽只会让缓存白失效。

### 5.5 `domain/schedule_template.dart`

`ScheduleTemplate` 增 `monthly` / `monthlySegments`（存**下标**）/ `teamSegOffsets`，编解码仍是纯函数、可直接单测。

`fromSchedule` 的归一化那一条要一并扩到段偏移：**我们班组归到第 0 位、`teamSegOffsets` 相对它归零**（模段数取正）。不归一化的话，用模板建出来的方案里「我们班组」会指到别人身上 —— 与周期模式那条是同一个坑。

### 5.6 `ShiftSource`

**不动。** 它只有 `shiftOn(date)` 与 `label` 两个成员，按月模式的实现全在 `ShiftSchedule` 里面。这正是 §7 那四条链路零改动的依据。

## 6. 界面

### 6.1 新建排班的选择页（`shift_template_picker_screen.dart`）

- `ShiftTemplateChoice` 增第三个变体：`ShiftTemplateChoice.monthly()`（与 `.custom()` 平级 —— 「我自己排」是周期模式的空白起步，「按月排班」是另一种起步，两者都不是模板）。
- 卡片**复用 `_patternCard`**：标题「按月排班」/ 副标题「每个月重复一套切法」，色条传**段的班次下标序列**（一「格」= 一段，不是一天 —— `cycleStripPlanOf` 直接可用，段数 ≥ 14 时它自带省略标记）。
- 位置：贴着「我自己排」那张卡（同属「从零开始」那一类），排它前面。
- 起步内容：**三段（1 / 11 / 21 日起）分别指向默认四班两倒的前三个班次定义**，用户进来就能看到三行、直接改指向。**（这是我的判断，不是用户说的；实施时如觉得空一段更干净，可以只放一段。）**
- 搜索：它不参与 `_matches`（与「我自己排」同待遇，永远在最下面出现）。

### 6.2 编辑器（`schedule_editor_screen.dart`）

**模式切换放在「周期设置」这张卡的最上面**，用现成的 `GlassSegment`（两个选项：「按周期」/「按月」）。选「按月」时，卡里那条步进器 + 周期行整组换成**段列表**。

> 为什么不把「跟随法定节假日」一起并进这个分段器：那一条是**破坏性**的（切过去会清空班次定义与全部按天覆盖，所以现在才要弹确认框 + 单独一张卡 + 一个开关）。把破坏性选项混进日常切换的分段器里，等于把「问一次」的机会抹掉。

**段列表的每一行**（`_monthRow`，与 `_cycleRow` 同配方）：

```
[每月] 第 1 天起   [中班  15:30–23:30]        (第一行没有删除键)
[每月] 第 11 天起  [白班  07:30–15:30]   ✕
[每月] 第 21 天起  [夜班  23:30–07:30]   ✕
```

- 日号可点 → `showGlassOptionPicker`，只列**合法**的日号（`上一段 + 1 .. 31 − 后面还有几段`）。
- 班次可点 → 与 `_cycleRow` 同一处选班次的交互，别另写一套。
- 删除键：`GlassDeleteButton(compact: true)`，**第一行不给**（第一段的起始日恒为 1，删了就没有「1 号」）。
- 底部「添加一段」：照编辑器既有那行「添加班次」的配方。

**第一次从「按周期」切到「按月」时，段表是空的 —— 要种一段。** 规则：**只在 `_monthlySegments` 为空时**种 `[(1, 0)]`（一整月都是第一个班次定义），用户自己往下加。两个理由：① 第一行没有删除键，空列表会让这块面板既没有行、也没有可删的东西，是个死角；② 只在空的时候种，才不会把用户上一次切过去时排好的段表冲掉（这与 §3.4 的「切换不丢数据」是同一条）。

（选择页那张卡走的是另一条：直接种三段 1/11/21。两者的差别是有意的 —— 选择页是「凭空开一套」，给个像样的形状最省事；编辑器里那一下是「我手上已经有一套班表了」，凭空编三段反而是替用户拿主意。）

**删一段 = 把它并进上一段**（上一段延伸到被删那段的末尾）。删最后一段就是上一段延伸到月底。这条语义是**唯一**能保持「不空档」的删法，要写进注释：删第二段之后，第一段吃 1–20、第三段仍从 21 起。

### 6.3 顶部卡片那一行

「我的班组 · 周期起始日」在按月模式下**没有意义**（按月不读 `anchorDate`）→ **按月模式下整行不显示**，方案名那个输入框照旧。

### 6.4 班组卡（折叠那张）

- 每组那一行在按月模式下把「周期起始日：2025-01-06」换成「**从第 N 段开始**」，可点 → 选项器（1..段数）。
- 段数那行提示（`teamHint`）在按月模式下换一句短的，讲清「各组按段错开、都在每月同一天换班」。

### 6.5 撞班提示

`_crewClashNotice` 走 §5.2 的分叉：位置与「一键均分」那个动作都不变，但**按月那一支不算 `days`、文案不带数字**（理由见 §5.2 末尾）；周期模式那句「有 N 天撞班」原样不动。一键均分在按月模式下走 §5.3。

### 6.6 预览条

**不用改。** `_previewStrip` 调的是 `_draftSchedule().shiftOn(date)`，按月模式接进去它自动就对；而且它从「今天」起算 14 天，**月末打开时会正好跨过月界、把「归零」那一下演出来** —— 这是免费拿到的验证手段，实施时应该专门出图确认一次。

### 6.7 空白表开关（`_setFollowHoliday`）

切到空白表时除了清空班次与周期，**还要清空 `_monthlySegments` 并把 `monthly` 置回 `false`**；切回来恢复默认四班两倒时同样重置。漏了的话会留下一套「有段表但没有班次定义」的方案。

### 6.8 文案（`core/l10n.dart`）

新增（命名由实施定，但**实施前先 grep 一遍有没有撞键** —— `nextDay` / `myCycleStart` 那两处都是踩过的）：

- 选择页卡片：标题 / 副标题
- 分段器两个选项：「按周期」/「按月」
- 「第 N 天起」/「从第 N 段开始」/「添加一段」/「删一段」的确认与说明
- 按月版的撞班句式、按月版的班组提示
- 模板卡副标题的按月变体（现在那个 `savedTemplateSubtitle(cycleLength, teamCount)` 在按月方案的 `cycleLength = 0` 时会写出「0 天」）

### 6.9 排班管理页那一行（**审查抓出来的漏网处**）

`schedule_management_screen.dart` 的列表行副标题里**无条件**印了 `${L10n.monthDay(s.anchorDate)}`。按月方案的 `anchorDate` 是个不再被读取的历史值，印出来就是**一个没有意义的日期** —— 而「界面上写着一个其实不生效的值」正是这个仓库反复清的那类东西（与 §6.3 同一条理由）。

按月方案那一行改印**按月切法的摘要**（如「每月 3 段 · 4 个班组」）；周期方案原样不动。这一处**在 §7 那张清单之外**，别因为它不在表里就漏掉。

（顺带核对过：日历的「切换排班」总览与 `schedule_span_label.dart` 都不印周期长度 / 起始日，没有同类漏网点。）

## 7. 与既有链路的关系（零改动清单 + 论证）

| 链路 | 为什么不用改 |
|---|---|
| 闹钟（`planShiftAlarms` / `AlarmService.reschedule`） | 逐天遍历、每天问一次 `ShiftSource.shiftOn(date)`，`ShiftSource` 与它的签名都不动 |
| 桌面小组件（`buildWidgetSnapshot` → `WidgetRenderer.kt`） | 同上，快照是「逐天算好再投递」；**Kotlin 一个字都不用改** |
| 按天改班（`ShiftDayOverrides`） | 它在 `ShiftSchedule.shiftOn` **之前**生效，与轮转怎么算无关 |
| 多套方案按日期衔接（`ScheduleChain`） | 它只调 `scheduleOn(day).shiftOn(day)`；`hasScheduleOn` 也不受影响 |
| 「本月统计」/ 信息卡高度 | 前者按 `shortLabel` 累加、后者按班次简称与组名算 —— 都不看轮转怎么来 |

**必须改的**（五**块**地方，每一块都可能牵涉多个文件 —— 不是「五处」）：

1. `isBlank` 与 `monthly` 这条判据本身（§3.5）
2. `ScheduleChain._rotationOf` 指纹（§5.4）
3. `crewClashes` 的按月分支（§5.2）
4. 我的模板的编解码（§5.5）
5. 界面：编辑器 / 选择页 / **排班管理页那一行**（§6，尤其 §6.9）

**编辑器里除了界面本身，还有三处会「静默停在周期模式」的调用点**，审查逐条点过名，实施时别漏：

- `_draftSchedule()`（`schedule_editor_screen.dart:387`）—— 它出的草稿喂给**预览条**与**撞班检查**两处。不带上三个新字段，预览会照着旧周期画、撞班检查也照旧周期算，**两个都不报错**。
- `_evenCrewStarts()`（`:1133`）—— 按月模式下要传**段数**而不是 `_cycle.length`（§5.3）。
- `_deleteClass()`（`:1588`）—— 现在拦的是「周期里还引用着这个班次」，并顺手把周期里更大的下标整体前移；**段表要同待遇**（引用检查 + 下标重映射），漏了就是段指向了别的班次。

`hasCycle`（管着长按拖选与「调整班次」能不能用）**不用单独改** —— 它是从 `isBlank` 推出来的（`!s.schedule.isBlank`），改对 `isBlank` 它就对了。**实施时确认这一点，别顺手加一遍。**

## 8. 验收

**新增用例**（一律**先看着它红**再改代码）

*领域层（纯 Dart，`shift_rotation_test.dart` 一族的写法）*

- **用户那个例子**：段表 `[(1,中),(11,白),(21,夜)]`，逐个断言 12 月 / 11 月 / **2 月**每天的班次 —— 12/1 = **中**（这条就是用户报的那个现象的护栏）、12/31 = 夜、2 月的 21–28 = 夜。
- 四个长度各一的月份各验一遍：31 天（1–10/11–20/21–31）、30 天、**2 月 28 天**、**闰年 2 月 29 天**。
- 任意段数与任意长度：`[(1,A),(6,B),(16,C)]` 逐日验；单段（`[(1,A)]`）整月同班。
- **每月 1 号恒落在第一段**（跨 12 个月逐一断言）。
- **班组按段错开（这一条是 §3.3 那条推演的护栏）**：3 组 3 段（1/11/21，中 / 白 / 夜三个互不相同、都不休息的班次）→ ① `crewClashes` 在**整个四年扫描**里为空；② 逐日断言三组的班次**两两不同且都非空**。**改成按天错开实现的话这条立刻红**，实施时反向验证一遍（把 `teamShift` 的按月分支临时换成 0/10/20 的天数错开，看着它红在 11 号与 21 号上）。
  ⚠️ 断言要用 `crewClashes`（它本来就把「两组同时休」排除在外），别自己写「两两不同」—— 否则一个腿上两个班段都是「休」的合法配置会被误判成撞班。
