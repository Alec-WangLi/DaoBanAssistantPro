## 1. 背景与目标

设计语言 v2 落地后，最终全分支审查 + 逐任务审查共留下 5 组欠账。它们**都不影响使用**，但都指向同一件事：**那条守门测试还不够可信，而阶梯本身还有一处是错的**。

本轮把这 5 组一次清完：

| # | 欠账 | 性质 |
|---|---|---|
| ① | 令牌自检是手写枚举 —— 加令牌忘加断言不会红 | 守门测试**漏检** |
| ② | 扫描器三类已知边界（命名常量逃逸 / 带子 widget 的 `SizedBox` 不扫 / **注释也会被扫**） | 前两条是漏检，第三条是**误报** |
| ③ | `lib/core/theme/` 整个目录不在扫描范围 | 扫描范围与「配色层」的边界不清 |
| ④ | 阶梯缺档：图标没有 22 一路、圆角没有小尺寸一路 | **一半是真问题**（见 §5） |
| ⑤ | `durFlow` 名字与实际用途不符（注释已改准，名字还叫 "Flow"） | 命名 |

目标：让「守门测试绿」重新等于「界面层**在扫描面内**真的没有字面量」（扫描面是下面逐类点到的字面量，不是「一切数值」），并把阶梯里唯一那处**角色分配错误**改正。

## 2. ① 令牌自检的完整性检查

**问题**：`design_tokens_test.dart` 的「角色令牌的尺寸与规格一致」是一条**手写枚举**的 `expect` 列表。加了一个令牌但忘了加断言时，测试照样绿 —— v0.6.11 就漏过 `padChipV`（事后手工补的）。

**做法**：加一条新用例，读 `design_tokens.dart` 的源码、按名字抽出一组**阶梯类**常量，断言每一个都在本测试文件里以 `AppTokens.<名>` 出现过。

抽哪些（按名字前缀，这一组就是「阶梯」的定义）：

- 排版：15 条角色 `TextStyle` 的名字（`ringClock` … `tinyLabel`）
- 图标：`iconSm` / `iconMd` / `iconLg`
- 间距：`spaceXs` … `space3xl`
- 光学：`gapHair` / `padChipV` / `gapIconText` / `gapIconTextLg`
- 圆角：`radiusS` / `radiusM` / `radiusL` / `radiusXL`
- 明度：`inkMutedAlpha` / `inkFaintAlpha`
- 时长：`durFast` / `durMed` / `durSlow` / `durRingEnter`

**不在自检范围内**（写进注释说明，不是遗漏）：配色（`bg*` / `surface*` / `ink*` / `danger` / `success` / `holiday`）、玻璃配方（`blur*` / `glass*`）、弹簧与缩放（`qSpring` / `pressScale` / `pillGrow`）—— 它们各自有别的用例盯着，或本身就是配方而不是阶梯。

**失败长什么样**：新加一个阶梯令牌却没在自检里断言 → 那条用例红，并指出漏了哪个名字。

**怎么验证它不是恒真**：临时删掉自检里任意一条 `expect`，这条完整性用例必须变红。（写进报告的验证步骤。）

## 3. ② 扫描器的三类边界

### 3.1 注释与字符串：不再扫（现在会误报）

**现状**：扫描器读原始源码，**注释里写 `fontSize: 10` 会把构建打红**。这个坑在 v0.6.11 里咬过两次（第一次是有人把基线值写进注释）。它是**误报**，不是漏检 —— 但「不许在注释里提及被禁模式」是没法长期维持的约定。

**做法**：扫描前先把源码「**非代码部分**」用等长空格替换，再跑规则。

- 行注释 `//…` 到行尾
- 块注释 `/*…*/`（可跨行）
- 字符串字面量的**内容**（`'…'` / `"…"` / `'''…'''` / `"""…"""`），识别转义

**关键是「等长替换」**：把字符换成空格、不删字符，这样所有命中偏移不变，行号换算与错误信息不受影响。

### 3.2 带子 widget 的 `SizedBox`：要扫（现在整条跳过）

**现状**：`_spacingCall` 的参数部分写的是 `[^()]*`，遇到 `SizedBox(width: 6, child: Center(…))` 就整条不匹配 —— 于是**这种写法里写多大的间距都不会被发现**。

**做法**：把「匹配到右括号」换成**配对括号扫描**：从 `SizedBox(` / `EdgeInsets.xxx(` 的左括号出发走括号深度，取到配对的右括号为止，再在参数串上找数字。

**保留原有语义**：参数串里是「算式」的（`width: cellW - _cellInset * 2` 的 `2`）依然不算间距值 —— 那条判据（数字的前后字符是 `:` `,` `(` 与 `,` `)` 或串尾）不变。

### 3.3 命名常量：**按名字**扫，不再无条件逃逸

**现状**：`static const double _hitPad = 6;` 这类常量整个逃过扫描 —— 规则只看 `SizedBox` / `EdgeInsets` 的**参数位置**，看不到常量声明。于是有一条绕过路径：**把不合栅格的值提升成一个命名常量，守门测试就再也看不见它。**

**但先量了一遍，结论跟审查员的估计不一样。** 扫描目录里 off-grid 的 `const double` 一共 **15 处**，其中**只有 4 处是真的设计间距**：

| 真间距（4 处） | 值 | 收进 |
|---|---|---|
| `calendar_screen.dart` `_cellInset` | 2 | `AppTokens.gapHair` |
| `shift_template_picker_screen.dart` `_stripSpacing` | 2 | `AppTokens.gapHair` |
| `home_shell.dart` `_innerPad` | 6 | `AppTokens.gapIconText` |
| `glass_segment.dart` `inset` | 3 | `AppTokens.padChipV` |

另外 11 处**不是间距**：控件几何（`_trackHeight` 190、`_thumbSize` 46、`_weekdayH` 26、`_stripDot` 14）、比例（`_cellAspect` 0.78、`_cellAspectMin` 0.62、`_armThreshold` 0.7）、派生下限（`_minCellH` 58）、计数（`maxSlots` 14）、以及一个**测试用 id**（`alarm_service.dart` 的 `testId = 99999`）。

**所以「凡是 off-grid 常量就报」是错的** —— 它换来 4 个真命中，代价是 11 条永久豁免注释，信号会被淹掉，以后没人会去读那些豁免。

**做法**：规则**按名字收窄**。

> 扫描目录里 `static const double <名> = <数字>;`，**名字里含 `Pad` / `Gap` / `Inset` / `Spacing`** 之一、且数字不是 `1` 也不是 4 的倍数时报出来，除非带具名豁免。

落在这条规则上的有 5 处：上面 4 处改成引用已有令牌（**值一字不改**），剩下的 `glass_choice_chip.dart` 的 `_hitPad = 6` 带一条豁免 —— 它是把 32dp 的视觉高度补到 44dp 触摸目标的**推导值**，不是设计间距。

豁免写法：

```dart
// design-tokens-ignore: 命中区补到 44dp 的推导值，不是设计间距
static const double _hitPad = 6;
```

- 冒号后必须**有非空理由**（只有标记没理由不算数）。
- 作用域：**同一行或紧邻的上一行**。
- 命中的豁免条目**打进日志**，让「故意不扫」看得见。

**这条规则的已知边界（写进注释）**：名字不含那四个词的常量仍不扫（比如有人把间距叫 `_k`）—— 它拦的是**顺手把间距提成常量**这个习惯，不是对抗性的绕过。要拦后者得做标识符解析，不划算。

## 4. ③ 扫描范围纳入 `lib/core/theme/`

**现状**：`lib/core/theme/` 整个目录不在扫描范围，理由是「配色层本身」。但实测这个目录里 8 处命中中，**7 处确实是配色层**（`app_colors.dart` 的 5 个主色、`app_theme.dart` 的 2 个中性 seed），真正该管住的只有 `animated_background.dart` 里那 1 处色值 —— 而它是个**渲染文件**，不是配色层。

**做法**：

- 扫描范围加 `lib/core/theme`。
- 一份**显式的文件级豁免**，每条带理由：`app_colors.dart`（主色板本身）、`app_theme.dart`（中性 seed 与主题装配）。
- `animated_background.dart` 里那处 `const Color(0xFFB9BECF)`（响铃背景中间那团光斑）收进配色层的 `app_colors.dart`，具名 `bgBlob`。

## 5. ④ 阶梯：一半是真问题，一半是假问题

审查把「阶梯缺档」列为待办，v0.6.11 里有两处被这条逼着改了观感：导航图标 22 → 20、周期色条格子从圆角方块变成圆点。

**逐条核过之后，只有一半成立。**

### 5.1 图标：真问题，但根因是**角色分配错了**，不是缺一档

渲了对比图（导航图标 20 与 24）：**24 明显更好** —— 图标在胶囊里站得住，与 11px 标签的比例更接近标准底栏。

而 20 这个值不是继承来的：**是 v0.6.11 我自己在规格 §3.6 里把「导航项」归到 `iconMd` 的**。原来的代码是 22。

**做法**：**不新增 22 这一档**。把规格 §3.6 的角色分配改成「导航项 → `iconLg`(24)」，`home_shell.dart` 跟着改。20 这一档仍被按钮、列表项、提示条、弹窗关闭钮用着，不会闲置。

### 5.2 圆角：假问题，写成规则

渲了对比图（周期色条：圆点 vs 半径 4 的圆角方块）：高密度那几行（上 12 休 12、DuPont 28 天）**圆点明显更清爽**；方块只在 4 天周期那几行略占优，整体偏重、像缩小的表格。而那个变量本来就叫 `dot`。

为一个元素回到「半径 3」而新增一档圆角不值。

**做法**：**不新增圆角档位**。在规格 §3.1 补一条规则：

> **≤16dp 的实心小元素一律走 `pillOf`。** 阶梯里没有小尺寸档是有意的 —— 小到那个尺度时，圆角与 pill 的差别已经小于抗锯齿带来的差别，而且 pill 在高密度排布下更干净。

把现状从「意外」变成「规定」。

## 8. 验收标准

- `flutter analyze` 0 error / 0 warning。
- `flutter test` 全绿（当前 137 条 + 本轮新增）。
- **每条新机制都要有正反两面的用例，且验证过它不是恒真**：
  - ① 完整性检查：临时删掉一条自检断言 → 必须红。
  - ② 注释剥离：注释里的 `fontSize: 10` **不报**；代码里的 `fontSize: 10` **照报**。
  - ② 配对括号：`SizedBox(width: 6, child: …)` **要报**；`width: cellW - _cellInset * 2` 的 `2` **不报**。
  - ② 具名豁免：带理由的标记**豁免**；只有标记没有理由的**不豁免**。
  - ② 常量规则：名字含 `Pad`/`Gap`/`Inset`/`Spacing` 且 off-grid 的常量**要报**；名字不含的（控件几何、比例）**不报**。
- `app/tool/visual` 出图全绿，且**除导航图标外零视觉差异**（导航图标 20→24 是唯一有意的视觉变化）。
- **实际拦截面（收窄说明，避免高估）**：先前的措辞（含 `PRODUCT_SPEC.md` 那处）把「不许写」写成了整类（透明度 / 颜色 / 时长），但规则实际只认 —— 字号 `fontSize:`、字重 `fontWeight:`、`onSurface` 系文字明度 `.withValues(alpha:)`、圆角 `circular(`、`Duration(milliseconds:)`、`Color(0x…)`、图标 `size:`、间距类字面量与间距常量。**有意不在规则内**：装饰 / 玻璃配方的 alpha（`Colors.white.withValues(alpha:)`）、`Color.fromARGB`、`Duration(seconds:)` / `microseconds:`、`EdgeInsetsDirectional.*`、`final`（非 `const`）间距常量、多声明符常量、RHS 为算式的常量。故「守门测试绿」只等于「**上述类别**里没有字面量」，不等于「界面层零数值」。
- 手工核对本机 `git log --oneline -1` 与版本号两处一致（`app_info_test.dart` 会把关）。
