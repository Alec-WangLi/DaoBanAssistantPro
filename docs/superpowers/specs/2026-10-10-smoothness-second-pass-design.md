# 动画与流畅性 · 第二轮（玻璃模糊的代价）设计

- 日期：2026-10-10
- 起点：v0.10.21 真机测完之后的用户反馈 ——「功耗应该是降低了，但页面流畅性感觉好像还是没有变化。
  比如在编辑排班界面滑动时，能感觉到页面不知道是掉帧还是抽帧，反正看着卡卡的」。
  追问「是一阵一阵的，还是整段都不顺」→ **一阵一阵的、隔一会儿顿一下**。手机已连 ADB。
- 这一轮的结论来自**在这台真机上直接量**（一次性探针 `app/tool/probe/`，不随本轮入库，跑完即删）。
  规格里每一个数字都是量的。

## 1. 目标

把**每一帧的 GPU（光栅线程）开销**降下来，让画面留在帧预算之内。**不改观感、不改交互语义、
不动任何动画的时长与曲线、不碰闹钟语义。**

## 2. 实测基线（Redmi K25102RKBEC · 1200×2608 @480dpi）

### 2.1 这块屏全程 120Hz —— 帧预算只有 8.33ms

`settings get system peak_refresh_rate` = 120，`dumpsys display` 全程 `peakRefreshRate=120`，
探针量到的帧间隔中位数 **8.32ms**。**预算 8.33ms，不是 16.67ms。**

### 2.2 编辑排班页滑动（6 次甩动，425 帧）

| 指标 | 值 |
|---|---|
| build（UI 线程） | p50 **0.52ms**、p90 0.65、max 4.6 |
| **raster（光栅线程）** | p50 **4.19ms**、p90 **13.10**、p99 **21.87**、max 25.2 |
| totalSpan | p50 5.42ms、p90 20.43 |
| **掉拍帧（间隔 2 拍以上）** | **57 / 425 = 13.4%** |

**build 只有 0.52ms** —— 上一轮（v0.10.20/0.10.21）做的正是 UI 线程（436 → 42 个 widget/帧），
那里已经没剩什么可优化。**瓶颈整个在光栅线程，而上一轮一个字节都没碰过它。**
这就是「功耗降了、流畅没变」的原因：省下来的是 CPU，掉的是 GPU 的帧。

### 2.3 四个 tab 的光栅画像（每页甩 4 次）

| 页面 | raster p50 | p90 | p99 | min（静置） |
|---|---|---|---|---|
| 我的 | 1.91 | 3.45 | 9.70 | — |
| 待办 | 2.81 | 6.48 | 14.89 | — |
| 闹钟 | 2.81 | 9.77 | 21.85 | — |
| 日历 | 6.22 | 10.36 | 26.77 | — |
| 编辑排班 | 4.19 | 13.10 | 21.87 | — |

**我的页只要 1.9ms** —— 引擎与设备都没有问题，代价全在**页面内容**上。

### 2.4 代价是 `BackdropFilter` 这条通道本身（编辑排班页，同一段滑动）

| 变体 | raster p50 | p90 | p99 | 掉拍 |
|---|---|---|---|---|
| 基线（模糊 σ18 + 饱和度矩阵） | 4.19 | 13.10 | 21.87 | 13.4% |
| 只去掉饱和度矩阵 | 3.16 | 8.21 | 13.80 | — |
| 只留模糊（σ18） | 3.85 | 7.92 | 25.06 | — |
| **完全不要 `BackdropFilter`**（填充配方不动） | **2.20** | **2.37** | **3.76** | **6.9%** |
| 走低端档（模糊关 + 填充变实） | 2.07 | 2.21 | 8.12 | 1.3% |

**只留模糊、或只留饱和度，都只降到 8 左右；两者都去掉才降到 2.4。**
所以贵的不是滤镜算什么，而是**那层 backdrop 渲染通道本身** —— 每个 `BackdropFilter` 都把这一帧
劈成两段、抓一次背景。σ 取多大、矩阵复不复杂，都不是主要矛盾。

每一页都受益（去 `BackdropFilter` 之后）：

| 页面 | p50 前 → 后 | p90 前 → 后 |
|---|---|---|
| 日历 | 6.22 → **3.59** | 10.36 → **5.92** |
| 闹钟 | 2.81 → **2.50** | 9.77 → **4.75** |
| 待办 | 2.81 → **2.42** | 6.48 → **4.15** |
| 我的 | 1.91 → **1.40** | 3.45 → **2.76** |
| 编辑排班 | 4.19 → **2.20** | 13.10 → **2.37** |

### 2.5 观感代价：**量出来几乎为零**

- 同一台机器、同一个包连拍两张的噪声本底是 **0**（逐像素完全相同）。
- 日历页（有光晕、最"该有玻璃感"的那一页）：全屏 ≥4 的像素 **0.43%**、≥8 的 **0.01%**、max **16**。
- 编辑排班页：≥8 的 **0.26%**、max **25**。
- 放大 12 倍之后，差异只有两类：**文字与描边的抗锯齿**（1px 级）、
  以及**光晕透过信息卡的那层极淡纹理**（原始幅度 1~16/255）。
- 出图三张给用户看过（上下对照 + 12 倍放大 + 卡片边缘放大），结论一致：**看不出区别**。

## 3. 范围

### 3.1 玻璃模糊收窄（本轮核心）

**规则**：`BackdropFilter` 只留在**背后真有东西会动**的地方。

| 面 | 背后是什么 | 结论 |
|---|---|---|
| `GlassTile`（列表/页面里的卡片） | 平色页面底 | **不挂** |
| 日历页那两张 `GlassTile`（信息卡 / 小窗卡） | 极淡的光晕 | **不挂**（§2.5 量过看不见） |
| 底部导航胶囊 | 列表从它下面穿过 | 保留 |
| 液态透镜（`liquid_lens` / `liquid_track`） | 同上 | 保留 |
| 弹窗 / 弹层 | 正文 | 已是 `solid: true`，本来就不挂 |
| 按钮 / 提示条（`GlassBlur`） | 所在面板 | 保留（合计只占约 0.5ms，且它们浮在滚动内容上） |

**改动落在 `GlassTile` 自己身上，不在那 8 个调用点。**
全仓扫下来，**仍然开着模糊的调用点只有 8 处，全部是 `GlassTile`**
（日历 2：信息卡与小窗卡；编辑排班 6）。其余 16 处 `GlassTile` 本来就传了 `enableBlur: false`。
所以这一处改完，整条链就收口了。

**实现要点**：只摘掉 `BackdropFilter`，**它外面那圈 `ClipRRect` 留着**（见 §3.2），
**填充配方（`glassSurface` / `glassTint`）一个字节都不改** ——
现有那个 `enableBlur: false` 开关**不能拿来用**：它同时会把填充换成更不透明的那一支
（那是低端档的补偿配方），换上去就是肉眼可见的观感变化（见 §5）。
所以这一处要**把"糊不糊"与"用哪支填充"两件事拆开**。

**为什么不干脆把 σ 调小**：§2.4 已经量过 —— 只留模糊（σ 仍 18）p90 是 7.92，仍然是 §2.4 里
最差的两档之一。σ 不是主要矛盾。

**这一条其实是把 v0.4.1 已经对「列表行」做过的事补到「卡片」上** ——
那次（`enableBlur:false` 去逐行模糊）的理由就是这个，卡片当时被漏下了。

### 3.2 顺带查出来的一处：`GlassPanel` 的 `boxShadow` 被外层 `ClipRRect` 裁掉了

`ClipRRect(child: BackdropFilter(child: panel))` 把 `panel` 的 `boxShadow` 一起裁进了圆角矩形内。
出图核过：把整圈裁剪去掉，卡片四周会多出一圈本该有的阴影（肉眼能看见）。

于是今天全 app 有**两套卡片观感**：带模糊的卡片**没有阴影**（被裁掉），
`enableBlur: false` 的卡片与 `solid: true` 的面板**有阴影**。

**这一轮的决定：不动它，`ClipRRect` 留着、阴影照旧被裁掉。** 理由是这一轮的契约是
「观感不变」，而补上阴影是**肉眼可见**的改动，属于观感决定、得单独拍板。
但它不许不明不白地留着 —— 实施时在 `GlassPanel` 那一段写一条注释，
把这个状态、它的成因、以及「补阴影要单独开一轮」写清楚。

### 3.3 上一轮明确留下、这一轮全部收掉

| 项 | 现状 | 这一轮 |
|---|---|---|
| `appSettingsProvider` 全量 watch | 7 处（含 `app.dart` 根节点）。**拨一下触觉开关会重建整个 App** | 每个消费者**只 select 它自己真正渲染的那几项**：`app.dart` → 主题 / 主色 / 语言；`calendar_screen` / `alarm_screen` / `schedule_screen` / `home_shell` 只 select `language`（它们只是「语言切换时重建」）；**「我的」页是例外** —— 它把主题档、主色、语言、液态玻璃、触觉五个开关都画在自己身上，就得 select 这五项，收成 `language` 会把那几个开关**冻住**（builder check 抓出来的） |
| `L10n` 里 `DateFormat` | 每次调用都新建（月标题、完整日期等，一屏几十次） | 按 `(pattern, locale)` 缓存 |
| 切 tab 保活 | `PageView` 销毁非当前页，切回重建 | **不做**（已量，见下） |
| `AlarmStore` 逐条写盘 | `put()` 每次 `all()` 读全表 + 全量序列化 + 全量写回 ⇒ 一次 `rescheduleAll` 约 53 条是 **O(n²)** | 批量化：一次 `rescheduleAll` 只读写一次 |
| `AlarmRingService` 没有自停 | `START_NOT_STICKY`，**没人关就一直响**（用户睡着/不在就是一直响 + 一直唤醒） | 加 15 分钟超时自停（时长见 §9）。**自停必须走与用户关闭完全相同的那条拆除路径**：`exitLockScreenMode()`（v0.8.0 记过——它是只进不出的，不撤就等于把「锁屏下能操作 App」那个洞重新打开）、撤通知、放 wakelock、把响铃界面关掉。**「再睡一会」重新计时**（那一档要的就是再一个窗口） |
| 小组件刷新闹钟 | 已有精确权限时走 `setExactAndAllowWhileIdle` | **默认就退非精确**（跨天翻页不要求秒级；已有注释说明这是可接受的降级） |
| 三条 deferred minor | ① 光晕暂停判据是「手指按着就停」（规格原意是"只在动的那几百毫秒"）② 换月没进暂停判据 ③ `WidgetService.push` 没有 in-flight 守卫 | ① **「在动」= 那四种交互正在进行**（飞行 ticker 在跑 / 拖动中有新位移 / 带子的弹簧未静止 / 换月的 `AnimatedSwitcher` 在跑），不是「手指按着」；停手就恢复 ② 换月也进判据 ③ 加守卫，重复触发只跑一次 |

### 3.4 一处量过之后**决定不做**的：切 tab 保活

上一轮把它列进了「非目标」，这一轮把数据补上，**结论是不做**。

切到四个 tab 各量一遍，**切后 6 帧的 UI 线程耗时**：

| 切到 | 第一帧 build | 接下来 6 帧 build |
|---|---|---|
| 闹钟 | 0.54ms | 0.5 / 0.6 / 2.4 / 3.1 / 15.4 / 0.7 |
| 待办 | 0.36ms | 0.4 / 0.4 / 0.5 / 0.5 / 0.9 / 1.0 |
| 我的 | 0.99ms | 1.0 / 1.0 / 1.1 / 2.2 / 10.1 / 15.9 |
| 日历 | 2.36ms | 2.4 / 0.5 / 0.7 / 6.3 / 18.5 / 29.6 |

（15.4 / 10.1 / 18.5 那几帧是**切走时旧页销毁**或路由动画叠上来的，不是新页的构建。）

**重建一页的 UI 线程代价最多 2.4ms，远在 8.33ms 预算之内。** 保活省的就是这一点构建，
换来的是四个页面的 widget 树与数据流常驻内存 —— 不成比例。
真正贵的是切过去之后那几帧的**光栅**（首帧 3.4~26.7ms），而那是 §3.1 要解决的，
保活解决不了（页面重新可见时该画还得画）。

## 4. 验收

### 4.1 探针（前后对比，跑完即删）

以**编辑排班页**为准（同机、同段滑动）：

| 指标 | 今天 | 目标 |
|---|---|---|
| raster p50 | 4.19ms | **≤ 2.5ms** |
| raster p90 | 13.10ms | **≤ 4ms** |
| 掉拍帧 | 13.4% | **≤ 2%** |
| build p50 | 0.52ms | 不变（只许更小） |

**做完 §3.1 之后必须重跑一遍四个 tab + 切 tab**，把仍在 8.33ms 之外的帧挑出来单独查 ——
不知道还剩多少就不算收口。

**Definition of Done**：目标是**硬的**，但不许用"放宽阈值糊过去"的方式收口。所以是：

- 达标 → 收工；
- **没达标 → 必须做一件事：把剩下的帧逐帧归因，写清楚"还差的是什么、为什么这一轮不做"**，
  并且这一轮**不许**就此宣称流畅性解决了。归因是**有界的**（一次测量 + 一次排查），
  不是"再想更多优化"——如果归因指向一处**改法明确、代价可控**的东西，就地做掉；
  指向一处**要动观感或要单独一轮**的东西，写进本轮的账本与最终汇报，交给用户拍板。

这条是为了堵住两个方向：既不许"没到 4ms 就接着无限期优化"，也不许"没到就算了、报告里不提"。

### 4.2 像素基线（`tool/visual/` 全量出图逐张比）

**这一轮与上一轮不同：差异是预期的。** 条件是：

- 每一张有差异的屏都要**逐张写出理由**，写不出理由的就是回归；
- 差异必须落在这三条之内，超出任意一条就停下来查：
  1. 幅度 **≤ 32/255**；
  2. 差异像素 **< 1%**；
  3. 差异**只出现在玻璃卡片的描边/圆角上**（1px 级抗锯齿），
     不在色块、文字主体、胶囊填充上。
- 已知假差异（响铃页时钟跳字、跨天「今天」位移）照旧剔除。

### 4.3 既有护栏

`flutter test` 全绿（当前 **807** 条，只增不减）；`flutter analyze` 0 error / 0 warning。

### 4.4 新增护栏

1. **「一屏的 `BackdropFilter` 层数 ≤ 一个量出来的上限」** —— widget 测试里
   `find.byType(BackdropFilter)` 数出来钉住（这是能直接跑的那条，比扫源码有鉴别力）。
   **必须反向验证**：把卡片的 `BackdropFilter` 加回去，这条要立刻红。
2. **「`GlassTile` 的构建路径里不许出现 `BackdropFilter`」** —— 扫源码，防它长回来。
3. **「`AlarmStore` 一次 `rescheduleAll` 的落盘次数」** —— 原生侧没有测试目标，
   所以这条靠**真机 + 日志**核，不进自动护栏（与既有的原生约定一致）。

### 4.5 探针怎么跑、工作区现在什么样（builder check 问到的）

**设备就在这个会话上。** 实施与验收都由**这一个会话**在真机上跑：
`flutter build apk --profile` → `adb install -r` → `adb logcat` 收 `onReportTimings` → 分析。
不是"改完把数字交给人去量"。

**工作区里现在有三处探针脚手架，它们的去留是明确的：**

1. `app/tool/probe/perf_main.dart` —— 探针入口（`flutter build -t` 指向它）。
   **本轮全程留着**（§4.1 的"再量一遍"要用），**收尾前删掉**。
2. `app/lib/core/glass/glass.dart` 里三个 `probe*` 全局 —— **它们的最终形态是全部删掉**；
   但 §3.1 的正式实现要先把"糊不糊"与"用哪支填充"拆开，
   **那一步做完之后这三个开关就完成使命了**，不要留到收尾。
3. `app/android/app/build.gradle.kts` 里给 `profile` 包挂正式签名那一段 ——
   不加的话 profile 包装不进这台已经装了正式版的机器（`INSTALL_FAILED_UPDATE_INCOMPATIBLE`），
   而卸载会**清掉用户真实的数据**。**收尾前还原**（它是本地调试用的，不属于产品）。

**每次量之前确认两件事**：`settings get system peak_refresh_rate` 仍是 120
（掉到 60 会让 8.33ms 的判据失去意义），以及屏幕上那份数据是**用户的真库**而不是种子数据。

## 5. 交互与观感：只有一处变了

**唯一一处可观察变化**：玻璃卡片背后那层极淡的模糊没了（§2.5 量过：全屏 ≥4 的像素 0.43%、
放大 12 倍才看得见）。**填充、描边、圆角、阴影、液态档的一切、动画的时长与曲线，全部不变。**

不发散的三条：
- 卡片**在视觉上没有变薄**：填充配方是原来的那一支（不是低端档那支更实的）。
- 底部导航胶囊、液态透镜、分段器、开关的模糊**一个都没动**。
- 标准档与液态档的**结构**都不变，只有卡片少一层渲染通道。

## 6. 风险与代价

- **这条改动会让像素基线出现普遍的小差异**（每一屏带玻璃卡片的都会中）。
  这是**有意的、量过的**，不是回归 —— 但必须逐张写进账本，见 §4.2。
- **`GlassTile` 的判据是"背后是平色"**：如果以后有人把卡片放到会动的东西上面，
  它就真的该糊。这条写进 `GlassTile` 的文档注释，别只留在规格里。
- **原生那三项（`AlarmStore` / 响铃自停 / 小组件非精确）没有测试目标**，
  验收只能靠真机 + 日志 —— 与仓库既有的原生约定一致，但要在真机上逐条过。
- **切 tab 保活可能不做**（先量）。不做也要把量出来的数字写进账本。

## 7. 非目标（这一轮明确不做）

- 光晕的刷新间隔 / 光斑数 / 强度（观感项，要单独拍板）。
- 信息卡那层 `BackdropFilter` 之外的配方调整。
- 任何动画的时长、曲线、弹簧参数。
- 响铃界面的观感。
- **`GlassDialog` / `GlassBlur` 的模糊是否该收**（它们合计约 0.5ms，收益不成比例）。
- 液态玻璃那四层光谱模糊的层数。

## 8. 版本与收尾（分两步，2026-10-10 用户拍板）

这一轮原计划直接出 v0.11.0 正式版。之所以拆成两步，是因为本轮含三项**原生改动**
（闹钟存储批量写、响铃自停、小组件非精确闹钟）—— **碰的是闹钟语义，而这个仓库的 Kotlin 侧
没有测试目标**，仓库自己的规矩就是这类只能真机验。

### 8.1 这一轮先出 **v0.10.22 测试版**（`beta` 分支）

- 更新日志的 0.10.22 条目**原样写这一版改了什么**（测试版条目不归纳），窗口仍 10 条。
- `AGENTS.md` 版本史 + 「最近改动」。
- `beta` 提交 → `git push origin beta` → `git tag v0.10.22 && git push origin v0.10.22`
  → `scripts/release.ps1 -SkipConfirm`。
- 发完 curl 一次 main 上的 `latest.json` 核对版本号。
