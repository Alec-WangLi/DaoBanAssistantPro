# 液态玻璃推广 · 第二轮（分段器内容扭曲 / 开关重做 / 待办打勾）设计

> 规格。实施计划见 `docs/superpowers/plans/<date>-liquid-glass-rollout-2.md`（下一步写）。
>
> 上一轮（抽共享件 + 分段器与开关接档）见 `2026-10-01-liquid-glass-rollout-design.md`。

## 1. 目标

v0.10.9 真机反馈的三件事：

- **A. 分段器补上「内容被透镜边缘挤」** —— 底栏有、分段器没有，两处观感不一致。
- **B. 开关重做** —— 颜色比别的面浅、按住时彩边糊成一团、拖不动、轨道太短。
- **C. 待办从开关改成打勾** —— 勾选语义不该用开关表达。

## 2. 用户拍板的（不可自行更改）

1. **开关不再「只往纵向拉长」**，与底栏 / 分段器**统一**（同一套 `LiquidLensMetrics.forCapsule`，纵横一起长）。
   v0.10.9 那条「参考 iOS 26 往纵向放大」的拍板**作废**。用户 2026-10-01 的原话是「你参考底部导航栏那个滑块……还是优先把它统一起来」。
2. **彩边保留**，但**宽度随透镜尺寸自适应**（不是关掉）。原话：「既然这个开关是小的，那彩边范围自然也要自适应变小」。
3. **开关尺寸 56 × 30**（原 46 × 28）。
4. **开关支持拖动**：横向拖动能把钮拨过去，松手吸附到最近一端并提交。
5. **待办改成打勾**，且**两条档位要能看出区别**。原话：「打勾的话，要融入咱们的设计理念，尤其是现在要区分液态玻璃开启和关闭两种适配状态」。
6. **分段器也采用新的彩边缩放**（2026-10-01 追加拍板）。
7. `tool/gif/tmp_rollout_probe_test.dart` 那四张动图是这一版的样图基准 —— **观感以它为准**。

## 3. 从这一轮量出来的四条（写进地基，别只当这一版的做法）

### 3.1 彩边的四个宽度是**尺子**问题

四层光谱（环 `lensRingWidth` 2.4 / 白芯 1.0 / 内晕 10 + 6 / 外溢 8）是**照 64 高胶囊量出来的绝对像素**。
搬到开关那枚基准高 24 的钮上，**内晕比钮本身还粗** —— 它就不再是「一圈折射的边」，而是把钮从中间糊成上下两团。

用户看到的那一刻是「像两个半圆一样」：钮被拉成纵向胶囊后，轮廓 = 上半个圆 + 下半个圆 + 两条直边，那道过宽的光晕正好把两个弧读成两个实体。

**判据：光谱层的宽度与模糊必须跟着透镜尺寸缩放。**

### 3.2 不只是彩边 —— 浮起阴影同样是常量

`_LensShadowPainter` 的偏移 `2 + 3·lift` 与模糊 `5 + 5·lift` 也是照大胶囊调的。小控件上那圈灰晕比钮还大，是「占满了整个轨道」的另一半来源。

**判据：`rimScale` 管的是「四层光谱 + 浮起阴影」一整组，不是只调彩边。**

### 3.3 白芯要按**控件尺寸**判，不是按钮的颜色判

`lensRingCore` 描的是透镜的轮廓路径。在小钮上它渲成**一道横穿钮身的白线**（放大 3× 那张图上很清楚）。
v0.10.9 关掉它是因为「白上画白等于没画」—— 那只覆盖了白钮那一档；**钮一改成主色，白芯就回来了，而且是坏的**。

**判据：开关与勾这两件（基准高 < 30）的 `showRingCore` 恒为假，与钮是什么颜色无关；底栏与分段器不变。**

### 3.4 半透在小控件上读作「颜色变浅」

同一份 `accentGradient`（`accent@0.85 → @0.50`）在 118dp 宽的分段器滴上够浓；在 28dp 的勾上，「透出来的那部分」占了大半，整枚比标准档那枚实心淡一大截 —— 正是用户这一轮报的「颜色变浅了」。

**判据：当底色本身就是状态（勾上 / 没勾上）时，它不能靠半透来读。**装饰性的面（滴、轨道）继续用半透。

## 4. 三个面各自长什么样

### 4.1 分段器 `GlassSegment`

- 内容层补上 `lensIconWarp`（底栏从 v0.10.4 起就有，分段器一直没有）。
- 那段仿射变换抽成一个**共享的「格」组件**，底栏与分段器**共用一份**（抄两份迟早走样，与 `LiquidLensController` 同一条理由）。
- **底栏必须逐像素不变**（见 §6.1）。底栏现在用 `ListenableBuilder(child: cell)`，每帧只重建外面那层 `Transform` —— 抽取要保住这个性质。
- **两处的坐标系不同构**（这一条最容易抄错）：
  - 底栏的格子是**内缩之后**排的 → `iconCenterX = pad + (i + 0.5) × itemW`；
  - 分段器的格子**铺满全宽** → `iconCenterX = (i + 0.5) × 内容宽 ÷ 格数`，其中 `内容宽 = itemW × 格数 + 2 × pad`。
  写成一样的话，扭曲的峰值会与透镜真实的边缘错开两三像素（铃形的 σ 只有 `0.45 × 半宽 ≈ 10px`，错开即可见）。
- **强度沿用底栏那三个数**（`lensIconPinch = 0.20` / `lensIconPush = 5` / `lensIconRingSigma = 0.45`），不另调。
- 彩边随尺寸缩到 `40 ÷ 64 = 0.625`。

### 4.2 开关 `GlassSwitch`

| 项 | 现在 | 改成 |
|---|---|---|
| 尺寸 | 46 × 28 | **56 × 30** |
| 钮 | 白色玻璃球（`fill: [white, white]`），白芯关 | **主色玻璃滴**（默认 `fill`），白芯关 |
| 升程 | `LiquidLensMetrics(protrude: 8, liftWidth: 0)`「只长个儿」 | `LiquidLensMetrics.forCapsule(30)`（**与另两处同一套**） |
| 彩边 | 开着，用 64 高的常量 | 开着，**按尺寸缩**（0.469） |
| 轨道「开」 | `accent @ 0.35` 淡染 | **不变** |
| 拖动 | 无 | 有（见下） |

- **尺寸两档都改。** 尺寸是 `GlassSwitch` 自己的属性，只改液态档的话切档位时控件会跳一下。
  ⚠️ **这一条会改到标准档的开关渲染** —— 「标准档逐像素不变」对开关这一件不再成立，这是**有意的设计改动**，不是回归（其余界面照旧逐像素不变）。
- 「追着滑块的光带」与「被折进来的胶囊边」**继续关掉**（v0.10.9 的理由不变：46→56px 宽的轨道上它们是杂线）。
- **拖动**：接 `onHorizontalDragStart / Update / End`，松手用 `release()` 的返回值与当前值比较，不同才提交。
  - `press` 仍然是 `moveToSlot: false`、控制器仍然是 `followFinger: false` —— 点按不挪钮，按住也只有横向拖动才走。
  - **不设「必须先按住 110ms」的闸门**：那个闸门只管「拉长」这个视觉，不该管能不能拖。
  - 拖动中被 `onTapCancel` 打断时走既有的 `cancel()`，位置回退到已提交的那一格。
- 触觉 `Haptics.select()`、`enabled` 置灰语义、`AnimatedAlign` 的 `easeOutBack` **一个字都不改**。

### 4.3 待办打勾 —— 新件 `GlassCheck`

**只有待办列表那一处是勾选语义。** 全 app 九处 `GlassSwitch` 里其余八处（联动闹钟 ×2、跟随法定节假日、液态玻璃、触觉、按天关闹钟、自定义闹钟启用、重复待办启用）都是真开关，**一律不动**。

| | 标准档 | 液态档 |
|---|---|---|
| 未勾选 | 空心环：`glassTint` 底 + `navBorder @ 0.45` 描边 1.5px | **同一圈环**（同样 1.5px、同样颜色），底下是一枚**没点亮**的玻璃滴（`glassTint` 填充） |
| 勾上 | 主色**实心**圆 + 白勾，环的描边渐变成 `accent @ 0.55` | 主色滴（**接近不透明**，见 §3.4）+ 白勾，环同样渐变成 `accent @ 0.55` |
| 按压 | `QScale(pressed, scale: pillGrow)`（与分段器标准档同一套） | 滴**凸出**（`forCapsule(28)`，与另两处同一套） |
| 勾的出现 | 勾按 `progress` **描出来**（`PathMetric.extractPath`），底色同时渐变 | 同上，另外整体跟着升程放大 |
| 彩边 | 无 | **无**（控件太小，理由同 §3.1） |
| 触觉 | `Haptics.select()`（与开关同一档语义） | 同左 |

- **环与勾要跟着滴一起放大。** 按住时滴凸出到 32×37，如果环和勾还钉在 28×28，画面上就是「圆胀出去了、圈留在原地」——样图里能看出来。放大倍率与滴的轮廓用**同一个** `lift`，别各算各的。

- **尺寸 28**，比原来的开关（46 × 28）窄 18px —— 待办行的 leading 因此让出一点宽度，标题变宽。**行高不变**（两者都 28 高）。
- **未勾选是「空心环」**：光靠玻璃填充在浅色页面上读不出来（`glassTint` 第一档是 `white @ 0.80`，与页面底几乎同色）。**定义这枚控件的形状的是那圈描边，不是填充。**
- 「勾描出来」而不是「缩放出来」：这是勾这个动作唯一像「被写上去」的写法，缩放只是弹一下。
- 删除线**本来就有**（`schedule_screen.dart` 的 `TextDecoration.lineThrough` + `inkFaint`），这一版**不动它**。
- 两档是**两棵树**，与底栏 / 分段器 / 开关同一套写法。

## 6. 守门与工装

### 6.1 逐像素

- **底栏不变**：`00_home_shell_*`（5 张）与 `36_home_shell_liquid_*`（5 张）与基线**逐像素相同**。这是「抽共享的格」这一条路的唯一验收。
- **允许变的**：`37_profile_liquid_*` / `42_segment_liquid_*`（分段器彩边缩放）；**所有带开关的屏**（尺寸 56×30）。这两类都要**逐张看过**再接受。
- 已知假象照旧：`08_ringing_*` 的时钟跳字。

### 6.2 `test/liquid_scope_guard_test.dart`

允许出现 `liquidGlassActive` 的位置：`core/glass/glass.dart`（定义处）、`features/home/`、`glass_segment.dart`、`glass_switch.dart`、**新增 `glass_check.dart`**。
`lens_warped_cell.dart` **不在名单里**（它不读档位），第二条「自证」断言照旧。

### 6.3 新的护栏

- **彩边随尺寸缩**：同一几何、两个 `rimScale`（1.0 与 0.469），量「轮廓外多远还有彩色像素」——0.469 那一档必须明显更近。**反向验证**：把乘法去掉，两档应当一样远。
- **白芯在小控件上不画**：开关静止帧在钮身中线那一行**不应出现白线**（放大对比两个 `showRingCore`）。
- **开关拖动提交**：拖到另一端松手 → 值翻转；拖回原处松手 → 值不变（两条都要有）。
- **开关按住时纵横一起长**：`lift=1` 的轮廓宽与高都大于静止值（钉住「不再只往纵向拉长」）。
- **勾两档是两棵树**：开着与关着光栅化像素必须不同；关掉液态档时与改之前逐像素相同。
- **勾的描出**：`progress = 0.5` 时描出的路径长度约为满档的一半（纯函数，直接量）。
- **分段器的扭曲**：拖到某一格时，那一格的文字包围盒比静止时**窄**（几何判据，抄底栏那条的写法）。

### 6.4 屏单与动图

- 屏单补 `44_todo_check`（未勾 / 勾上两态，含液态档那一档），并**重出所有带开关的屏**（`05_todos` / `06_alarm` / `03_management` / `02_editor_*` / `17_getting_started` / `37_profile_*` / `43_switch_liquid_*`）。
- **窄窗（200×400）必须出**：开关从 46 宽变到 56 宽，待办行与闹钟行的 leading 宽度都变了，这是最容易溢出的地方。
- 动图沿用 `tool/gif/tmp_rollout_probe_test.dart` 那四条的拍法；**凡是有弹簧的动图出帧必须 16ms、合成用 `--fps 62`**（16ms 一帧 = 62.5fps），**裁剪宽度不缩放、`--colors 256`** —— 见 §7。
- **`tmp_rollout_probe_test.dart` 是探针，跑完即删**：它的作用是把观感定下来（四个面的样图都在这一轮的对话里）。真实现落地时，那四条拍法搬进 `tool/gif/render_gifs_test.dart`（正式的素材线），探针文件删掉。
- **彩边缩放的实现已经落进 `lib/` 了**（`rimScale`，默认 1.0，底栏传 1.0 所以它一字未变 —— 已逐像素验过）。计划里它不再是「新建」，而是「补测试 + 接上分段器与开关的取值」。

## 7. 动图管线（这一版定死）

彩边是「两三个像素宽、低饱和、与背景反差小」的东西 —— 它恰恰是最经不起压缩的。同一段动画里「文字清楚但彩边没了」的原因就在这里：

- `--width` 会把帧**缩放**（仓库示例用的是 620，而帧本身是 840 宽）；
- `--colors` 会把调色板**量化**（示例用的是 **96** 色）。

**玻璃类动图一律：`--width` 取裁剪宽度（不缩放）、`--colors 256`、`--fps 62`（16ms 出帧）。** 换来的是体积变大，这是要付的代价。

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| **开关变宽把窄窗挤爆** | 200×400 出图逐张核（待办 / 闹钟 / 我的 / 编辑器）。这是本版最可能现形的地方。 |
| 分段器扭曲在窄窗下把文字挤出格子 | 「被挤」是**压窄**（`scaleX < 1`）加**往外推**（`dx`）。往外推的那一下在最靠边的格子上可能顶出格子 —— 窄窗那一张要专门看。 |
| 白勾压在主色上的对比度 | 与 AGENTS 里那条已知问题同源（teal 2.63 / orange 2.55 / rose 4.09 不过 AA）。**这一版不改**，沿用既有实心主色 + 白前景的做法，但要在出图时用既有的对比度审计看一眼。 |
| 抽「格」时把底栏的手感/性能弄丢 | 底栏的逐像素验收 + 保住 `ListenableBuilder(child: cell)` 那个「每帧只重建 Transform」的性质。 |
| `GlassCheck` 每行一个 `Ticker` | 控制器在静止时不推帧（`_syncTicker` 的门），所以待办列表里十几行不会常驻动画。已有护栏（`pumpAndSettle` 等得到停）。 |

## 9. 明确不做的

- **按钮 / 胶囊 / 芯片 / 输入框的液态档** —— 仍是「只有按住鼓起、没有指示块」的**另一套设计**，另开一轮。
- **把其余八处开关改成勾** —— 它们是真开关。
- **给勾加彩边** —— 控件太小，与 §3.1 同一条理由。
- **改删除线本身** —— 已经有了。
- **重做 `08_ringing_*` 那个时钟跳字的假象**。
