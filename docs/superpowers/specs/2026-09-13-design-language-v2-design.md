# 设计语言 v2 · 设计规格

- 日期：2026-09-13
- 目标版本：`0.6.11+82`（AI 只改末位 Z；`X.Y` 由用户决定）
- 状态：待评审
- 取代：`2026-09-03-design-language-unification-design.md`（那是 v0.4.4 的迁移计划，后续五版把变更日志追加进「修订记录」，已不能作为对照标准）

---

## 1. 背景与目标

v0.4.4 那轮把设计语言收敛成了令牌，但令牌层只约束住了「颜色 / 圆角 / 时长 / 模糊」这几层。全库审计（2026-09-13）的结果：

| 层 | 状态 |
|---|---|
| 颜色 | 干净。只有 3 处字面量，全在 `core/theme/` 内部（中性 seed、背景光斑），属于该有的地方 |
| 时长 | 干净。4 处字面量，全部就是令牌自身的定义 |
| 模糊 sigma | 基本干净。但 `blurChip` / `blurCard` 两个令牌**没有任何调用方** |
| 圆角 | 只有两处字面量：`GlassPanel` 默认 28、`GlassTile` 默认 20。**20 是唯一跑出阶梯的值**，而它是全 App 每张卡片的默认值 |
| 字号 | **跑了**。77 处字面量对 44 处引用令牌，散成 16 个值，其中 10 个不在令牌声明的档位上 |
| 字重 | **跑了**。w700 ×53 / w600 ×26 / w500 ×11 / w800 ×4；规格说 w800 只留给响铃大时钟，实际有 3 处在别处 |
| 间距 | **跑了**。57 处在 4px 栅格上，约 40 处不在（2 / 3 / 5 / 6 / 9 / 10 / 14 / 18 / 22） |
| 图标 | **跑了**。61 个图标只有 13 个写了尺寸（18 / 20 / 22 / 28 / 16 / 14；其中导航项写成三元、28 有两处），其余吃默认 24 |
| 组件 | `app_icon.dart` 是规格第 3.6 节要求的图标统一包装，**定义了但一次都没被用过** |

更根本的问题是两个：

1. **令牌按「多大」命名**（`fontBody` / `fontCaption`），于是「这个文字该用哪一档」只能靠感觉挑最像的 —— 这正是 12.5、13.5、14.5、15、22 这些值的来源。
2. **现有文档是迁移计划，不是活文档。** 它没法回答「这个新界面该怎么写」。

目标：**先把设计理念本身写清楚、定下来，再让整个 App 对齐到它**，并且加一条会失败的测试，让对齐是可持续的而不是一次性的。

## 2. 设计理念（六条）

这六条是**裁决依据**：任何界面细节有争议时，拿它来判。

1. **背景中性，强调色只染「点」。**
   页面底色恒为中性（亮 `#F5F6FA` / 暗 `#0B0B10`）。5 色主色只出现在开关、按钮、选中态、导航滑块这些**点**上。成片的彩色一律来自班次数据色，不来自主题色。

2. **玻璃是容器，不是装饰。**
   面板 = 背景模糊 + 半透明 tint + 1px 描边。**不加高光、不加底光、不额外加投影**。这三样都是 v0.4.4~v0.4.7 试过又撤掉的，写进规则就不再反复试。

3. **层级只靠三件事表达：字号、字重、明度。**
   不用边框、不用底色深浅来表达「这是次要信息」。次要文字一律走 §3.3 的 `inkMuted` / `inkFaint` 两档，不各自调 alpha。

4. **界面层不写数值。**
   字号、字重、圆角、间距、时长、颜色一律引用令牌。这条由守门测试强制（§5）。

5. **动效是弹簧，不是时长。**
   按压与切换走弹簧物理（`qSpring` / `pressScale` / `pillGrow`）。三档固定时长只留给颜色渐变与吸附这类非位移过渡。

6. **可读性优先于观感。**
   任何压在色块上的文字必须过 WCAG AA 4.5:1。现成工具：`inkFor`（把前景色调到在给定底色上可读）、`onSolid`（底色已定，白黑二选一）。

## 3. 令牌层

### 3.1 圆角（数值不变，用法写死）

| 令牌 | 值 | 用在哪 |
|---|---|---|
| `radiusS` | 12 | 小色块 · 徽章 · 胶囊标签 · 分段内滑块 |
| `radiusM` | 16 | 按钮 · 输入框 · 小卡 |
| `radiusL` | 22 | **卡片 · 列表行 · 提示条** |
| `radiusXL` | 28 | 面板 · 弹窗 · 底部弹层 |
| `radiusPill` | 高度 / 2 | 导航胶囊 · 开关 · 分段轨道 |

改动两处：

- `GlassTile` 的默认圆角 **20 → `radiusL`** —— 全 App 每张卡片 +2dp，这是本轮唯一一处「所有界面一起动」的改动。
- `GlassPanel` 的默认圆角写成引用 `radiusXL`（值仍是 28，只是不再写字面量）。

> **≤16dp 的实心小元素一律走 `pillOf`。** 阶梯里没有小尺寸档是有意的：小到那个尺度时，圆角与 pill 的差别已经小于抗锯齿带来的差别，而 pill 在高密度排布下更干净（周期色条那种一排十几个的场景最明显）。

### 3.2 字号与字重（改成角色令牌，15 条）

**令牌即完整样式**（字号 + 字重 + 行高），界面层只写角色名，不再写 `fontSize` / `fontWeight`。颜色由调用处 `copyWith(color:)` 覆盖 —— 因为同一个角色在不同底色上（尤其班次色块）要取不同的可读色。

**同一样式只留一个令牌。** 选择器里的格子与大数字实测就是 `14/w500`（选中时 `copyWith(fontWeight: w700)`），与列表行主文字同一套样式，所以共用一个令牌而不另立。

| # | 令牌 | 样式 | 用在哪 |
|---|---|---|---|
| 1 | `ringClock` | 84 · w800 · ×1.0 | 响铃界面的时钟 |
| 2 | `pageTitle` | 28 · w700 | **我的 / 待办**两个页面的页题（日历页无页题；闹钟页的页题用的是 bigNumber） |
| 3 | `bigNumber` | 24 · w700 | 闹钟页**页题**（`L10n.titleAlarm`）；时间选择器中间的 `:` 分隔符 |
| 4 | `dialogTitle` | 20 · w600 | 弹窗与底部弹层标题 |
| 5 | `sectionTitle` | 18 · w700 | 区块标题；信息卡的日期行 |
| 6 | `cellDate` | 18 · w600 · ×1.15 | 日历格里的日期数字（今天 `copyWith(w800)`） |
| 7 | `titleStrong` | 16 · w700 | 卡片标题 · 输入框标签 · 弹层选项 · 主按钮 · 待办标题 |
| 8 | `labelStrong` | 14 · w700 | 弹窗按钮 · 更新通道名 · 「上班 / 休息」状态词 |
| 9 | `rowPrimary` | 14 · w500 | 行内主文字 · 信息卡的时间 · 选择器里的格子 |
| 10 | `rowSecondary` | 13 · w400 | 副标题 · 说明 · hint · 更新日志正文 |
| 11 | `labelSecondary` | 13 · w600 | 星期行 · 分组小标题 |
| 12 | `microStrong` | 12 · w700 · ×1.15 | **格子里的班次简称** · 「今天」徽章 |
| 13 | `microLabel` | 12 · w600 | 法定节假日徽章 · 其他班组色块 · 选择器星期 |
| 14 | `microText` | 12 · w400 | 微字正文：「其他班组」标签 · 高级材质说明 · 日志 |
| 15 | `tinyLabel` | 11 · w400 · ×1.15 | 格子里的农历 · 导航标签 · 他处小注 |

**为什么把 `microStrong` 和 `microLabel` 分开**：两者都是 12px，但活儿不同 —— 前者要在密网格里一眼读出来（日期格三行里最关键的一行），后者是容器内部的标签。并成一个，要么让日历核心那行字变轻，要么让所有徽章变重。

> **同名角色令牌不保证跨页面收敛。** 别把「同名」当成「同尺寸」：日历里的区块标题走 `sectionTitle`(18)，编辑器里的区块标题走 `titleStrong`(16)；`dialogTitle` 还被用在了年份滚轮上。要判断某处多大，看它**实际引的是哪个令牌**，而不是它叫什么名字 —— 更不要因为「两处角色同名、尺寸却不同」就去改代码，那是误导性的「对齐」。

**字重规则**：只用 **w500（正文）/ w600（标签）/ w700（强调）** 三档。`w800` 只保留在两处，且是规则不是意外：响铃大时钟、日历里的「今天」。

**一个角色内的个别变化走 `copyWith`，不另立令牌**：格子里的「今天」加粗、选择器选中项加粗、导航标签选中态、调休日的「班」标记转主色 —— 都是「同一个角色的一处刻意变化」，写成 `AppTokens.cellDate.copyWith(fontWeight: FontWeight.w800)` 比再造四个近义令牌清楚。

**Token 的准入规则**：只有当「已有令牌 + `copyWith(color:/fontWeight:)`」表达不出来时才新增。颜色不单独建令牌。

### 3.3 文字明度（新增，补上理念第 3 条的漏洞）

理念第 3 条说「层级只靠字号、字重、**明度**」，但明度恰恰是唯一没有令牌的一层。审计：次要文字用了 **0.45 / 0.5 / 0.55 / 0.6（还有 0.35、0.3）** 六种透明度，其中 0.55 用得最多（9 处），0.5 与 0.6 紧随其后 —— 全是「同一个角色被调了不同 alpha」。

> 「0.55 用得最多（9 处）」是当时的事实，但**「用得最多」不能当作选值的依据** —— 无障碍是硬标准，值必须按对比度实测来定。实测下来 0.55 / 0.60 在浅色底上都不过 AA，最终取 **0.62**（见下表）。

**收敛到两档**：

> 实测口径：浅色主题的 `colorScheme.onSurface` 是 M3 派生的 **`#1A1B20`**（不是 `inkLight` `#111118`），以下数字按它算。

| 令牌 | 值 | 用在哪 |
|---|---|---|
| `inkMuted` | `onSurface` @ **0.62** | 次要文字：副标题 · 说明 · hint · 分组标签 · 星期行。**值从 0.55 改到 0.62** —— 实测 0.55 只有 **3.72:1**（页面底 `#F5F6FA`）/ **3.85:1**（卡片 `#FFFFFF`），0.60 也只有 **4.39:1 / 4.53:1**，全不过 WCAG AA 的 4.5:1；0.62 在**页面底**（最坏浅底）**4.70:1**、**卡片 4.83:1**、略暗玻璃卡 `#EEF0F4` **4.59:1**，全过。暗色底下 0.55 本就过，所以改动只影响浅色主题 |
| `inkFaint` | `onSurface` @ **0.35** | **有意低于 AA 的豁免档**：禁用态 · 占位 · 待办已完成。低对比正是它的用途（已完成的语义由删除线另行承载，不靠明度），是**明确豁免**而不是漏网 |

> **（0.60 的残差已随跟进消除）**：先前取 0.60 时，压在浅色页面底 `#F5F6FA` 上的分组标签（如「我的 → 外观」）只有 **4.39:1**（更暗的玻璃卡 `#EEF0F4` 上 4.33:1），仍差 AA —— 页面底比卡片略暗，是这一档的最差底。跟进到 **0.62** 后页面底 4.70:1、卡片 4.83:1、玻璃卡 4.59:1，全浅底过线，**不再有残差**。

两个 alpha 抽成具名常量 `inkMutedAlpha` / `inkFaintAlpha`，由 `design_tokens_test.dart` 钉住 —— 下次谁想动这两个数，测试会先红、逼他先读这段理由。写成两个 helper 而不是两个 `Color` 常量，因为它要跟着主题明暗走：

```dart
static const double inkMutedAlpha = 0.62; // 页面底 4.70:1 / 卡片 4.83:1 全过（0.55 / 0.60 都不够）
static const double inkFaintAlpha = 0.35; // 禁用/占位/已完成档，有意低于 AA（豁免）

static Color inkMuted(BuildContext c) =>
    Theme.of(c).colorScheme.onSurface.withValues(alpha: inkMutedAlpha);
static Color inkFaint(BuildContext c) =>
    Theme.of(c).colorScheme.onSurface.withValues(alpha: inkFaintAlpha);
```

压在主色胶囊上的次要白字（日历顶栏）另用 `Colors.white.withValues(alpha: 0.98)` 那套，属于**前景色已定**的情形，不归这两档。

导航胶囊的未选中前景同理：它是磨砂玻璃、压在任意内容之上，对比度要求与页面正文不同，取值是暗 0.72 / 亮 0.55，**不并入这两档**，而是抽成 `navInactiveForeground(context, {required isDark})`，与 `navFill` / `navBorder` / `navForeground` 同一族。

### 3.4 间距（两套刻度）

原来只有「4px 栅格」一条规则，但审计发现那 40 处非栅格值里，6 和 10 **几乎全是「图标↔文字」的水平贴合**（按钮内、日历顶栏按钮之间、提示条），是有意的光学调整而不是随手写的。硬套 4px 会让图标显得脱开、小胶囊显得臃肿。所以拆成两套：

| 刻度 | 值 | 用在哪 | 令牌 |
|---|---|---|---|
| **节奏** | 4 · 8 · 12 · 16 · 20 · 24 · 32 | 页面留白 · 区块间距 · 卡片内边距 · 列表行 | `spaceXs` 4 · `spaceSm` 8 · `spaceMd` 12 · `spaceLg` 16 · `spaceXl` 20 · `space2xl` 24 · `space3xl` 32 |
| **光学** | 2 · 3 · 6 · 10 | 图标与文字之间 · 小胶囊/徽章的上下内边距 | `gapHair` 2 · `padChipV` 3 · `gapIconText` 6 · `gapIconTextLg` 10 |

`space2xl` / `space3xl` 与光学那四档都是新增的（现只有 Xs/Sm/Md/Lg/Xl 五档 = 4/8/12/16/20）。

**判定规则**：这个间距是在分隔两个**板块**，还是在贴合**一个控件内部的两个元素**？前者走节奏，后者走光学。

**强制规则（可被测试检查）**：间距位置（`SizedBox` 的 `height`/`width`、`EdgeInsets.*` 的参数）上的数字**只允许 `1`（描边与发丝线）与 `4` 的倍数**。出现 2 / 3 / 5 / 6 / 7 / 9 / 10 / 14 / 18 / 22 这类值一律失败，必须换成对应的光学令牌或就近归到节奏档位。

注意判定的是「**是不是 4 的倍数**」而不是「是不是那七个档位值」：像 `EdgeInsets.fromLTRB(16, 8, 16, 96)` 里的 96（给悬浮胶囊让位）虽然不在档位上，但它在栅格上，是合法的。

于是「4px 栅格」不再靠自觉：**栅格上的值直接写数字（它本身就是刻度），栅格外的值必须有名有姓**。实测 43 处、分布在 15 个文件，需要在迁移时归位。

### 3.5 颜色 / 玻璃 / 动效（沿用，只做清理）

- 配方、令牌值**全部不变**。只处理两个没人用的模糊令牌：`blurChip` / `blurCard` —— 要么删掉，要么把散落的字面量（`GlassTile` 的 `blurSigma: 18`、`GlassPanel` 默认 24）收编进来。**取后者**：让 `GlassTile` 引用 `blurCard`、`GlassPanel` 引用 `blurPanel`，`blurChip` 若无调用方则删。
- 动效令牌基本已在用。审计发现**一处漏网**：响铃界面的**入场动画** `Duration(milliseconds: 650)`（`alarm_ringing_screen.dart` 里 `_enter.forward()`，配 FadeTransition / ScaleTransition）不是令牌，补成 `durRingEnter = 650ms` 收进来。令牌名取 `RingEnter`（响铃**入场**）而非初稿的 `Flow` 命名 —— 「Flow」会被误读成背景光晕那圈循环，而它是响铃界面入场时的一次性动画；背景光晕的 26s `repeat()` 在 `core/theme/animated_background.dart`，本轮未纳入令牌（范围外，记为遗留）。

### 3.6 图标（收敛到三档）

现状 61 个图标里只有 11 个写了尺寸，其余吃 `IconTheme` 默认的 24。

**方案**：三档尺寸令牌 ——

| 令牌 | 值 | 用在哪 |
|---|---|---|
| `iconSm` | 16 | 小注 · 行内提示（信息卡闹钟图标等） |
| `iconMd` | 20 | 按钮内 · 列表项 |
| `iconLg` | 24 | 默认（`IconTheme` 统一设成它） · **导航项** |

**导航项归 `iconLg`(24)。** v0.6.11 曾把导航项归 `iconMd`(20)，出图对比后改为 24：胶囊里 20 的图标偏小、与 11px 的导航标签比例失衡，24 才站得住、更接近标准底栏。**不新增 22 这一档。**矮屏（52dp 胶囊、竖向更挤）按原设计回落 `iconMd`(20) —— 沿用历史的 `isShort` 分档（原 `isShort ? 20 : 22`），属**同一角色按布局档位的个别变化**（与 `copyWith` 区分选中态同性质），不新增令牌、也不违背「导航项归 `iconLg`」。（本节下方「13 处显式尺寸如实落到三档」与 §4 里写的「导航项 → 20」是 v0.6.11 当时的实装记录，导航项这一档已被本条校正。）

并把 `app_icon.dart` **真正用起来**：图标一律走 `AppIcon`，尺寸只从三档取。`IconTheme` 的 `size` 也设成 `iconLg`，这样漏包的图标也落在刻度上而不是裸 24。

现存的 **13 处**显式尺寸如实落到三档：`14→16`（节假日徽章里的庆祝图标，+2）· `16` 保持（×2）· `18→20`（弹窗关闭钮、提示条图标、次要按钮内图标，+2）· `20` 保持（×6）· `28→24`（×2：响铃界面的大闹钟图标、待办页 FAB，各 −4）· 导航项 `isShort ? 20 : 22` → `iconMd`(20)（常规态 −2）。**（v0.6.12 已校正这一处：常规态改归 `iconLg`(24)、矮屏保持 `iconMd`(20) —— 见 §3.6 的说明。）**

**这里原本写的是「11 处」且称 28→24 是「本轮唯一的图标缩小」，两处都错**：普查漏掉了写成三元的导航项（`size:` 后面跟着的是变量名不是数字，逐行正则扫不到），又把两个 `28` 都算给了响铃界面。实际是 **13 处、3 处缩小**。

其余约 40 个未写尺寸的图标本来就在 24，不受影响；`app_theme.dart` 的 `IconTheme` 也被显式设成 `iconLg`，让漏包 `AppIcon` 的图标同样落在刻度上。

## 4. 迁移清单（按文件）

**core/**

- `design_tokens.dart`：删掉 `fontDisplayXl`…`fontCaption` 那一组（改用 §3.2 的角色令牌）；新增 §3.2 的 15 条 `TextStyle` 令牌；新增三档图标令牌；新增光学间隙令牌；新增 `durRingEnter`；把「只留这四档」那段与代码矛盾的注释重写；`blurChip` 按调用情况去留。
- `glass/glass.dart`：`GlassPanel` 默认圆角改引用 `radiusXL` 与 `blurPanel`；`GlassTile` 默认圆角 **20 → `radiusL`**、`blurSigma` 引用 `blurCard`。
- `widgets/app_icon.dart`：上岗，图标尺寸只接受 `iconSm/iconMd/iconLg`。

## 5. 强制手段

新增 `app/test/design_tokens_test.dart`，两条：

1. **令牌自检**：断言 §3.2 那张表的字号 / 字重 / 行高逐一等于规格值。这样「规格」和「代码」是同一份，改令牌必须先改规格。
2. **字面量守门**：扫 **`lib/features/` · `lib/core/widgets/` · `lib/core/glass/`** 三个目录的全部 `.dart`（`lib/core/theme/` 是配色层本身、`design_tokens.dart` 是令牌定义处，都不在扫描范围内），出现下列字面量即失败：
   - `fontSize:` 后跟数字
   - `fontWeight: FontWeight.` —— **除非它落在 `copyWith(...)` 的括号内**（一个角色内的个别变化走 `copyWith` 是允许的，见 §3.2）
   - `onSurface.withValues(alpha:`（文字明度必须走 `inkMuted` / `inkFaint`）
   - `BorderRadius.circular(<数字>)`
   - `Duration(milliseconds: <数字>)`
   - `Color(0x...)`
   - `AppTokens.font<大写字母>`（旧的按尺寸命名的令牌，本轮之后一个不剩）
   - **间距位置上的非栅格数字**：`SizedBox` 的 `height`/`width` 与 `EdgeInsets.*` 的参数里，只允许 `1` 与 `4` 的倍数；其余一律要换成光学令牌或就近归到 4px 栅格上（见 §3.4）
   - **图标尺寸字面量**：`Icon(` / `IconThemeData(` 的参数里写数字

   **所有规则都读整个文件文本再定位，不是逐行匹配。** 这不是洁癖 —— 迁移期间靠实装才暴露出三个盲点，全都是「正则只在一行内找」造成的：① `Icon(` 与 `size: 28` 分写两行；② `onSurface` 与 `.withValues(alpha:` 链式跨行；③ `fontWeight:` 与 `FontWeight.wN` 三元跨行。三处都是手工发现的，守门测试一处都没拦住。

   两条**已知边界**，写在扫描器的注释里而不是靠口口相传：
   - **扫描读的是原始源码，含注释与字符串。** 所以注释里也不能字面写 `fontSize: 10`，写了会把构建打红（改写成「基线字号是 10」即可）。彻底解决要跳过注释/字符串，属于更大的改动，本轮不做。
   - 字重那条正则把 `)` `,` `;` 当作值的边界，所以 `fontWeight: f(x) ? FontWeight.w700 : …` 这种**条件表达式里带函数调用**的写法会漏。

   迁移期间用过一个 `_pending` 文件集合兜住尚未迁完的文件；**Task 8 收口时已连同它的进度用例一起删除**，现在没有任何豁免 —— 任何一个界面层文件写一个字面量都会立刻变红。

   与 `app_info_test.dart` 同一个套路 —— 把约定变成会红的东西，而不是写在文档里靠人记。
