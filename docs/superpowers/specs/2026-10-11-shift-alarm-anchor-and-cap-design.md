# 班次闹钟：三档落点 + 每班 10 条

- 日期：2026-10-11
- 起因：v0.11.0 真机反馈第 4、5 条（用户已确认这两条一起做、上限取 10）
- 影响版本：v0.11.1 测试版
- 相关既有规格：`2026-09-21-multi-alarm-per-shift-design.md`（多闹钟、原生 id 空间）
- 修订：2026-10-11 经 builder-check 后重写 §3（原规则会打到内置的 24 小时值班模板）、§5（`nextDay` 键名撞车）

## 1. 要解决的两件事

### 1.1 「班中闹钟」被排到了班次当天凌晨（**这是 bug，不是缺功能**）

用户原话：「有的人中班时间是下午 4:30 到次日 0:30。他想定一个 0:15 的闹钟，提醒自己准备下班。但是这个闹钟定不出来。」

代码里实算过一遍：班次 16:30 → 次日 00:30，编辑器把结束时间存成 **回绕式** `endMinute = 30`；值班窗口时长 `span = 30 − 990 + 1440 = 480`；闹钟 00:15 = `15`，相对上班的偏移 `rel = ((15 − 990) mod 1440 + 1440) mod 1440 = 465`；`465 < 480` ⇒ 判成「落在值班窗口内 → **班次当天**」（`domain/shift_rotation.dart:112-114`）。

而 `shiftAlarmFireAt`（`features/alarm/alarm_service.dart:83-90`）只有 `date` 与 `date − 1` 两个落点、**没有 `date + 1`**，于是这条闹钟排在班次当天凌晨 00:15 —— 比上班早 16 小时 15 分，且**不报错**。

根因是一条被写进设计的隐含假设：「落在值班窗口内」等价于「落在班次当天的钟点上」。**窗口跨过午夜时这是假的** —— 窗口内那一次出现在次日。同一条病在内置的 12 小时制夜班（20:30→08:30）上也一直潜伏着，只是模板里的闹钟恰好都避开了那一档。

### 1.2 一个班次只能挂 6 条闹钟

用户原话：「现在每个班次的闹钟最多只能有 6 个，还能不能再增加？」

6 不是产品口味，是原生 id 空间算出来的：id = `序号 × 天数窗口 + 天数偏移`，`6 × 60 = 360 ≤ 400`，400 是 Kotlin `cancelAllNativeAlarms` 的扫描上界。

### 1.3 用户追加：下班之后的钟点也要能表达

「比如 00:30 下班、他想 01:00 响一下提醒自己回家。」

这一类现在落在班次当天凌晨 01:00（上班前 15 个半小时），等于没用。

## 2. 目标 / 非目标

**目标**

- 闹钟的落点从「前一天 / 当天」两档扩到「前一天 / 当天 / **次日**」三档。
- 用户那个例子（16:30–00:30 + 00:15）落在**次日 00:15**（下班前 15 分钟）。
- 下班之后的钟点（16:30–00:30 + 01:00）落在**次日 01:00**。
- 上限 6 → **10**，原生 id 空间与 Kotlin 扫描上界同步。
- **内置的 20 种模板一条都不受影响**（这是硬验收，不是希望 —— 见 §3.2）。

**非目标**

- 不做「用户手动指定这条闹钟算哪天」的开关 —— 规则算出来、界面上把算出来的那天写出来给用户看。
- 不改原生 id 算式（`offset` 仍按**班次那天**算）。
- 不碰 `cancelAllNativeAlarms` 的盲扫（改成按清单撤是另一件事，另案）。
- 不碰自定义闹钟 / 待办提醒 / 重复待办的号段。
- 不给「24 小时值班」补「下班前闹钟」这一档（保持既有行为，见 §3.1 的例外）。

**反目标**（技术上做成了也算失败）

- 让老用户既有的闹钟静默改了日子却没有任何提示。任何行为变化都必须在更新日志里写明白。
- 让内置模板的闹钟换一天。**24 小时值班的 07:00 上班提醒就是这条红线上的例子。**

## 3. 落点规则（这一版的全部内容）

班次记在**班次当天 D**，上班钟点 `s`、下班钟点 `e`、值班窗口 `[s, s + span)`，`span = e > s ? e − s : e − s + 1440`（`e` 可能是累计式的 ≥ 1440，也可能是回绕式的 < s —— 两种存法同解，既有护栏在案）。闹钟的钟面值是 `t`（0..1439）。

**先算 `rel = (t − s) mod 1440`** —— 它的含义是「钟点 t 在上班之后**最近那一次**出现，距上班多少分钟」。`rel` 就是那一次出现相对上班的偏移。

规则：

1. **没有下班钟点**（`e == null`）：窗口算不出来 ⇒ 退回旧的两档 —— `t > s` → 前一天，否则当天。**这一类永远不会是次日。**
2. **窗口内**（`rel < span` 且 `span < 1440`）：落在那一次出现上，即绝对时刻 `s + rel`：
   - `s + rel < 1440` → **D**；
   - `s + rel ≥ 1440` → **D + 1**（窗口跨过午夜、这一次出现在午夜之后 —— **这就是 1.1 那个 bug 的修法**）。
3. **窗口外、且 `t > s`** → **D − 1**（既有约定，一字不动。v0.8.9 立的：00:00 上班、23:00 响铃排前一天）。
4. **其余**（窗口外、且 `t ≤ s`）→ **D 与 D + 1 里离窗口更近的那一个**：比较 `s − t`（D 落在窗口前多远）与 `t + 1440 − (s + span)`（D + 1 落在窗口后多远），取小者；**相等取 D**。（D − 1 不必参与：对 `t ≤ s` 它永远比 D 更远。）

**`span ≥ 1440` 的例外（24 小时值班）**：窗口长度达到一整天时，`rel < span` 对**任何**钟点都成立，「上班前」与「班次中」在模型上已经合并 —— 这时保持既有行为，**一律 D**（既有用例 `shift_rotation_test.dart:436`「24 小时值班：全天都算当天」钉的就是它）。**没有这条例外，内置的 `duty_24_24/48/72` 三个模板会一起回归**：它们配的 07:00 上班提醒，`span = 1440` 时窗口是 `[480, 1920)`，D 的 07:00 在窗口外、D+1 的 07:00 在窗口内 ⇒ 规则 2 会把它排到**次日 07:00**，也就是从「上班前 1 小时」变成「下班前 1 小时」。这是 builder-check 抓出来的，原稿漏了。

### 3.1 为什么第 4 条不是「离窗口最近」一刀切

那样会把第 3 条推翻：白班 08:00–20:00 的 22:00/23:00 现在排**前一天**（上班前 9~10 小时），最近原则会把它排成**当天 22:00**（下班后 2 小时）—— 那是没有用户要求、且与 v0.8.9 那条真机反馈相反的行为变化。第 3 条与第 4 条的交界就是「钟点是否晚于上班钟点」，这条线保持不变。

### 3.2 行为变化（必须逐条进更新日志）

| 类别 | 改前 | 改后 | 性质 |
|---|---|---|---|
| 跨午夜窗口内、落在午夜之后的钟点（20:30–08:30 的 02:00；16:30–00:30 的 00:15） | 班次当天 | **次日** | 修 bug |
| 正好等于下班钟点的那一刻（20:00–08:00 的 08:00；20:30–08:30 的 08:30） | 班次当天 | **次日**（就是那一刻） | 修 bug |
| 窗口外、`t ≤ s`、且 D+1 更近（16:30–00:30 的 01:00；20:30–08:30 的 09:00–14:29；白班的 00:00–01:59） | 班次当天 | **次日** | 新能力 |
| 钟点晚于上班钟点、且窗口外的一切（00:00 班的 23:00、白班的 20:00–23:59） | 前一天 | 前一天 | **不变** |
| 24 小时值班的一切钟点 | 当天 | 当天 | **不变**（§3 的例外） |
| `e == null` 的一切钟点 | 两档 | 两档 | **不变** |

**「内置模板不受影响」是硬验收，不是估计。** 实施时要把 20 种模板 × 各自的闹钟，在新旧规则下**逐条列出落点**做对比，差集必须为空；把这份对比做成一条用例（`shift_templates_test.dart` 那一族的方式），而不是靠读代码相信。（`duty_24_24/48/72` 能过全靠 §3 那条例外，所以这条用例同时也是那个例外的护栏。）

## 4. 上限 6 → 10

- `domain/shift_rotation.dart` 的 `maxAlarmsPerShift`：6 → 10。
- 原生 id 空间：`10 × 60 = 600`，最大 id `9 × 60 + 59 = 599`，与自定义闹钟段（`10000` 起）之间仍隔着三个数量级。
- `MainActivity.kt` 两处扫描区间 `for (id in 0..400)` → `for (id in 0..600)`（`cancelAllNativeAlarms` 与 `cancelAllNotificationAlarms`，现分别在 `MainActivity.kt:604` 与 `:620`）。
- `core/l10n.dart` 的 `alarmLimitReached`（`:516-517`）改数字。
- 守门用例 `shift_alarm_decision_test.dart` 的上界断言 `400` → `600`。

**注释与其它 `0..400` 引用一并扫掉**（builder-check 列出来的，实施时逐处确认）：
`MainActivity.kt` 两处循环、`AlarmStore.kt:191`、`WidgetRenderer.kt:77` 与 `:125`、`test/widget_fixed_cards_guard_test.dart:192`、`shift_rotation.dart:80`、`alarm_service.dart:275`（这两处引的行号 `MainActivity.kt:550` 也已过期，实际在 `:604`/`:620`）。

**代价**：每次 `reschedule` 多扫 200 个 id。那次重排本来就有约 600ms 的开销（扫 ~1400 个），多这一截不致命；真正该做的是把盲扫改成按清单撤，另案。

1. **编辑页每条闹钟行的钟点块**（`schedule_editor_screen.dart:715-724`）：`前一天 23:00` / `次日 00:15` / 纯钟点。
2. **编辑页整组那行小字**（`:772-791`）：现在只讲「前一天」，要能讲三档。措辞由实施定 —— 至少要把「有闹钟不在班次当天」这件事说清楚，多条时取**第一条非当天的**举例（与现状同构）。

## 6. 实现要点

- `alarmFallsOnPreviousDay` 那个 `bool` 撑不住三种状态。换成三值：枚举 `AlarmDayAnchor { prev, same, next }` 或等价的 `int` 偏移函数（`−1 / 0 / +1`）。**推荐枚举**，调用点 switch 不出错、名字自带含义。调用点共四处（§5 那四处）+ `shiftAlarmFireAt`。
- `shiftAlarmFireAt`（`alarm_service.dart:83-90`）按偏移建日期：`DateTime(y, m, d + delta)`，**仍然不能用 `add(Duration(days:))`**（夏令时会把钟点挪掉一小时，既有注释在案）。
- `planShiftAlarms`（`alarm_service.dart:122-153`）**不动**：它已经逐条调 `shiftAlarmFireAt`，`offset` 也仍按班次那天（`d`）。次日触发只改变 `fireAt`，id 不变 —— 那是「重排绝不重新编号」的前提。
- 三档判定与新 `shiftAlarmFireAt` 都是纯逻辑、不碰 Flutter，留在现有文件里（`domain/shift_rotation.dart` 判定、`features/alarm/alarm_service.dart` 算时刻）。

## 7. 验收

**新增用例**（先看着它红）

- 用户那个例子：`16:30 – 次日 00:30`（回绕式 `endMinute = 30`）+ 00:15 → **次日 00:15**；+ 01:00 → **次日 01:00**。
- 同一条班次、累计式 `endMinute = 1470` 与回绕式**逐钟点同解**（把新形状加进 `shift_rotation_test.dart:403` 那条「两种存法同解」）。
- 夜班 `20:30 – 08:30` + 02:00 → **次日 02:00**；+ 08:30（正好下班）→ **次日 08:30**；+ 09:00 → **次日 09:00**；+ 19:00 → **当天**；+ 14:29 / 14:30 → 次日 / 当天（阈值边界，写在用例名里）。
- 白班 `08:00 – 20:00` + 23:00 → **前一天**（第 3 条守住的证据）；+ 00:30 → 当天（白班的 `t < 02:00` 才改判次日）。
- **24 小时值班 `08:00 – 08:00` + 07:00 → 当天**（§3 例外，这条就是那个回归的护栏）。
- `e == null`：`t > s` → 前一天、`t ≤ s` → 当天，**永远不会次日**。
- 上限：编辑页到 10 条才收掉「添加闹钟」；`10 × 60 ≤ 600`。
- 原生扫描区间与 Dart 常量一致（扫源码，`MainActivity.kt` 的 `0..600` 对上 `maxAlarmsPerShift × shiftDaysHorizonForTesting`）。
- **模板差集用例**：20 种模板各自的闹钟，新旧规则下落点逐一对比，差集为空（§3.2）。

**既有用例的改动**（逐条列出，别偷偷改绿）

- `shift_rotation_test.dart:385-388`「20:00–次日 08:00 的夜班：19:00 与 02:00 都当天」—— 02:00 那一半改成**次日**（19:00 不变），用例名一起改。
- `shift_rotation_test.dart:394-401`「回绕式存法的跨午夜班（20:30 → 08:30 存成 510）也算得对」—— 凌晨 2 点那半从「当天」改成「次日」。
- `shift_rotation_test.dart:428` 起「正好等于下班时刻 / 下班之后 —— 与旧规则逐字相同」—— 它举的是 **00:00 班的 08:00**（`t > s`），走第 3 条、**应当不变**；跑一遍确认没被误伤。但它的注脚「与旧规则逐字相同」对**别的形状**已经不成立（20:00 班的 08:00 现在改判次日），措辞要收窄到它真正举的那个形状。
- `shift_alarm_decision_test.dart` 的上界断言 `400` → `600`。

**⚠️ 断言必须落在「哪一天」，不能只断言那个布尔值。** 现有一批用例断言 `alarmFallsOnPreviousDay(...) == isFalse`，而「次日」的返回值**也是 `false`** —— 光断言布尔值，一整类回归（比如 24 小时值班那三个模板）会**静默通过**。新用例一律断言 `shiftAlarmFireAt(...)` 的**日期 + 时刻**。

**真机复验**

- 配一条 16:30–次日 00:30 的班次 + 00:15 与 01:00 两条闹钟，确认闹钟页与日历信息卡都写「次日」，且到点真响。
- 班次里加到第 10 条，确认第 11 条的按钮收掉、说明文案对。
