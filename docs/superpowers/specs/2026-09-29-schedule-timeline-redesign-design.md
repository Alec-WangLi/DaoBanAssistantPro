# 排班时段重做（把「时段」从方案属性改成一条时间线）· 设计规格

> 2026-09-29 头脑风暴定稿。**目标版本由用户拍板**（末位 `Z` 归 AI，`X.Y` 归用户）。

## 1. 背景与目标

v0.9.12 把「多排班表按日期衔接」发了出去，用户真机试用后反馈两件事：

> **「假设我在日历界面切换排班那里，选了排班表一。然后我去排班管理那里不小心给两个新的排班表 2 跟 3 设定的生效时间都是 9 月 1 号到 9 月 30 号，最终回到日历界面，它给出的真正的排班表是排班表 3。感觉有点乱现在这个功能。同时日历界面的切换排班按钮相当于没用了，你切换什么班表呢？它现在也不会生效。」**

问题**不是有 bug**，是**按钮的语义和模型的语义打架**：

- 解析规则「起点最晚的赢」当初是为了**永远不报错**（重叠也有确定答案），代价是**结果不可预测** —— 用户看不出为什么是 3 而不是 2；
- 「切换排班」改的是 `isCurrent`，而 `isCurrent` 在这套模型里**只是没被时段覆盖时的兜底**。时段一旦盖满，那个按钮就什么也改不动 —— **用户以为它在管全局，它其实只在管「剩下的」**。

**目标**：让「某天归哪套」变成**没有歧义的唯一解**，并把「排时段」这件事从「某套方案的属性」提到它该在的层级 —— **一条时间线**。

## 2. 已定决策（2026-09-29 拍板）

① **保留「其余时间」，且它可以设成「无」。** 没被任何时段覆盖的日子用这一套；设成「无」时那些天**真的没有排班**（日历按现有「无班次」的画法画）。理由（用户原话）：「有的用户两个排班表之间，领导可能确实给他休息几天，有的时候他懒得去新建一个休息的排班表，直接留空也不是不行」。

② **界面并进「排班管理」页**（顶部一节），不新开页面 —— 一页看尽「我有哪些班表 + 它们怎么排」。

③ **日历顶栏那个按钮换成「排班时段」只读总览**：图标从「上下箭头」换成时间线，点开按时间列出各段 + 其余时间，**高亮今天所在的那段**，底部「管理排班时段」跳到排班管理页。它不再假装能切换，但「这段时间在用哪套」一眼看得到。

④ **重叠一律禁止**（用户原话：「一个人不可能一天同时有两个排班吧？我只能认为是他在排班的时候不小心弄错了时间」）。保存时校验、撞上不让存、点名冲突的那一段；**不做自动截断**。

## 3. 模型：只改一条规则

### 3.1 存储完全不动（零 schema 改动的部分）

- 段仍然是 `ShiftScheduleRows.effectiveFrom` / `effectiveTo`（可空闭区间，语义不变）；
- 「其余时间」仍然就是 `isCurrent` 那一行 —— **只是改了说法**。

**没有新表、没有新列。** 这是本次重做最省的地方：`ScheduleChain` / `Span` / 日历 / 闹钟 / 小组件那一条链路**一行都不用改**。

### 3.2 解析从「三段」变「两段」

```dart
ShiftSchedule? scheduleOn(DateTime day) {
  // 段之间不重叠（界面禁止 + 迁移规整过），所以至多命中一段。
  // **真命中两段时仍按「起点最晚的赢」取** —— 那条规则降级成纯防御的
  // tiebreak，只在库里真有重叠（脏数据 / 手工改库）时才会用到。留着它而不是
  // 直接取第一段，是因为「按列表顺序取第一个」是另一种**静默的不确定**。
  ScheduleSpan? best;
  for (final s in spans) {
    if (!s.covers(day)) continue;
    if (best == null || _startsLater(s, best)) best = s;
  }
  return best?.schedule ?? fallback;   // 「其余时间」；可能为 null
}
```

`fallback` 从「一定有」变成**可以为 null**：`isCurrent` 全为 false 是合法状态。

### 3.3 重叠校验（新）

```dart
/// [self] 之外的、与它时段重叠的那些段（按起点升序）。
/// 重叠**不允许**：界面在保存前拿它拦下并点名。
List<ScheduleSpan> conflictingSpans(List<ScheduleSpan> all, ScheduleSpan self);
```

就是现在的 `overlappingSpans` 改个名与用途（原来服务于「提示一句」，现在服务于「不让保存」）。首尾相接仍**不算**重叠（`A.to + 1 天 == B.from` 是正常的衔接）—— 这条判据原样保留，它的用例也原样保留。

### 3.4 仓库层新增一个方法

```dart
/// 把「其余时间」设成**无**（全部 `isCurrent = false`）。
Future<void> setRemainingNone();
```

以及 `setCurrentSchedule` **保持不变**（它仍是设置「其余时间」的唯一入口，只是现在只由「排班时段」那一节调用）。`currentScheduleId()` 在全部为 false 时返回 null —— 它本来就会，只是从前有「保证恰好一套」的约定在，现在那个约定没了。

### 3.5 为什么这样更简单

- **用户看到的歧义没了**：某天最多只有一段覆盖，答案是唯一的；
- **没有「谁的起点更晚」这条要记住的规则** —— 它在界面上再也不出现了；
- **不能表达的状态就别让它可表达**：重叠不可能被建出来（校验挡在保存前），所以「乱」的源头被堵掉了。

## 4. 界面

### 4.1 排班管理页：顶部一节「排班时段」

**不分「有段 / 无段」两套版式** —— 永远列出「其余时间」那一行，没有段时就只有它。

```
排班时段
  没被时段覆盖的日子，用「其余时间」那一套。
  其余时间            四班两倒     ›
  ＋ 添加时段
```

有段时（按起点升序，「其余时间」恒在最上）：

```
排班时段
  没被时段覆盖的日子，用「其余时间」那一套。
  其余时间            四班两倒     ›
  9月1日 ～ 9月30日     备选A       ›
  10月3日 ～           排班表三     ›
  ＋ 添加时段
```

- 点任意一行 → **编辑弹层**：换排班表 / 改起 / 改止 / 删除。起止**都可留空**（留空 = 不限起点 / 一直持续），各带一个清除钮。
- 「其余时间」那一行多一个动作：「**设为无**」。
- 「＋ 添加时段」→ 同一个弹层（新建态：选排班表 → 选起止）。
- **保存时校验重叠**：撞上就不写库，弹一句点名冲突（`L10n.spanConflicts(名, 区间)`）。

### 4.2 排班表列表（页面下半部分，基本不变）

每行仍显示「时段标签 · 班组数 · 锚点日」，时段标签复用现成的 `effectiveRangeLabel`，只改两处说法：

| 情形 | 旧 | 新 |
|---|---|---|
| 没段、是 `isCurrent` | 其余日子 | **其余时间** |
| 没段、不是 `isCurrent` | 未参与衔接 | **未使用** |

「未使用」的行补一句轻提示（副标题尾巴）：**「未使用 —— 去上面的「排班时段」把它排进去」**。这一条是为了补上「新建排班不再自动接管」带来的落差（见 §5）。

### 4.3 日历顶栏：`切换排班` → `排班时段`

- 图标 `Icons.swap_vert_outlined` → `Icons.timeline`（具体用哪个图标等出图时看，工装会拍）；
- 点开是**只读**的底部弹层，与 §4.1 同一个列表形态（「其余时间」+ 各段），**把今天所在的那一段高亮**（打勾 + 主色），底部一个「**管理排班时段**」跳到排班管理页；
- 不再有「点一行就切过去」这个动作 —— 那正是让人以为「切换生效了」的根源。

**日历上那片真正的空白**（其余时间设成「无」、又没段覆盖）：在网格中间给一句说明 —— `L10n.noScheduleHere`（「这段时间没有排班 —— 去「排班时段」里加一段」）。**不放动作按钮**（日历不是编辑场所），一句话指路即可。

### 4.4 编辑器：删掉「生效时段」那一节

`ScheduleEditorScreen` 回到只管班次与周期。保存路径里的 `setScheduleSpan` 调用、`_effectiveFrom` / `_effectiveTo` 状态、校验与重叠提示**一并删掉**。

## 5. 连带的行为变化（写下来免得被当成 bug）

- **「新建排班」不再自动接管日历。** 从前日历弹层里那条路走 `makeCurrent: true`；现在那条路没了，只剩排班管理页的 `makeCurrent: false` —— 新建出来的方案是**未使用**，要生效得去「排班时段」把它排进去。这是**有意的**：一个刚建出来、还没看过的班表不该悄悄接管整张日历。落差由 §4.2 那行「未使用 —— …」补上。
- **「设为无」是唯一能到达「没有默认」的入口。** 删掉一套方案时**仍然自动把「其余时间」交给列表里的第一套**（与今天一致），免得「删了一套之后整张日历变空」这种惊悚结果。想让空白真的是空白，自己去点「设为无」。
- **`clearAll` 不变**（清空后会重新播种一套默认）。

## 6. 迁移：schema 12 → 13（纯数据规整）

v0.9.12 已经在真机上跑过，库里可能躺着重叠的段。**必须把数据整理成合法的**，否则新界面一打开就显示一个它宣称不可能存在的状态。

**规整规则：按 v0.9.12 的解析结果等价改写** —— 升级前后日历上看到的一模一样，只是数据变合法。

算法（一次事务，只写改过的行）：

1. 读出所有**带时段**的行，按 `(from 升序，from 为空排最前；并列按 id 升序)` 排序；
2. **从后往前**走一遍，维护一个「下一个保留下来的段的起点」水位线：
   - 若当前段的 `to` 为空（一直持续），或 `to ≥ 水位线 - 1`（也就是它伸进了下一段），就把 `to` 截到 `水位线 - 1`；
   - 截完若 `to < from`（整段都被后面的盖住了），**把两列都清成 null**（它变成「未使用」）；
   - 更新水位线为当前段（保留后的）起点。
3. 只 `UPDATE` 真正改了值的行。

举例（都是老规则下会出现的形态）：

| 升级前 | 解析出来的结果 | 升级后 |
|---|---|---|
| A `[1/1, ∞)`、B `[7/1, ∞)` | 1/1–6/30 归 A、7/1 起归 B | A `[1/1, 6/30]`、B `[7/1, ∞)` |
| A `[8/1, ∞)`、B `[7/1, ∞)`（列表序） | 全程归 A | B `[7/1, 7/31]`、A `[8/1, ∞)` |
| A `[1/1, 12/31]`、B `[1/1, 6/30]`（A 的 id 大） | 全程归 A | B 清成 null（未使用）、A 不动 |

**schemaVersion 12 → 13**，只有 `if (from < 13)` 一个分支、里面是 Dart 逻辑（读表 → 算 → 写回），没有 DDL 改动。

⚠️ 照惯例：**迁移分支倒序跑**，从更早版本升上来时这段也会执行。它只读 `shift_schedule_rows` 的时段列，而那张表从 v1 就在、每份 fixture 都建过它 —— 所以**这次不用给更早的 fixture 补 DDL**。但实施时要把全套迁移测试跑一遍确认（v11→v12 那次的教训）。

## 9. 明确不做

- **不做独立的「排班时段」页**（已定：并进排班管理）。
- **不做自动截断 / 一键修正重叠**：不替用户改设置，只告诉他撞了谁。
- **不做时间线的拖拽排序**：段是按日期排的，手排没有意义。
- **不做「按周 / 按月的重复时段」**（「每周三换那套」这类）：时间线就是两个日期。
- **不在日历上放编辑入口**（只读总览 + 一句指路）。
- **不动 `ShiftAlarmOverrides`**（按天关闹钟，全局表）与 `ShiftDayOverrides`（按天改班，按 `{scheduleId, day}` 归属）。
- **不改 Kotlin**：这一轮连 `ShiftSource` 那条链路都不碰。

## 12. 风险与坑

1. **迁移必须与旧解析结果逐条等价** —— 用户已经在用 v0.9.12，升级后日历**不能有一天的班变了**。§6 那三条用例就是钉这个的；实施时**先写用例、拿旧规则算一遍期望值**，再写迁移。
2. **「其余时间为 null」是新的合法状态**，所有 `chain.fallback` 的消费点都要能接住 null：日历（网格 / 信息卡 / 本月统计）、闹钟（`planShiftAlarms` 本来就逐天 `shiftOn`，null 只是不排）、小组件（见第 7 条）。
3. **`deleteSchedule` 的自动接管要保留**（§5），否则「删掉默认那套」会让整张日历变空。它的现有用例（`save_schedule_current_test` / `deleteSchedule` 那几条）**必须原样全绿**。
4. **`setScheduleSpan` 仍要公开**：现在只有「排班时段」弹层调它，但**空值必须能写下去**（把设好的时段清回留空），所以那句「显式构造 `Value`」的注释与理由要留在原地。
5. **日历弹层从「能切」变成「只能看」**，`_switchSchedule` 与 `Haptics.commit()` 那处要一起删干净 —— 留一个没有入口的私有方法会在下一轮审查里被当成死代码。
6. **`effectiveRangeLabel` 的两种「没设」说法要改**（其余时间 / 未使用），而 `schedule_span_label_test.dart` 里那两条断言要跟着改 —— 别只改实现忘了用例。
7. **`hasCycle` 的语义在 fallback 为 null 时要重新过一遍**：它是「链上有没有一套有周期的方案」，用于小组件的空态判定；无段 + 其余时间为无时应当是 `false`（桌面显示空态提示），这条要有用例。
