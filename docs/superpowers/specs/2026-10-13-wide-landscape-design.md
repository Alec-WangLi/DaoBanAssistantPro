# 横屏（平板 / 车机）重新适配（设计）

- 日期：2026-10-13
- 起因：用户把 v0.11.13 装到**车机**上，拍了五张实际照片回来（日历 / 编辑排班 / 我的 / 闹钟 / 待办），
  并提出五条：
  1. 横屏下**顶栏太长**，希望「统一放到左边，跟日历一起」；
  2. 日历的**日期内容老被底部悬浮胶囊遮挡**，要重新优化大小；
  3. **今日信息卡缩在屏幕右上角**一小块，觉得奇怪，「就算是一小块，也得放在右下角吧」；
  4. **底部悬浮导航胶囊被拉太长**，可以缩短；
  5. 系统字号已经调到**特大**，日历界面的字**还是偏小**。
- **用户拍板（2026-10-13，三轮）**：
  1. 优先级 = **「扫一眼就走，主要是看今天什么班」** —— 车机是**看板**，操作回手机上做。
     原话：「毕竟都放车上了，哪有时间再操作这些啊？要操作也是搁手机上再单独操作嘛。**所以你要搞清楚优先级。**」
  2. 版式选 **方案 A**（左栏＝顶栏＋日历，右栏＝今日卡贴右下）。
  3. 范围：**优先日历页 + 胶囊**；另外三个 tab 的宽屏「如果难度不大的话，也顺便一起」。
- 影响版本：从 v0.11.14 起。

---

## 1. 现状：量出来的，不是推的

一次性探针（`app/tool/probe/landscape_probe_test.dart`，跑完即删）把五个页面在
**1024×600 / 1280×800 / 1920×720** 三档下渲了一遍 —— 屏单里**从来没有过「宽且不矮」这一档**
（只有 900×420 那个「宽且矮」的手机横屏）。五条抱怨在图上全部复现，各自在代码里找到了根因：

| # | 症状 | 根因（代码位置） |
|---|---|---|
| 1 | 顶栏横跨整屏 | 一行档的顶栏是 `Row[‹, Expanded(年月胶囊), ›, 总览, 今天]` —— **年月胶囊外面套着 `Expanded`**，拿到多宽就撑多宽。1280 上那条胶囊长约 1600px（`calendar_screen.dart:956`） |
| 2 | 最后一行被胶囊压住 | 网格视口 = 「整屏高 − 顶栏」，**没有给底部胶囊留位**。竖屏时下面压着信息卡（卡片自带 96 的让位），宽屏把卡片挪进侧栏之后，网格就一路铺到屏幕底（`calendar_screen.dart:794`、`calendarCellHeight`） |
| 3 | 信息卡缩在右上角 | 宽屏分栏里卡片放在 `SizedBox(width: 300)` 的侧栏，而 `Row(crossAxisAlignment: start)` 让它**顶对齐**；它内容本来就短，于是是一小块浮在右上、下面一片空（`calendar_screen.dart:816-830`） |
| 4 | 胶囊被拉太长 | `GlassNavBar` 只有 `Padding(horizontal: outerPad)`、**没有上限宽度**。1920 上四个 tab 摊开 1900px（`glass_nav_bar.dart:282`） |
| 5 | 格子里的字不跟字号走 | 格子内容按 `(cellH − 内缩) / _cellDesignH(55)` 等比缩放，**并被夹在 `_cellMaxScale = 1.25`**。车机上 cellH ≈ 90~120，早就顶到天花板 —— 于是调特大、格子变大，字都不再长（`calendar_screen.dart:1782`、`:2891`） |

第 5 条**不是 bug**：那个 1.25 是 v0.7.2 照**手机格子**定的（「再大就喧宾夺主：格子被字填满、
格子之间的呼吸感没了」）。这条判断在手机竖屏上是对的，在**车机**上正好相反。

## 2. 规矩：这一版要什么

按用户给的优先级（**看板**，不是操作台）定四条：

1. **一眼看得清** —— 今天什么班 / 几点，是这一页的第一信息。格子里的字**跟着格子长**，
   不在车机上停在手机那一档。
2. **没有任何内容被悬浮层压住** —— 网格的六行、右栏的信息卡，都完整落在胶囊之上。
3. **横屏才变，竖屏一个像素都不动** —— 手机竖屏、小窗（200×400）、400×640 各档，
   版式与观感逐像素不变。这是本轮的**硬验收**。
4. **操作照旧** —— 手势（点选 / 长按拖选 / 液态玻璃那套）、数据、闹钟链全部零改动。

- **左栏** = `Column[ 顶栏, 周标题, 7×6 网格 ]`。顶栏**收进左栏**且**左对齐、不再拉伸**。
- **右栏** = 固定宽（见 §4.4），内部把卡片推到底：**没有富余时整栏可滚**，而不是溢出。
  写法照抄竖屏那一支的思路（`ConstrainedBox(minHeight: 视口高)` 套在 `SingleChildScrollView`
  里、`Column(mainAxisAlignment: end)` 把卡片推到底）—— 富余时卡片贴底、不富余时这一栏
  自己滚（「面板套滚动」在 AGENTS.md 里是被禁的，**但这一栏不是面板，是布局列**；竖屏
  信息卡那一支本来就有同样的兜底，见 `calendar_screen.dart:2757`）。
  卡片自身仍是「内容多高就多高」（`inSidePane: true` 那条路不变）。
- **两栏都让开胶囊**：整个 Row 底下留 `kNavCapsuleInset`（96），与竖屏信息卡用的是**同一个常量**。

草图（A / D / E 三版并排）画在 `app/build/mockups/`（`build/` 是 gitignore 的临时产物，
用 `python -I build/mockups/gen.py` 重新生成）。**用户在三版里选了 A**：
D 是顶栏竖过来贴左边缘（省一行高度但月份不好扫），E 是右栏整列都给「今日」（字最大，
但就不是「右下角一小块」了）。

## 4. 逐项决定

### 4.1 什么时候换版式：新增 `AppLayout.isWideLandscape`

```dart
/// 平板 / 车机的横屏：**够宽、够高、而且是横着的**。三个条件缺一不可。
final bool isWideLandscape;
```

| 条件 | 为什么 |
|---|---|
| `isWide`（宽 ≥ 720） | 有横向余量才谈得上分栏 |
| `!isShort`（高 ≥ 480） | 手机横屏 900×420 分栏之后网格每行只剩 41dp（`_minCellH` 是 58），比现在还差 |
| `availableWidth > availableHeight` | **竖着的平板**（800×1280）也满足 `isWide`，但它该走竖屏那套 —— 七列格子要的是宽度，不是分栏 |

⚠️ **`isWide` 本身不动**。`CenteredContent`（另外三个 tab 与三个编辑页）靠它把内容限宽到
720；把方向条件并进 `isWide` 会让**竖屏平板从「居中 720」变成「拉满整屏」**，那是另一个 bug。

**这顺带修掉一处既有的怪相**：现在日历页判的是 `layout.isWide`，于是**竖着的平板**
（800×1280）也会被拆成左右两栏、信息卡缩在右上角。改成 `isWideLandscape` 之后它走竖屏版式。
（真机上一台都没有，但判据本身是错的。）

### 4.1.1 ⚠️ 日历页因此是**三支**，不是两支

把「分栏」的判据从 `isWide` 换成 `isWideLandscape` 会让**「宽且矮」（手机横屏 900×420）**
掉进竖屏那一支 —— 而竖屏那一支里有 `if (!layout.isShort) gridArea`（`calendar_screen.dart:839`），
**格子会被整块删掉**，只剩一张紧凑信息卡。那是实打实的回归。

所以这一页必须是**三支**：

| 档 | 判据 | 版式 |
|---|---|---|
| **宽横屏**（平板 / 车机） | `isWideLandscape` | §3 的新版式（顶栏进左栏、卡片贴右下、字号上限放开） |
| **宽且矮**（手机横屏） | `isWide && isShort` | **今天的版式原样保留**（顶栏仍横跨全屏、卡片仍在右上栏）**＋ 让开胶囊**（§4.2）**＋ 字号上限放开**（§4.5，格子小，实际不生效） |
| 其余 | 其余全部 | 竖屏版式，**一个像素不动** |

第二支的存在只为一件事：**不改手机横屏的既有观感**，但把「最后一行被胶囊压住」修掉。

### 4.2 网格必须让开胶囊（**两支宽屏都要**）

用 `kNavCapsuleInset`（96，`core/layout.dart`）—— **与竖屏信息卡下方那 96 是同一个常量**
（`calendar_screen.dart:2714` 那里写着它的来历：64 的胶囊 + 32 余量，84 时卡片底边几乎贴在胶囊上）。

| 支 | 怎么留 |
|---|---|
| 宽横屏（新版式） | 整个 Row 的**外面**包一层 `Padding(bottom: kNavCapsuleInset)` —— 左右两栏（网格与卡片）同时让开 |
| 宽且矮（今天的版式） | 在 `Row` 外面同样包一层。顶栏仍横跨全屏、**不受影响**（它在 Row 之上） |

**竖屏那一支不动**：它本来就把 96 写进信息卡自己的内边距里（`fromLTRB(16, 8, 16, 96)`），
那是**卡片**让位，不是页面让位 —— 别顺手把它也套上，那会白留 96dp。

### 4.3 顶栏：横屏下收进左栏、内容收缩、左对齐

- 只在 `isWideLandscape` 下生效；其余档位走现有的「一行 / 两行」两支，一个字不动。
- 横屏下**永远一行**（触发线上左栏宽约 396dp，`_oneRowFits` 必然为真），所以那一支可以不走判据。
- 关键改动只有一处：**年月胶囊不再套 `Expanded`**，改成按内容收缩（`IntrinsicWidth` 或
  按排版量出的固定宽），整行 `mainAxisSize: min` 靠左。于是 ‹ 年月 › 总览 今天 五个控件
  挤在左边一小片，右边不再是空的。

### 4.4 右栏宽度

```dart
final railW = (layout.availableWidth * 0.27).clamp(280.0, 340.0);
```

- 1280 → 340（夹到上限）；1024 → 280（夹到下限）；1920 → 340。
- 为什么**不是写死 300**（现状）：720/800 这种刚过线的宽度上，写死 300 会把左栏挤到
  360 宽（格子 48dp）；比例 + 上下限在小屏上把右栏收窄、把宽度让给日历。

### 4.5 格子字号的上限在宽屏档放开

`_cellMaxScale` 由常量改成**按档位取值**：

| 档位 | 上限 | 理由 |
|---|---|---|
| 非宽屏（手机竖屏 / 窄屏 / 小窗） | **1.25（不变）** | v0.7.2 定的是「不许喧宾夺主」，手机上仍然成立 |
| 宽屏（`isWide`，横竖都算，含竖屏平板） | **1.7** | 车机上格子高 90~120，1.7 让内容占到格子的 ~78%，字明显变大而仍有呼吸 |

判据取 `isWide` 而不是 `isWideLandscape`：**宽且矮那一支格子只有 41dp 高**，上限根本不生效，
多一个分支只是多一处要维护的东西。**竖屏平板（`isWide` 但仍然竖着）因此也会拿到 1.7** ——
它格子高约 177dp，`(177−12)/55 ≈ 3.0` 顶到 1.7、内容占 52%，比现在（1.25、占 39%）更饱满，
是想要的（§4.1 只把**分栏**挡在横屏之外，没把字号一起挡住）。

`_cellMaxScaleWide = 1.7` 是**起手值**，实现后要出图核（1.7 是照 1920×720 上 cellH≈90 反推的：
`(90 − 12) / 55 ≈ 1.42` 不顶上限，1280×800 上 `(104 − 12) / 55 ≈ 1.67` 刚好顶到）。
**这条是观感决定，出图之后可能还要回来调。**

### 4.6 底部导航胶囊限宽

`GlassNavBar` 外面套一层 `ConstrainedBox(maxWidth: 440)` + 居中。

- **居中是相对整个屏幕**，不是相对日历的左栏。`GlassNavBar` 挂在 `HomeShell` 的
  `bottomNavigationBar` 上，它**看不见**日历页的栏宽 —— 也正因如此，草图里那条胶囊看起来
  在左栏下面只是示意（1280 上两者差约 150dp）。这一条**有意如此**：胶囊是全 app 的，
  不该跟着某一页的分栏走。
- 440 ≈ **手机那一条胶囊的宽度**（420 宽的屏上是 372）。四个 tab 每个 110dp，
  比手机上的 93dp 还宽一点，不会局促。
- 加 `ConstrainedBox` 会同时改到**标准档**那棵树 —— 这与仓库里那条
  「两档各一棵树、标准档逐像素不变」**不冲突**：标准档的「不变」指的是**加液态玻璃之前**
  的观感，而这里是**有意的设计改动**（用户第 4 条），两档都会宽屏限宽。
- **已有一屏会变**：屏单里 `landscape 900×420` 那一档的胶囊从 **868** 变成 440
  （900 − 外侧留白 16×2 = 868，那一档是 `isShort`）。这是预期的。
- ⚠️ 矮屏那一档（`isShort`，胶囊高 52 / 外侧留白 16）**尺寸一个字不改**，只是宽度被夹到 440。

### 4.7 另外三个 tab

**它们已经没问题**：`alarm_screen` / `schedule_screen` / `profile_screen` 三页与
`schedule_editor` / `schedule_management` / `shift_template_picker` 三个编辑页**都已经套了
`CenteredContent`**（宽 ≥ 720 时限宽 720 并居中）。1280×800 上出图核过：三页都是
一列 720 居中的内容，没有任何溢出或错位。

所以这一轮它们**只跟着 §4.6 的胶囊限宽一起变**，内容版式不动。

**唯一一处看得出不一致的**（**用户 2026-10-13 拍板：收**）：待办页那颗悬浮「＋」按钮
落在**屏幕**右下角，而列表限宽在中间 —— 在 1280 上两者对不上。

⚠️ **不能靠给 FAB 套一层 `CenteredContent`** —— FAB 的落点由
`FloatingActionButtonLocation` 算（`schedule_screen.dart:886` 的 `_AboveCapsuleFabLocation`），
外面套盒子只会跟 Scaffold 的定位打架。**要改的是那个 location 的 `getOffset`**：

```dart
// 内容栏宽度（与 CenteredContent 的判据同源：宽 ≥ 720 才限宽）
final contentW = math.min(AppLayout.maxContentWidth, geometry.scaffoldSize.width);
final rightEdge = (geometry.scaffoldSize.width + contentW) / 2;
return Offset(rightEdge - geometry.floatingActionButtonSize.width - _fabMargin,
              base.dy - 76);
```

- **手机上逐像素不变**：`scaffoldSize.width = 420 < 720` → `contentW = 420` →
  `rightEdge = 420` → `dx` 与 `endFloat` 一模一样。
- 1280 上 FAB 从屏幕右缘（x≈1208）挪到内容栏右缘（x≈928）。
- 那个 `-76`（抬到胶囊之上）**不动**。

范围因此变成：日历页 + 三个 tab + 一个 location。

### 4.8 一个字不动的东西

- 手机竖屏 / 窄屏 / 小窗（200×400）/ 400×640 的全部版式（**硬验收：逐像素不变**）
  - **例外只有一个**：**竖屏平板**（`isWide` 但竖着，如 800×1280）格子里的**字号**会变大
    （§4.5 的判据是 `isWide`）—— 版式不变，只有格子内容更饱满。真机上一台都没有。
- 日历的手势：点选、长按拖选、液态玻璃的透镜 / 水带 / 飞行、「点今天」
- `info_card_metrics` 的算法（横屏下卡片仍走 `inSidePane: true` 那条「高度交给内容」的路）
- 数据层、闹钟链、桌面小组件、原生 Kotlin —— **一行都不改**

## 6. 护栏与验收

### 6.1 常设护栏（新用例）

1. **`isWideLandscape` 的判据**（纯函数，`layout_test.dart`）：
   - 1280×800 / 1920×720 / 1024×600 → true
   - 800×1280（竖着的平板）→ **false**
   - 900×420（宽且矮）/ 420×900 / 360×780 / 200×400 → false
2. **⭐ 900×420 上网格仍然在**（回归用例，`calendar_screen_test.dart`）：
   在 900×420 下断言 `day-card-*` 的个数 > 0。**这条是本轮最容易踩坏的地方** ——
   把分栏判据从 `isWide` 换成 `isWideLandscape` 而不补第二支，格子会被
   `if (!layout.isShort)` 整块删掉，界面上只会少一块、不报任何错（§4.1.1）。
3. **宽屏下网格的六行完整落在胶囊之上**（几何断言，`calendar_screen_test.dart`）：
   滑到底之后，最后一行格子的底边 ≤ 胶囊顶边。**夹具的月份必须真的有六行**。
4. **宽屏下胶囊宽度 ≤ 上限**（几何断言，`glass_tier_test.dart`）：
   1280 与 1920 两档各断言一次；420 竖屏断言仍是 372（**没被限宽影响**）。
5. **宽屏下顶栏不再拉伸**：断言年月胶囊的宽度 < 左栏宽度的某个比例（现在它恒等于整屏宽）。
6. **格子字号上限按档位走**：同一个 `cellH` 下，宽屏档算出的缩放 > 竖屏档。
7. **待办 FAB 的落点**（`schedule_screen_test.dart`）：
   - 420×900 下与 `endFloat` 逐像素相同（`dx` 相等）—— 钉住「手机上零变化」；
   - 1280×800 下 FAB 的**右缘**与内容栏右缘对齐（差 ≤ 16 + 1）。

### 6.2 工装

- 新增一个**宽屏档循环**（照 `xl360` / `xl320` 那两个循环的写法，不铺全部 39 屏）：
  `1280×800` 与 `1920×720` 各渲 `00_home_shell` / `01_calendar` / `05_todos` / `06_alarm` /
  `07_profile` / `02_editor`。

  而真正需要人眼的只有这六屏。

## 7. 不做什么

- **不做「宽屏下把另外三个 tab 的版式重排」**（比如闹钟页改成两栏）—— 它们已经限宽居中，
  没有坏掉的地方；用户说的是「顺便」，成本收益不成比例。
- **不做横向平板（800×1280）的专门版式** —— 走竖屏那套即可。
- **不碰桌面小组件** —— 它是原生 `RemoteViews`，与这一页无关。
- **不动 `CenteredContent` 的 720** —— 1280 的车机上 720 居中是对的（表单拉满整屏更难读）。
- **不给胶囊做「随屏幕变宽而变宽」** —— 上限就是上限。
