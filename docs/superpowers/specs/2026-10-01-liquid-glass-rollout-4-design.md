# 液态玻璃推广 · 第四轮（开关轨道色 / 弹窗凝聚 / 响铃页药丸）设计

> 规格。实施计划见 `docs/superpowers/plans/2026-10-01-liquid-glass-rollout-4.md`（下一步写）。
>
> 上一轮（竖直档的轮廓 / 彩边落点 / 升程冻死）见
> `2026-10-01-liquid-glass-rollout-3-design.md`。版本：`0.10.12+136` → **`0.10.13+137`**。

## 1. 目标

v0.10.12 装上真机之后，用户提了两件事：

- **A. 开关的轨道色要跟着拖动走。** 原话：「长按拖动滑块时，能不能把它背景的颜色也一起变了？
  比如现在开着的时候，背景是蓝色……拖动的时候，能不能也把背景色的变化做出来？
  你可以看一下 iOS 26 里他们那个开关拖动时底部胶囊的颜色是怎么过渡的。」
- **B. 全 app 还有哪些地方可以加液态玻璃。** 原话：「不一定非得都是现在这种液态玻璃滑块的
  形式。」

**A 已经实施并提交**（`34d7684`），本规格一并记档。B 经一次全 app 扫描 + 三轮真机看图，
收敛成两处落地。

## 2. 用户拍板的（不可自行更改）

1. **开关轨道色走「跟着滴漫过去」** —— 两档并排图里挑的 B（另一种是「整条一起淡入」）。
2. **第 2 条做两处**：响铃页的上滑关闭、二十来个实心面板的**凝聚 / 消散**；
   **不做**「任何一块玻璃面的跟手折射光」；**日历那块先放一放**（它经常选的是**一段**
   日子而不是一格，「一段被液体裹住」长什么样得先定，而且它是全 app 每天看得最多的东西，
   值得单独一轮）。
3. **弹窗收敛成一个统一入口**：「把二十来个 `showDialog` 换成我们自己的一个统一入口」——
   为的是把时长与曲线拿到自己手里（现在整段只有 `showDialog` 给的 150ms）。
4. **响铃页那枚**：「不做成圆形了，改成类似液态玻璃滑块的样式。上边加一个箭头，这样就能
   知道是往上滑来关掉闹钟。按住的时候，滑块得变大，跟其他地方差不多。同时，还要有水滴那种
   头大尾轻的变化。同时挂在「液态玻璃」开关后面。它要是挂上去，就得像底栏那样再分一棵树
   出来」。
5. **「长按它放大后应该是大过下面的滑轨吧？你看咱们其他地方的滑块，不都是这样的吗？
   那些滑轨的边缘会被折弯」**。
6. **「如果这个滑轨上面有字，记得这个字是不是也得扭曲效果」**。
7. **原型「还差点意思」的两条**：药丸静止时的**边缘高光**、轨道垫一层**下浓上透的竖向
   渐变**。第三条（越过阈值时彩边闪一下）**明说先不做**。

## 3. 三件事

### 3.1 开关的轨道色（已实施 · `34d7684`）

**现状**：`LiquidTrack.trackTint` 是个 `Color?`，调用点喂的是 `widget.value` —— 而那个值
在 `onTapUp` / `onDragEnd` 才翻。于是**整段拖动颜色一动不动，松手那一刻跳一下**，而滴还在
弹簧上慢慢滑过去，两者根本不同步。

**改法**：`trackTint` 变成 `Color? Function(double progress)`，每帧按**滴的当前位置**重算。
关键是用 `controller.position`（弹簧的当前值）而不是 `page`（逻辑目标）—— 后者在
`release()` / `snapTo()` 里早就被吸附到目标了，读它同样是跳变。

**画法**（用户挑的这一档）：边界从轨道**左缘外面**一路扫到**右缘外面**，只在边界两侧各
半格宽做过渡。

- 过渡带宽度取 `itemW`（一个格宽），与滴的直径同量级；
- `progress = 0.5` 时过渡带中心落在**轨道正中央** —— 而那也是滴滑到一半时的位置
  （两条算式在那一点上天然相等，不是凑的）；
- 用 `ui.Gradient.linear` **两个点两个色**、不列 `stops`：渐变的两端就是过渡带的两端，
  两端之外由 shader 自己钳住（`TileMode.clamp`）。于是不必处理「边界跑到轨道外面」时的
  stop 越界，也不会出现两个 stop 重合时那一列像素的颜色跳变。

**范围**：只作用于液态档。标准档那棵树本来就用 `AnimatedContainer` 做颜色过渡，**一个字
没动**。

**护栏**（`test/glass_switch_liquid_test.dart`，走**光栅化像素**）：拖动中滴左边有色、
右边没有色，**且那一刻值还没有翻**；静止关 = 一点色都没有、静止开 = 左端有色（过渡带确实
扫到了轨道外面）。**反向验证过**：把输入换回 `widget.value`，第一条当场红（左端蓝度 0）。

### 3.2 弹窗：统一入口 + 凝聚 / 消散

**现状**：`lib/` 里 **21 处 `showDialog`**（8 个文件）+ **8 处 `showModalBottomSheet`**
（5 个文件），共 **29 个实心面板**，绝大多数自己写 `barrierColor: Colors.black26`。入场只有
`DialogRoute` 自带的 150ms 淡入 —— 读起来像一张不透明卡片被点亮，而不是一块玻璃凝出来。

**新入口**（放在 `lib/core/widgets/glass_dialog.dart`）：

```dart
Future<T?> showGlassDialog<T>({
  required BuildContext context,
  required WidgetBuilder builder,
});

Future<T?> showGlassSheet<T>({
  required BuildContext context,
  required WidgetBuilder builder,
});
```

- `showGlassDialog` 内部走 `showGeneralDialog` + **一个自定义 `PopupRoute`**：要两条时长
  就得自己写路由 —— `showGeneralDialog` 只收一个 `transitionDuration`，而分开的那条是
  `TransitionRoute.reverseTransitionDuration`。**进场 300ms / 退场 200ms**（具体数值见 §8）。
- barrier 照旧 `Colors.black26`、`barrierDismissible: true`、点击外部关闭的行为与现在
  **逐点一致**。
- **凝聚 / 消散**（`GlassMaterialize`，从 `GlassDialog` 里那份 `_Materialize` 提出来）：
  缩放 `0.92 → 1`、模糊 `σ9 → 0`、不透明度 `0 → 1`；**进场 `easeOutCubic`**（一开始就冲、
  尾巴缓缓落定）、**退场 `easeInCubic`**（先慢慢化开、最后迅速散掉）。只喂一条曲线的
  话，退场会一直保持满尺寸、到最后几帧才「啪」地不见。
- `t >= 1` 时**直接返回原样的子树**：否则每一帧都要为一块 420 宽的面板付一层 `saveLayer`，
  而弹窗是常驻的。

**`GlassDialog` 里那份 `_Materialize` 必须拿掉**：它读的是 `ModalRoute.of(context).animation`，
留着会与新的路由转场**叠成两层**。拿掉之后，还直接用 `GlassDialog` 的地方就没有转场了 ——
所以 21 处必须**全部**迁到新入口（这一条由源码扫描护栏钉住，见 §6）。

> 订正（实施时发现）：最初数的是 `showDialog<`，**21 处里有两处不带泛型**（`showDialog(`），
> 所以真实数是 **21** 不是 19；弹层那边同理 —— 「9」把一行**注释**也数进去了，真实是
> **8 处调用**。两族加起来 **29** 个面板，不是 28。
>
> 还有一条是**独立审查**发现的：上面那句「**全部**自己写 `black26`」也不实 —— 有 **4 处**
> （`shift_template_picker_screen` 的模板管理 / 改名 / 删除、`schedule_editor_screen` 的
> 「存为模板」）**根本没写 `barrierColor`**，走的是 Material 默认的 `Colors.black54`。
> 统一入口把它们归一成 `black26`（与 AGENTS.md 那条「弹窗遮罩统一 black26，不能太暗」
> 一致）—— 但**那是一次行为改动**，这四个弹窗的遮罩比从前淡了一档。

**底部弹层**：`showGlassSheet` 用同一份 `GlassMaterialize`，但**保留 Material 自带的
「从底下升上来」** —— 那是弹层该有的动作，凝聚叠在面板上即可。

### 3.3 响铃页那枚药丸

**几何**（屏幕坐标，全部写死在 `_AlarmRingingScreenState` 的常量里）：

| | 静止 | 按住 |
|---|---|---|
| 药丸 | 52 × 38 | 84 × 44 |
| 轨道 | 72 × 190（矮屏 132） | 同左 |

- **药丸是横着的胶囊**（垂直于运动方向），由半径 `height/2` 的端头圆 + 外公切线构成；
- **按住时左右各鼓 16px** → 84 > 72，**凸出轨道两边各 6px**；
- **上下合计长 6px** → 44。⚠️ 两个量的约定不同：`protrude` 是**每侧**、`liftWidth` 是
  **合计**（见 `LiquidLensMetrics` 的字段说明）。

**整体转 90° —— 这不是取巧，是这一族形状的唯一解。** `LiquidLensShape` 的「沿运动方向
拉长」与「后缘收细（头大尾轻）」**都写死在局部 x 轴上**：底栏与开关的运动本来就是横向的，
所以那两处天然对齐；这枚滴是**竖着走**的，不转的话拉长会长在左右、头大尾轻根本读不出来。
`-π/2` 让局部 +x 指向屏幕**上方**（关闭方向）—— 前缘在上、后缘在下，尾巴拖在下面收细。

转过来之后局部 x = 屏幕的**上下**、局部 y = 屏幕的**左右**，于是：

| 参数 | 在屏幕上是什么 |
|---|---|
| `itemW` | 药丸的**高**（38，按住时长到 44） |
| `capsuleH − 2·pad` | 药丸的**宽**（52） |
| `capsuleH` | **轨道的宽**（72）—— 折边那两条边线就画在它两端 |
| `protrude` | 按住时往**左右**鼓出去多少（16） |
| `liftWidth` | 按住时往**上下**长多少（6） |
| `velocityRef` | 300（这一面一格只有 38px，全局 900 够不着，与开关同一条理由） |
| `rimScale` | 0.7 |

⚠️ **`capsuleH` 必须给轨道的宽、`pad` 必须给 `(72 − 药丸宽) / 2`** —— 折边
（`refractedCapsuleEdge`）的两条边线画在 `capsuleH` 的两端，给错了就折在空气里。
而 `protrude` 要足够大（`protrude > pad`）药丸才真的凸出轨道。

**两条档位两棵树**（与底栏 / 分段器 / 开关同一套写法）：

- **液态档**：`LiquidLens`，主色玻璃 + 光谱环 + 折边 + **静止时的边缘高光**（见下）；
- **标准档**：同一枚药丸、**同样的尺寸**，实心白 + 主色辉光，图标回到它原来那两个颜色
  （白图标压在实心白上会隐身）。
- 判据只在那一个调用点读，位置登记进 `test/liquid_scope_guard_test.dart` 的名单（**5 处
  → 6 处**，自证那条也要一起改）。
- **尺寸两档一起改是有意的**：只改一档会让切档位时控件跳一下（v0.10.10 开关那条规矩）。

**色带接上药丸**：`fillHeight` 从 `p × trackHeight` 改成 `thumbBottom`（= `p × (trackHeight
− thumbH)`）。两者相差 `p × 药丸高` —— 拉到顶时整整差出一整个药丸的高度，中间空一段。
贴住之后两支读成**一个东西：药丸拖着色带走**。

**轨道**：

- **下浓上透的竖直渐变**（白 0.03 → 0.14），替掉原来那层平色（0.08）。190px 里药丸只占
  38，上面八成是空的 —— 平色读起来就是「一根空管子」；
- 补上 `CapsuleRimPainter` —— 底栏 / 分段器 / 开关的轨道都是玻璃，这里此前只有一条描边，
  摆在一起就比它们单薄一档。

**文字**：`上滑关闭` 那行加 `LensWarpedVertical`（新增，与 `LensWarpedCell` **同一份纯函数**
`lensIconWarp`，只把位移落到 dy 上、两个缩放互换 —— 因为「被挤」永远是垂直于运动方向的
那一根）。横向那份的参数全是 x，套不上去。

**静止时的边缘高光**：新增 `LiquidLens.restEdge`（0..1，**默认 0**）。光谱那几层全被
`motion` 关着 ——「静止时一个彩色像素都没有」是 v0.10.7 为底栏定的规矩，而底栏那枚旁边有
图标与胶囊衬着、不缺这一圈。这一枚孤零零挂在深色页面上，关了它就只剩一块平色、读起来像漆。
用**竖直渐变**（白 0.40 → 0.06）而不是等宽纯白：与 `CapsuleRimPainter` 同一套读法，等宽白线
会读成「贴了一圈贴纸」。**0 时那一层连加都不加**，所以既有四处一位都不动。

## 4. 这一轮挖出来的两处地基缺陷（在共享件里，不是响铃页专有）

两处都在 `liquid_lens.dart`，都是**竖直档**（`宽 ≤ 高`）特有的，也都是「折边永远不亮」
的成因。**底栏与分段器走的是横向档，逐字不受影响**（见 §5）。

### 4.1 折边用的半径在竖直档里被钳住 → 折边一次都不会亮

`refractedCapsuleEdge` 用的是 `leftRadius` / `rightRadius`，而那一对是**沿运动方向那一轴**
的半径，在竖直档里被 `_cap = min(高, 宽) / 2` 钳住 —— 那道钳位本来是「两个端头圆不许互相
吞掉」的兜底，代价是**它永远够不到胶囊的边**（`reach = max(rl, rr) − cy` 恒为负）。

**修法**：给 `LiquidLensShape` 加 `leftCrossRadius` / `rightCrossRadius` —— 端头圆在
**横轴**（`capsuleH` 那一轴）上的**实际**半径 = `height / 2`（后缘那份乘 `(1 − 0.35 · stretch)`），
折边改用它。横向档下 `_cap` 恰好就等于 `height / 2`（那一档只在 `宽 > 高` 时走到，于是
`min` 取到的总是高），**所以底栏与分段器的算式逐字相同**。

### 4.2 竖直档里那枚滴是**椭圆**，不是「两个圆 + 外公切线」

`_verticalStretched` 把半径为 `宽 / 2` 的正圆纵向拉开 `h / w` 倍 —— 出来的是一枚椭圆。
而 `refractedCapsuleEdge` 的横向那套算式假定圆心在 `centerX ± (宽/2 − r)`，竖直档里
`r`（= `h / 2`）比 `宽 / 2` 还大，**两个圆心会跑到对方的另一侧**，算出来的 `xL` / `xR`
挤在中间变成一小段弓 —— 画出来是滴正中间一道莫名其妙的短弧，而不是「边被折了」。

**修法**：竖直档走自己的弦长算式 —— 椭圆在边线（`y = 0` / `capsuleH`）上的弦长为
`宽 · √(1 − (2 · cy / 高)²)`，两端对称于中轴。横向档那段一个字不动。

## 5. 验收：底栏与分段器逐像素不变

§4 动的是**共享件**，而底栏那枚滑块有「逐像素不变」的验收。**这一条不能只靠推导**：

1. 在改动前的提交上开一个临时 worktree，渲一遍 `tool/visual` 的全套图当基线；
2. 改完之后重渲，逐张逐像素比（`scripts/diff_visual.py`）；
3. **有任何一张带底栏的图不同就停在那里解决，不往下走。**

推导给的是预期（横向档下 `leftCrossRadius` 与 `leftRadius` 相等、算式同源），基线是证据。
两者都要。

## 7. 风险与代价

- **旋转把浮起阴影也转了**：`LiquidLens` 的阴影是「投在下方」（局部 +y），转 90° 之后变成
  「投在右侧」。深色全屏页面上很轻，但它是真实存在的。要根治得给 `LiquidLens` 加一个
  「阴影方向」参数，本轮**不做**（记在这里，别让它变成下次的「怎么有点怪」）。
- **文字被挤时横向变宽**：「上滑关闭」四个字本来就快顶满轨道宽，互换轴之后它被挤的那一瞬
  会**略微溢出轨道两边**。它那时已经在淡出（`p ≥ 0.625` 就归零），看得出但很轻。要不要
  压上限见 §8。
- **`restEdge` 是栈上的第 4 层**：只在那一个调用点开，且不做每帧重建；但深色全屏页面上
  多一层绘制的代价要**量一次**（不靠估），确认帧时间没有肉眼可见的跳动。
- **统一入口动 29 处调用点**：机械但面积大。泛型与返回值必须逐个对上（不少调用点用了
  `showDialog<bool>` 之类的返回），全靠现有弹窗用例兜。
- **`showDialog` → `showGeneralDialog` 的行为差**：路由类型从 `DialogRoute` 换成
  `PopupRoute`，要确认 `Route.isCurrent` 那套（`dialogCloser` 依赖它）、返回键、点击外部
  关闭这三件事的行为**逐点一致**。`dialogCloser` 的护栏用例照跑。
