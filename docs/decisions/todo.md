- **重复待办的「编辑入口」不许依赖「当前这一次」存在（v0.12.2）**：系列是按规则**到点才生成行**的 —— 每月 1 号的系列在 1 号之前列表里什么都没有。从前唯一能改规则的入口是「点当前那一条待办」，于是这类系列在面板里只弹一句「没有下一次」、**改不了**（2026-10-21 用户真机：「已添加的重复待办，它不能修改，也找不到编辑」）。现在面板点任意一行都开**系列编辑器**（`recurring_series_editor.dart`），它编的是系列本身。保存时：有当前这一次 → 一起更新；**只有规则真的变了才对齐日期**（`occurrenceOnOrBefore`），只改标题 / 时间时不要把用户手工挪过的这一次拽回规则日。**加新的「管理系列」入口时照这条办**：先问「没有当前行时它还能用吗」。
- **待办归档的五条约束（v0.11.3，②③ 在 v0.11.4 有改动）**：① **截断（`pruneArchivedTodos`）只许碰 `isCompleted == true` 的行** —— 按总数截断会先删掉一条「很旧但一直没做」的待办，那是数据丢失不是归档。② **归档里只有「一次性待办」给勾选框**（v0.11.4 放宽；原先是整区都不给）—— 重复待办的**历史行**可能是旧 occurrence，而那个系列**已经走到下一次**了，取消勾选会让一个系列出现两条未完成的行：生成器下一次跑会把旧的**重新标回完成**（`app_repository.dart` 那段「多条未完成是脏数据，留日期最新的那条」，用户看到的是「我明明取消了，它又变回去了」），而在它跑之前，主列表里会挂出一条日期在过去、再也做不完的待办。判据就一条：`archived && e.seriesId != null` 才留空位、其余都画勾。
  **同轮顺手修掉一处既有崩溃**（最终审查报的，它自己判为「不是这一版引入的」—— 确实如此）：`recurring_panel._edit` 原先写的是 `live.single`，系列短时间有两条未完成时当场抛 `StateError`（「Bad state: Too many elements」），点那个系列就崩。它可达的路径与本版无关（把当前那一条勾回来、而生成器还没跑就到得了），但既然「两条未完成」这件事被这一版重新摆上台面，就把它改成 `live.last`（列表先按日期升序排）—— 与生成器那句 `keep = live.last` **一字不差**，两处对「当前那一条」的定义从此一致。用例在 `recurring_panel_test.dart`：⚠️ **那两条未完成必须在页面挂载之后才插** —— `ScheduleScreen` 一挂上就跑生成器，它会自己把脏数据收掉，提前插的话用例是句空话。③ **会话内那个集合（`_sessionRows`）要在 `await` 之前乐观写，而且勾上与取消「两个方向」都写进去**（v0.11.4 改的；原先叫 `_justCompleted`、取消时是 `remove`）—— 勾上那半边是「先划掉再收走」；**取消那半边是「不许跳走」**：那一刻库里记的还是「已完成」，判据 `!isCompleted || 集合里有` 会判成「已完成」，那一条就先离开主列表、等写库回来才回来（用户 2026-10-11 报的「点一下它跳一下」）。用例 `todo_archive_screen_test.dart` 的「取消勾选：那一条整趟都留在主列表里，不许跳走」靠一个**刻意把 `setEventCompleted` 拖慢 200ms** 的仓库把那个窗口撑开 —— 真库太快，窗口可能一帧都不到，不拖慢的话那条断言是句永远为真的空话。④ **`skipRecurringOccurrence` 必须单调**（水位线不倒流）：主列表里被删的永远是最新那一次，所以从前它只会往前走；归档里有更旧的 occurrence，删它会把标记往回写，生成器随后把刚删掉的那条又补出来。⑤ **「下次进来才收走」靠的是 `PageView` 把离屏页 dispose**（v0.10.22 明确决定不做 tab 保活）—— 它**不是任何一处代码显式写的**，`home_shell_nav_test` 里「切走之后待办页会被销毁」那条用例钉着它，谁把保活加回来它就红。
- **重复待办的提醒排的是「下一次」，不是当前那一条的日期；而且带 `seriesId` 的行不在这条链路上排。** 两条都容易写错、且错了都不报错：① 照「拿行的日期算提醒时刻、过去就不排」写的话，**下午打开 App 时今天那次早过去了 → 这条重复待办的提醒永远排不上**（`planRecurringReminders` 从「此刻之后」算第一条，用例在 `recurring_alarm_plan_test.dart`）；② `rescheduleEventReminders` 里那句 `if (e.seriesId != null) continue;` 漏了的话，同一次会**响两声**（行一条、系列一条）。
- **编辑一个重复待办时，绝不能用「当前这一次」的日期改写系列的 `startDate`。** v0.9.14 的代码是 `startDate: date`，后果**按星期几现形**：`occurrenceOnOrBefore` 有一道 `daysBetween(start, 候选) >= 0` 的闸门（它本来是给生成器用的：不许造出起始日之前的行），而「把每周三改成每周五」要回退到**本周之前的那个周五** —— 起点一变成今天，那个周五就早于起点、被判成不合法 → 返回 null → **静默不对齐**。今天若是周三或周四，这条路径整天失灵，其余五天看不出问题 —— `recurring_dialog_test` 因此在 **v0.9.14 是带着一条红用例发出去的**，v0.9.15 跑全套时才撞上。**改回 `startDate: s.startDate` 之后那条例用立刻转绿**（反向验证过：只在周三/周四复现，别的日子两种写法都绿，所以这条护栏的鉴别力是「挑对日子」。）
- **重复待办的规则不落进 Kotlin：Dart 侧算好时刻表，原生只做「弹队首、续队尾」。** `AlarmScheduler.nextPending` 是**唯一**一处「挑第一个还没过的时刻」的实现，两个接收器与开机重排都走它。理由：Kotlin 在这个仓库里**没有可跑的测试目标**，而月末特例（31 号落小月）/ 多选星期几 / 提前提醒的偏移 / 夏令时这些边角照抄一份必然与 Dart 侧对不上 —— 症状还是「某天没响」这种不报错的。队列是 `repeatTimes: LongArray`（未来 180 天、最多 200 条），塞在 Intent extras 里并落进 `AlarmStore` 的两份清单（`Entry` / `Quiet` 都要，否则重启后不再续排）。响铃那条用 **`repeatType = 3`**（「时刻表驱动」）与自定义闹钟的 0/1/2 分开：前者按队首续、后者按 `nextDaily` / `nextWeekly` 重算，两套不能混。护栏是 `recurring_native_guard_test.dart`（扫源码，五条）。
- **生成器只往前顺延、永不回退；所以「改周期」要自己对齐，而「勾掉 / 删掉当前那条」必须写跳过标记。** 三件事是一条链：① `advanceRecurringTodos` 只在行的日期**早于** occurrence 时改它 —— 用户手工把这一次挪到周五之后不许被拽回来；② 代价是「把每周三改成每周五」这条路径**得自己回退对齐**（在 `_EventFields.commit` 里显式 `setEventDate`），别指望生成器，也别把哪一边当 bug 改；③ **勾掉当天那一条时，`setEventCompleted(done: true)` 会顺手把 `skipThrough` 记到系列上** —— 不记的话生成器下次一跑就发现「没有未完成的行、而这次的发生日正好是今天」，于是**立刻补出一条一模一样的**（用户勾完、下次打开 App 它又回来了；与「删掉又回来」是同一个洞）。这一条是**出图时看出来的**（`24_todos_recurring`），不是评审也不是测试抓到的。

- **行挂发生日，提醒按落点（2026-11-09，v0.12.11；撤销 2026-11-05「行跟着提醒走」）**：用户 v0.12.10 反馈「待办时间在班次里，却在班次时间之外显示」。现在行的 `date` = 发生日（班次那天），提醒仍按 `alarmDayAnchor` 落在前一天 / 当天 / 次日；副标题写「班次名 · 次日 02:00」。旧版写在提醒落地日的行由 `migrateLegacyRecurringRowDays` 一次性迁回（prefs 键 `recurringRowDayMigratedV1`，覆盖归档行，手工挪过的不动）。旧水位线不迁移：升级后极少数跨午夜系列可能少出现一次。
- **`skipThrough` 生成器与排提醒都要读（2026-11-09）**：只读生成器的话，勾掉之后排提醒还会把同一时刻排回去（用户报「打勾了到点还响」）。`upcomingFireTimes` 现在跳过 `dayNumber(occ) <= skipThrough`；取消勾选在等值时清水位线，否则撤销后提醒永远不响。冷启动必须走 `rescheduleAll`（`reschedule` 会取消重复待办号段却不排回来）；「以后不再重复」解绑时把行日期改到提醒落地日，保住一次性的绝对时刻。
