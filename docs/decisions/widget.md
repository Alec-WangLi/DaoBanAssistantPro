- **桌面小组件走原生 `RemoteViews`，不是 Flutter 渲染**（v0.8.4 新增）：Dart 侧 `features/widget/widget_snapshot.dart` 产出「已本地化的快照」（**协议 v2**：农历短/全串、周几、月份标题、days/months 双窗口）写进 SharedPreferences（`shift_widget`/`snapshot`），原生 `ShiftWidgetBase` + 三张 provider 只排版 —— 桌面小组件的**用户可见文案**全部来自 Dart 侧快照（`L10n` 产出），双语仍然只有 `l10n.dart` 一处要维护。Kotlin 侧**只有 `AlarmLog` 的日志串**是中文（仓库既有惯例，与本功能无关）；**用户可见**的中文一个字面量都不许出现。
  **三张固定卡（v0.8.8 重做 · 取代 v0.8.6 的五档自适应）**：`WeekStripWidgetProvider` **4×1 本周条**（今天所在那一周的七列：周几 / 日数字 / 班次胶囊）、`TodayCardWidgetProvider` **4×3 今日卡**（照搬 App 底栏信息卡的完整版：日期 + 今天徽章 + 待办徽章 + 完整农历 + 班次行 + 已调班徽章 + 时间 + 其他班组）、`MonthWidgetProvider` **4×5 整月**（月份标题 + 周几行 + 6×7 = 42 格）。**尺寸与内容都在编译期定死、`resizeMode="none"`** —— 一张卡只为它自己的尺寸排版，运行期不再分档；旧的 `WidgetTier` 与五档版式（列表/网格/装配壳七张布局）已**删净**，`onAppWidgetOptionsChanged` 也一并没用了。**换版式会让旧实例失效**：桌面上的老小组件会消失、**必须重新添加**（provider 类名换了，系统认不出旧实例）—— 这点写进了更新日志。
  三张卡的尺寸两头都声明：Android 12+ 认 `targetCellWidth/Height`，12 以下不认，靠 `minWidth = 70n − 30` 的老公式折算（4 列 → 250dp；1 / 3 / 5 行 → 40 / 180 / 320dp）。这份对应关系、三张卡的 manifest 声明、月历 42 格 id 都**没有编译期保护**，由 `app/test/widget_fixed_cards_guard_test.dart` 扫源码守门（它是删掉的五档阈值护栏的等价物）。
  快照窗口是**「−3 ~ +3 个月」的绝对窗口**（v0.9.18 从三个月放宽；整周对齐、最坏 **231 天**，上限 `kWidgetSnapshotMaxDays = 240`；**协议版本仍是 v2**，只改范围不动字段 —— 放宽窗口就是改算式，能翻多远、箭头灰不灰仍由 `monthCovered` 现算）。**装完新版必须打开一次 App**：数据只能由 Dart 算，不打开的话卡片还挂着升级前那一次的渲染字节（`MY_PACKAGE_REPLACED` 到「App 第一次运行」之间没有触发点）—— 这条写进了更新日志与使用帮助，**含窗口里已经过去的天** —— 所以本周条画得出「上周日~本周六」那种跨月的周、月历跨月那一格也不必特殊处理；跨天时原生拿 `LocalDate.now().toEpochDay()` 对表整体右移、不重算，耗尽了退化成占位态。月历**渲染哪个月由 `WidgetRenderer.displayedMonth` 定**（每个实例落盘一份锚点、存该月 1 日的 epochDay，默认今天那个月；**锚点那个月要是画不出就当没设**，见「关键决策与坑」里那条），它的 **42 格是连续 42 天**（从该月 1 日所在周的周一起）—— 月头月尾画的是相邻月份的日期（日数走 muted、胶囊照画），快照没盖到的格才挖空。月份标题从 `snap.months` 按「年-月」查、**查不到就隐藏标题行**，绝不借相邻月份顶上。
  三张卡里只有月历有 42 格 —— **42 格共用一张 `widget_month_cell`、每格一个 `RemoteViews` 实例**，胶囊是**定尺**的 `WidgetChip.tintedChip` 位图，靠 LruCache 按 (颜色, 尺寸) 复用，同尺寸 + 同色共一张、42 格实际只画得出屈指可数的几张；**别按格子改尺寸或按格子造唯一颜色**，那会把这套复用打掉（Task 1 的探针结论）。**胶囊一律走 14% 淡染 + 45% 描边**（与 App 日历格同一套配方，spec §4.1），文字因此走中性 `wg_ink_*`（淡染底混合后≈卡片底，必然过 AA；`onSolid` 那套黑/白字在淡染底上是错的）。**没班次那格 / 那一列整个不画胶囊**（与 App 日历格一致）—— 不能拿 `wg_empty_*` 顶：`WidgetChip.tintedChip` 里 `Paint.setAlpha` 会**覆盖**颜色字节自带的 alpha（fill 写死 36、stroke 写死 115），`#14000000` 会变成一条 45% 的黑描边环。
  两条「长在 App 里、搬到桌面上就错」的配方：**月历的格子不带白卡**（App 里每格是白卡，那是垫在 #F5F6FA 中性底上的；桌面上卡底 96% 不透明、42 张叠起来会糊成一片，分区改靠间距与明度，spec §4.2）；**「今天」只走主色、不许加粗**（`TextView` 没有 `setTypeface(int)` 重载，`setInt(id, "setTypeface", …)` 会在宿主进程抛 `ActionException`）。今日卡跨天**降级**而不是硬撑：`todayCard` 里的农历 / 待办数 / 其他班组是**生成那天**的，跨天刷新时原生只能对表右移、重算不了，故 `todayCard.day != 今天` 就把这三样留空、只显示 `days[todayIndex]` 里按日期烘焙的日期 / 班次 / 时间 —— **绝不把旧数据当成今天显示**。
  刷新粒度＝跨天 + 班次边界，不逐分钟（三张卡共用同一个 `WidgetRefreshScheduler` 精确闹钟；`ShiftWidgetBase.onDeleted` 判「三张卡一个实例都不剩」才取消它）。另：小米/HyperOS 上标准 Android 小组件不进原生那一栏，藏在「支持小部件的应用」→「安卓小部件」二级分类里（README / 更新日志都写了怎么找）；小米桌面会**按资源 id 缓存 drawable**，**改了小组件的资源色之后验证前必须先重启桌面**（`am force-stop com.miui.home`），否则会误判成「改没生效」。**另一条实测过的平台边界（v0.8.8）**：小米这套启动器**不认 `previewLayout`** —— 只有它时 picker 里三条缩略图全显示应用图标。三张卡的缩略图因此改走 `previewImage`（矢量图、无文字、只有形状与色块），加完就显示了；`previewLayout` 保留着（别的启动器可能认）。**改缩略图时两个都得管**。
- **给 `MainActivity` 造 `getActivity` 的 PendingIntent，requestCode 要从下面的占用清单里避开。** 这个池目前已占：班次闹钟 0..600、自定义闹钟 10000..11000、待办提醒 20000..21000、`AlarmRingService` 的 0/1、闹钟自检测试 99998/99999，以及**小组件自己在 100000 起的那一段**（`WidgetRenderer.WIDGET_REQ_BASE`，基数 **64**：`Root(n) = B + 64n`、`Cell(m, c) = B + 64m + 1 + c`；`widgetId` 一直涨到约 **3350 万**才 `Int` 溢出）。这段的结构性错开**靠的是偏移、不是整除**：格子偏移 `1 + c` 恒 `< 64`（月历最多 42 格 ≤ 63），所以 `Cell − Root` 恒不为 0、永远撞不上任何实例的 `Root`。**别把它记成「`Cell` 永不为 64 的倍数」——那在绝对值上是错的**（`B = 100_000 ≡ 32 (mod 64)`，`Cell(w, 31) = 100_032 = 64 × 1563`）。**往后再往这个池里加东西，先看这条。** `Intent.filterEquals` **不比 extras 也不比 flags**，所以这个池里只要 requestCode 撞上，两个毫不相干的点击就会共用一枚 PendingIntent、配 `FLAG_UPDATE_CURRENT` 互相抹掉对方的 extras —— 症状是「小组件点错天」或「闹钟通知点开的响铃界面失效」，都不报错。**小组件翻月另占广播池的 `900_000` 起、步长 4**（`BASE + widgetId * 4 + dir`，dir 0=上月 / 1=下月 / 2=回今天）—— 它与上面这一整池（活动池）互不相干，但同样**逐实例逐方向唯一**：`filterEquals` 不比 extras，撞号会让两张卡共用一个箭头（点这张、那张翻页）。基数与展开形式由 `widget_fixed_cards_guard_test.dart` 钉住。注意目标是**别的组件**的 `getBroadcast`（`AlarmReceiver` / `WidgetRefreshReceiver` / `ScheduledNotificationReceiver`）不在这个池里，它们的 requestCode 与这里无关 —— 评审时就有人拿 `ScheduledNotificationReceiver` 的循环来对撞，那是**广播池**，与活动池互不相干。这条只差 1 的余量（既有最高 99999）是复核时算出来的，所以写下来，别让它再被踩。
- **桌面小组件的「今天」是**半透明**玻璃块（2026-10-15 反转了 v0.11.9 那条「做成实心、别再改回去」）。** 当年做诚实的理由是「桌面没有实时背景模糊，半透明块压在**任意壁纸**上会消失」——**那条推理的前提是面板底半透明**，而**同一轮**已经把月历的面板底换成了**不透明**的页面色（`widget_page_*`，那层不透明是**为了让周几行过 AA** 才定的）、格子换回了**白卡**。于是今天那格现在是「不透明页面底 → 白卡 → 主色块」，与 App 里（`#F5F6FA` 页面 → 白 92% 卡 → 主色块）**结构同构**。另一条独立理由也不成立：**App 那枚块自己不带模糊**（液态档就是 `LiquidLens` 的 `fill: [accent 22%, accent 10%]` + 一圈描边，标准档是 14% 淡染 + 2px 主色描边），模糊在页面背景那一层。所以 `WidgetChip.glassBlock`（主色 22%→10% 对角渐变 + 2dp 实心主色描边）是**照抄**，不是打折。用户 2026-10-15：「尤其是那个半透明块，如果你能实现的话，那基本上就很好了」。
  - ⚠️ **`glassBlock` 是新开的一支，别拿它替换 `WidgetChip.block`** —— `block` 三处共用（月历「今天」/ 周条的「今天」列 / 今日卡的「今天」药丸），后两处必须保持**实心**：药丸是**白字压主色**，半透明会让白字在浅主色上读不出来。
  - 那格的字因此**回到中性色**、不再走 `onSolidInk`（那是给实心块的）；**顺带把「今天且是法定节假日」的红字还了回来**（以前为了压在实心块上读得出来被整段吃掉）。那格的胶囊也回到普通淡染配方（「淡染压在实心块上会糊」那条理由没了）。护栏在 `widget_cell_block_guard_test.dart`（一条断言 monthCard 里**不许**出现 `onSolidInk`，一条算出五种主色下 `ink` 过 AA 而白字都过不了）。
- **桌面小组件的字号**脱离系统字号，改按真实尺寸缩放**（2026-10-15）。** 用户报的：「系统字号调到 200% 时桌面那张卡还会跟着变大」——真机实测比「变大」更糟：今日卡的时间行被**切掉**、「其他班组」整行不见、周条七列的「周四/周五」挤成一团。根因是**卡片尺寸编译期定死（`resizeMode="none"`）而字号写 `sp`**：尺寸不动、字在长，装不下就切。两件事一起做：① 9 张会渲染真数据的布局（`widget_preview_*` 是静态缩略图，豁免）全部 `sp` → **`dp`**，渲染侧一律 `setTextViewTextSize(..., COMPLEX_UNIT_DIP, …)`（`SP` 会乘 `fontScale`）；② 按**真实尺寸**算一个系数再设回去 —— 月历格用行槽高、今日卡用卡内可用高，基准与算式取 App 那一份（`cellDateSm` 13 / `cellShift` 12 / `tinyLabel` 11，`_cellDesignH` 55）。护栏 `widget_font_scale_guard_test.dart`（扫源码 + 两条自证）。
- **桌面小组件的班次胶囊：宽度按简称**现量**，不是定值比例（v0.11.24）**。判据是「胶囊宽 ≤ 格宽 × ~82%」（与 App 同一量级 —— 它那边走 `_shiftChip`：`spaceXs` 包着 `FittedBox(Text(cellShift))`，所以「白」窄、「大休」宽）。v0.11.23 那版把胶囊改成**跟着格子等比缩放**、宽度却仍是**写死的 40dp 基准**，格子一小它就顶满：真机量到占格宽 **95.5%**（左右各只剩 1dp），App 里只有 **81%**。改法是加 `chipWidthPx(context, abbr, textSizeDp)`：用 `Paint.measureText` 在**我们自己的进程**里按真 Android 字体现量 + 两侧各 4dp —— 既绕开「`RemoteViews` 在宿主进程渲染、量不到文字宽」，又绕开「改容器尺寸要 `setViewLayoutWidth` = API 31」（本仓 minSdk 26）。两处布局里胶囊那两层**角色对调**：TextView 当宽度驱动者（`wrap_content` + `layout_gravity="center"` + `paddingHorizontal="4dp"`，三个属性缺一不可），ImageView 改 `match_parent` 贴上去。**⚠️ 验收口径：拿「两字简称」当上界量** —— `shortLabel` 上限 2 字，单字简称天然只有约 50% 宽，拿它量会误判通过、漏掉真正逼近间隙的那一档（与 `_monthRow` 那条「拿最长的那一档量」同一条规矩）。
  - ⚠️ **量出来的两个坑**：`AppWidgetOptions.OPTION_APPWIDGET_MIN_HEIGHT` 给的是**格子**尺寸（266dp），比真正画出来的卡（256dp）大一档；「内容墨迹高度」也**不能**当设计高度用（它含了上下 44dp 内边距，而且不含行盒行距）。
  - ⚠️ **今日卡的缩放只缩不放（`maxScale = 1.0`）**：自然内容高 148dp、可用 212dp，顶到 1.25 时**行距（16/14/8dp）与徽章盒（24dp）不跟着缩放**，字一放大农历就折成两行、整体高过可用高 —— 真机出图时「本月统计」被**整行切掉**。外壳定尺寸、没有滚动，溢出就是静默丢内容。想真正填满得改卡片尺寸（4×2）或再补内容，两件都不在这一轮。
  - 月历胶囊的尺寸改由**位图驱动**（外面两层 `wrap_content`、带 drawable 的 ImageView 按位图固有尺寸量），布局里那个写死的 40×18dp 拿掉 —— 字按格子放大之后它会溢出来。
- **桌面小组件里「会变的颜色」烤位图，「不会变的颜色」用静态 `<shape>`**（v0.11.9）。位图一律被宿主 `fitXY` 拉伸 —— 圆角会随宽高比变成椭圆，所以**只有颜色由用户决定的那些**（今天那块块用主色、实心胶囊用班次色）才烤位图，而且尺寸要从 `AppWidgetOptions` 现算；格子卡底、面板底这些颜色固定的走矢量图，圆角天然不失真。
- **实心块上的字一律走 `onSolidInk` = 比较两个对比度取更大**（与 App 的 `AppTokens.onSolid` 逐字同一条判据），**不是**拿相对亮度卡一个阈值。v0.11.9 第一版写成「亮度 > 0.55 取黑」，而 **teal 的亮度是 0.549**（刚好压在阈值下面）→ 配了白字 → **2.63:1**，而「用户自己用的就是 teal」这句话就在本文件上面。**这个错是静默的**：默认那颗蓝选出来是对的，只有换到 teal / 橙 / 粉才现形 —— 所以真机验收矩阵里必须带上**最坏的那两颗主色**。两个候选还必须是**纯白与纯黑**：那条「恒 ≥ 4.58」的保证是按两个极值推的，换成近黑（第一版是 `#111818`）最坏一档只剩约 4.1。
- **桌面小组件：往容器里 `addView` 之前必须先 `removeAllViews`**（每一个容器、每一次渲染，包括 `continue` 逃掉的那几支）。** `RemoteViews.addView` 的官方文档写的就是这条：宿主可能**回收**布局，要用 `removeAllViews(int)` 清掉已有的子视图。漏掉的症状是「内容一变就重影」（2026-09-29 几个 OPPO / vivo 用户反馈：按天把前夜改成休班之后，桌面上旧日期旧班次压在新内容上）：宿主收到**同一个布局 id** 的 RemoteViews 时走 `reapply`，把动作串在**已在的那棵视图树**上重放，而 `AppWidgetHostView` 不会清空子视图；格子根是 `match_parent`，后加的不把先加的挤开，而是叠在同一块面积上。**内容一样时只是「稍微糊一点」，没人看得出来** —— 只有某格内容变了旧层才现形，这也是它被当成新 bug 的原因。`WidgetRenderer.kt` 里四处（周条 7 格、月历 42 格、其他班组色块、今日卡整棵子树）都要清，前两处放在**循环开头**而非紧贴 `addView`。**为什么只有部分机型中招**：新 AOSP / 启动器会回收已加进去的子视图（`canRecycleView`，Android 12 起进 CTS），刚好把缺陷盖住 —— **「我这台上没问题」不能当成这条不存在，它取决于宿主**。护栏是 `widget_fixed_cards_guard_test.dart` 的「每处 `addView` 的容器都先被 `removeAllViews` 清过」（扫源码，这套路与那 42 个槽位 id、`widget_layout_whitelist_test.dart` 同一份家法）。**别为消掉它的红而放宽正则。**
- **改小组件的**外层布局**（padding / 结构 / 层级）之后，验证前必须让宿主重新 inflate —— 光重推一遍 RemoteViews 不够**（2026-10-16 踩的，与上一条同源）。宿主收到**同一个布局 id** 的 RemoteViews 时走 `reapply`，把动作串在**已在的那棵视图树**上重放，**从不重新 inflate 布局本身**。所以根布局（`widget_week_strip.xml` / `widget_month_card.xml` / `widget_today_card.xml`）的 padding、子视图增删、层级顺序**在桌面上不会自己出现**，要 `adb shell am force-stop com.miui.home`（或把卡片删掉重加）才看得到。**「每格那分子 RemoteViews」不受这条影响** —— 渲染侧每次都 `removeAllViews` + `addView`，子布局是重新 inflate 的；于是同一次改动里 `widget_strip_cell.xml` 的外边距立刻生效、而 `widget_week_strip.xml` 的内边距纹丝不动，**两者的差就是这一条**。当时为此白跑一轮，还顺着错误的现场下了两个错结论（先怀疑 aapt2 把 `paddingVertical` 丢了，改了写法又加了一条理由写错的护栏注释）。**判据**：`aapt2 dump resources <apk> | grep -A1 'layout/widget_week_strip'` 拿到混淆后的文件名，再 `aapt2 dump xmltree --file <那个文件> <apk>`，直接看**编进 APK 的**属性 —— 真机上没变化时先走这一步，**别急着改代码**。

## 原文留档 · v0.11.25：`RemoteViews` 外层布局只 inflate 一次

> 一句话：改完 `widget_*.xml` 的 padding / 结构 / 层级，**重推快照是没用的** —— 宿主只在建立视图时 inflate 一次外层布局，之后每次更新只是把动作串在已有视图树上 `reapply`。要么 `am force-stop com.miui.home`，要么把卡片删掉重加。子 RemoteViews 因为每次都 `removeAllViews` + `addView`，才会重新 inflate。

## 原文留档 · v0.11.26：`FrameLayout` 会把 `match_parent` 解析成固定高度

> 一句话：要「竖条通高」必须是**横向 LinearLayout**（它会二次测量 `match_parent` 子层）。`FrameLayout.onMeasure` 对每个子层只量一次，`match_parent` 高度按位图自己解析成**固定 200dp**，与内容脱钩、还把卡片撑高。
