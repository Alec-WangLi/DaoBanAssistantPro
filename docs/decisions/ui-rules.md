- **「实心主色底 + 白字」现在是一条「按需压深」的规则，不是凭感觉挑深色**（2026-10-15 收口，v0.11.22）。原状：五种主色下白字对比度 = primary 5.26 ✓ / sky 4.74 ✓ / **teal 2.63 ✗ / orange 2.55 ✗ / rose 4.09 ✗**，而用户用的就是 teal。**两条弯路都记在这儿，别再走**：**① 旧填充是半透明的**（0.85 → 0.50），压在白卡上连 primary 的渐变尽头都只有 **2.1:1** —— 也就是说「白字压实心主色」在浅色下**五种主色全不达标**，不只是那三颗；**② 第一版修法是一律「明度 × 0.62」**（v0.11.21），不问原来多深都再砍四成，于是本来就够的 primary 被砍成 **11.35:1** —— 浅色档下那块面看着就是一块黑（用户真机：「太暗了」「胶囊的颜色之前浅一点挺好看的」）。
  **现在的规则在 `AppTokens.solidAccent`：本来就过 AA 的**原样返回**，不够的压到「**刚好过线**」就停** —— 判据按**真正画出来的那一层**算（渐变最浅的 0.92 端压在**白底**上，线取 4.52 = AA 4.5 + 8 位取整余量）。默认蓝 / 天蓝因此**一个像素都没动**，只有 teal / orange 被压。
  **配套的一半同样要紧：压深的面上的字一律显式写白。** 跟着**主题深浅**取字色是错的 —— 浅色档会给近黑，而那块底**两档是同一个颜色**。已知的两处：底栏走 `AppTokens.navForeground(accent)`（判据是「压在哪块底上」，**签名里已经没有 `isDark`**）、分段器由 `GlassSegment` 给选中格一层白 `DefaultTextStyle` 一处收口（调用点自己显式给了颜色的，以调用点为准 —— 编辑器「工作 / 休息」那处就得自己写白）。
  **护栏三条**（都反向验证过）：`design_tokens_test` 的「**刚好够**」（本来就够的必须原样返回；压过的**再亮 2% 就不许过**）+「导航选中项的字压在真正的底上过 AA」、`glass_segment_ink_test.dart`（渲真分段器，读**解析出来**的字色）。⚠️ **顺带作废一条假的绿**：原来那条「胶囊滑块上的字色」把滑块模拟成 `Color.lerp(bg, accent, 0.6)` 的**半透明**面 —— 判据跟着一个过时的材质走，v0.11.21 换材质时它照样绿。**教训：对比度判据里的「底」必须与真正画出来的那一层同源。**

- **弹窗里的异步动作，`pop()` 之前必须确认自己这层还是最上层 —— 用 `glass_dialog.dart` 的 `dialogCloser(context)`，别直接 `Navigator.pop`**：保存类动作是异步的（写库 + 重排提醒要过原生通道），这段窗口里按钮照旧能点 —— 点两次「保存」、或点完「保存」立刻点「取消」/点遮罩，每条路径都会 `pop()` 一次，**第二次 pop 关掉的不是弹窗，而是 App 唯一剩下的那层路由**：Navigator 一条路由不剩 = 整屏纯黑，release 包剥掉断言所以既不报错也不崩，看着就是「屏幕黑了但 App 还活着」（v0.9.0 用户反馈的「添加待办事项，快速点击添加的时候，APP 直接全部黑屏，但是没有卡死」，2026-09-21 真机复现 + 单测复现）。两道护栏分工不同、缺一不可：`GlassActionButton` 上的锁（回调返回 `Future` 时，本次动作跑完前不再响应点击）挡**同一颗按钮被连点**，顺带挡掉重复入库（连点两次从前会插两条待办/两条闹钟）；`dialogCloser` 挡**两条不同路径各 pop 一次**——只上按钮锁挡不住这条，两次点击落在两颗不同按钮上。回归测试在 `todo_dialog_test.dart`（两条路径各一条用例，都反向验证过：把 `lib/` 的改动 stash 掉立刻变红）。**判据 `Route.isCurrent` 的 SDK 语义是这件事的关键**：路由一旦被 `pop()` 就进入 `popping`，而 `popping` 在 `_RouteLifecycle` 里排在 `remove` **之后** —— 即它不再算 `isPresent`，所以第二次 `pop()` 的 `lastWhere(isPresentPredicate)` 会落到下面那层（主界面就是这么被弹掉的）。
  **另一种写法同样致命、且更隐蔽**（v0.9.14 栽的）：`onPressed: () => dialogCloser(ctx)` —— `dialogCloser` 是**返回闭包**的，套一层箭头函数等于把闭包造出来又扔掉，谁也没调。Dart 允许「返回函数的函数」赋给 `void Function()`（`void` 是顶类型），所以它**编译得过、不报错、也不关窗**，真机上就是「点了取消，弹层纹丝不动」（2026-09-30 用户反馈：时段弹层与其余时间选择层两处）。规训：`dialogCloser` 只有两种合法写法 —— `onPressed: dialogCloser(ctx)`，以及 `await` 之后自己 `()` 一下；**永远不要在外面再包一层箭头函数**。`schedule_timeline_test.dart` 里两条「点取消必须关窗」的用例钉着它。
- **触觉挂动作、不挂按压（`core/haptics.dart`，v0.8.2）**：词汇表**只有三档语义** —— `Haptics.select()`（选中变了：开关翻转 / 胶囊段切换 / 选项胶囊选中 / 选择器提交 / 日历滑块换格 / 长按拖选每进一格）、`Haptics.commit()`（动作落实、这一步不可逆：删除清空类确认 / 应用改班与恢复轮转 / 切换排班方案）、`Haptics.modeEnter()`（进入一个模式：长按进入日历多选态）。**普通点击、列表行点击与滚动一律不震**；选择器滚轮是唯一的例外 ——**吸附到新的一格震一记 `select`**（v0.13.8 改口径，见本条末尾） —— `GlassPressable`（统一按压反馈）故意不挂：它包的是*每一次*按压，包括普通点击。理由写在 `haptics.dart` 顶上：震动一旦成为背景噪音，信息量就归零，用户会把系统触觉整个关掉，那时你想用震动区分的那件事也一起没了。开关是「我的 → 外观」那一个（默认开），走模块级 `hapticsDisabled`（与 `liquidGlassEnabled` 同一条路：一处赋值全 app 生效，调用点不必各自查设置）；调用是 fire-and-forget，不 await、异常吞掉。**除 `core/haptics.dart` 外，任何文件不许出现 `HapticFeedback.`** —— `test/haptics_guard_test.dart` 扫 `lib/` 强制（在剥过注释/字符串的副本上扫，免得注释里提一句就打红）；绕过的那一行**不会**受用户开关控制。
  **同一条里最要命、且已经真犯过一次的子规则：共享组件已经自动震过的控件，绝不能再在调用点补一次触觉** —— 那就是「一次操作震两下」，两下比一下**信息量更少**。那份名单：`GlassSwitch` / `GlassSegment`（只在选中项**真的变了**时才发）/ `GlassChoiceChip` / 四个选择器提交点（时间、日期、月份、选项 —— **「取消」与该选择器内部的滚轮不在此列**：滚轮自己会震，调用点再补就是一下两记）。待办勾选正是这么被裁掉的：勾选载体是 `GlassSwitch`，它自己已发 `select()`，所以 `schedule_screen.dart` 那处 `commit()` **有意不加**（spec §4.2 的「一条自我纠正」有完整推导；§4.1 覆盖过的控件不再进 §4.2 的表）。**加任何一处触觉之前，先确认它不在那份名单里。** **v0.13.8 改口径：选择器滚轮从「一律不震」改成「换格一记 `select`」。** 当年禁的是把触觉挂到滚动**过程**上（每帧一次，拨一下连震十几下）；`onSelectedItemChanged` 只在**选中项真的变了**时回调一次，正是 iOS 时间轮盘那种「哒、哒、哒」。时/分轮盘与年月选择器的年份轮盘都走这一条，用例在 `haptics_shared_widgets_test.dart` 的「时间选择器：每换一格震一次」——它钉的是**格数与次数相等**，不是「有震就行」。
- **触觉的波形交给设备自己挑（v0.13.7 立，2026-11-10 实测）**：`Haptics.select/commit/modeEnter` 的主路径改走 `com.daoban.shiftassistantpro/haptics` → `android/.../Haptics.kt`，由原生侧点播**预定义效果** —— `select` 用 `EFFECT_CLICK`，`commit` / `modeEnter` 用 `EFFECT_HEAVY_CLICK`（API 34+ 带 `USAGE_TOUCH`；系统「触摸时振动」关掉时不发，因为直接调 `Vibrator` 绕过了 `performHapticFeedback` 自带的那道闸门）。**为什么**：Flutter 的 `selectionClick` 落到 `CLOCK_TICK`，AOSP 请求 `EFFECT_TEXTURE_TICK`，这台小米机（25102RKBEC，HyperOS）的 HAL 不支持，于是回退成 `EFFECT_TICK`（一次 70ms）—— `dumpsys vibrator_manager` 的 Recent vibrations 里逐条写着 `original: Prebaked=TEXTURE_TICK` / `played: Prebaked=TICK`，手感就是「转子嗡嗡」；同一份记录里 MIUI 桌面按图标是 `Prebaked=CLICK`、输入法按键是 `Prebaked=THUD`，都是 HAL 按机型调过的短波形。**别再改回去**：`HapticFeedback.*` 现在是**回落链**（只给非 Android / 原生通道缺席用），不是主路径；`Haptics.kt` 的三档字符串与 Dart 侧 `_HapticLevel` 是契约，由 `test/haptics_native_channel_test.dart` 钉住。**边界**：波形与映射在这台机上核过（Recent vibrations 记录），档位手感只在这一台机器上试过，换机型（尤其 ERM 马达）没有样本。
- **「能改 / 能点」只许用三种视觉语言（v0.12.4 立）**：**有框的输入框 = 直接打字**；**铅笔 = 点开进入「编辑这条内容」的表单**（待办、自定义闹钟、我的模板、系列）；**箭头 = 点开打开别的东西**（选择器 / 页面 / 说明或动作弹窗）。判定只看「点开之后是什么」：进编辑表单 → 铅笔；打开别处 → 箭头；只做展示 → 什么都不加。**箭头尺寸随行高**：页面级 `ListTile`（48dp 以上）沿用默认 24，密集行与手写值行用 `iconSm`(16) + `inkMuted` —— 这两档在仓库里本来就并存，**别为「统一」把 24 归一成 16**。动词文案 + leading 图标的动作行（添加时段 / 恢复轮转 / 从文件中选择…）读起来就是按钮，不加箭头。**六处例外**：重复待办面板（用户 v0.12.3 明确去掉铅笔）、取色圆点（24dp 上叠图标会盖住颜色）、日历长按拖选（手势入口）、年月胶囊（实测 360dp 标准档只剩 **19.59dp** 余量，而 16dp 箭头 + 4dp 间距要 **20dp**，会把一行顶栏翻成两行）、排班管理里的方案行（用户 2026-11-09 明确去掉 `scheme-open-hint`）、编辑排班的值行（同轮去掉 `crew-*-chevron` / `my-cycle-start-chevron` / `monthly-day-chevron`；整行仍可点，只是不画箭头）。值行一律用 `core/widgets/glass_value_row.dart` 的 `GlassValueRow`（从管理页私有实现抽出来的纯搬运）：**别再为「标签 + 值 + 箭头」手写 `ListTile + trailing`** —— 窄窗里 `ListTile.trailing` 会吃掉整行宽度并抛 `Trailing widget consumes the entire tile width`（v0.9.14 / v0.9.18 两次踩过）。班组名能改却没人发现，根因是它**长得不像输入框**（裸 `TextField` + `InputBorder.none`），不是改不了 —— 新写「看起来只读、其实能改」的入口时，先按这条规则给它一种视觉语言。
- **新界面一律补进视觉工装的屏单（`app/tool/visual/visual_screens.dart`）**：加了新页面 / 新弹层 / 新的特殊状态，就往那份屏单里加一条（弹层是命令式的、没有可渲染 widget，得包一层薄壳把它弹出来 —— 见 `_OverridePickerHost` 的写法），再按 `app/tool/visual/` 出图看图。**这条是因为教训：v0.8.1 的四处在设计语言上跑偏（信息卡「已调整」写成裸文字而非胶囊、信息卡按压还留着 Material 水波纹、长按范围底色 18%、圆点尺寸没写明理由），过了三道评审 + 一次通过的令牌守门都没拦住 —— 根因就是那几处新界面从没进过屏单，没有人真正「看过」**。令牌守门只扫字面量，看不出「一颗裸文字徽章」和「一个胶囊」的差别；屏单是唯一会「看」的眼睛。**展开态也算特殊状态**：`67_editor_crew_expanded` 就是班组设置的展开态，而 `text_fit_guard_test` 是直接渲染屏单、没有交互钩子 —— 所以给了 `ScheduleEditorScreen` 一个 `@visibleForTesting initialCrewExpanded`，让护栏真的渲染它；只把屏放进屏单、却让护栏渲染成收起态，等于没验。
- **班次颜色的盘与它要过的那条线（v0.11.6）**：`core/shift_palette.dart` 的 `kShiftPalette` 是**唯一一处**盘（16 颗），`kShiftColorBar` 是那条线。判据是「**描边**对卡底的对比度」—— 班次色在日历格子与桌面小组件上走的都是「14% 淡染 + 45% 描边 + 中性字」，而 14% 的淡染本来就贴着卡底（实测落在 1.11~1.28），**可读性全压在那道描边上**。
  - **四处卡底**：App 浅 `#FFFFFF` / App 深 `#16161E` / 小组件浅 `#F5F5F5`（`wg_card_to_light` 96% 白压**纯黑壁纸**，它最暗的一档）/ 小组件深 `#24242B`（`wg_card_to_dark` 94% 压**纯白壁纸**，它最亮的一档）。**桌面那两处必须算**（用户 2026-10-11 拍板护栏要覆盖它）—— 小组件的卡是半透明压在**任意壁纸**上的。
  - **门槛 = 现有八个在四处卡底上的下界（1.35018838）**，常量取 `1.3501`（落在下界下面一点，这样定线的那颗自己也过线）。⚠️ **这个数有两个作废的前身**：**1.39472**（只算了 App 两处卡底）、**1.34906**（拿浮点混合算的）。**权威值是「实现算出来的那个」** —— `compoundOver` 每个通道取整到 8 位，与设备真正画出来的一致；文档给方法，用例钉数（`shift_palette_test.dart` 里有 `closeTo(1.350188, 0.00001)`）。
  - **加新色先跑 `shift_palette_test.dart`**：它逐颗 × 四处算一遍，任一低于门槛就红。**往盘里塞浅色一定红** —— 正黄 `#FFCC00` 在白卡上只有 1.22，所以「黄」那一档只能是琥珀 / 暗金 / 橄榄那种**暗黄**；同理太暗的（深紫 / 靛 / 深棕）在小组件深色卡上过不了。
  - **自定义色一律不透明**（十六进制只收 6 位 / 3 位，**八位判非法**）。两条理由都是硬约束：桌面小组件 `WidgetChip.tintedChip` 的 `Paint.setAlpha` 会**覆盖**颜色自带的 alpha 字节（低透明度会渲成一道实心环）；`widget_snapshot.dart` 用 `color: 0` 当「这天没班」的哨兵。
  - **自定义色不设取值范围、不警告**（用户 2026-10-11 拍板：「选得不好看那是他自己的事」）。配套是取色层里摆两颗**真的**日历小样 —— 不拦你，但也不让你蒙着选。
  - `parseHexColor` 里那句「**先逐字符验十六进制数字**」不能省：`int.tryParse(s, radix: 16)` 会吃下 `+4C8DF` / `-4C8DF` 这种带正负号的六字符串，长度检查拦不住，结果是**一个完全不相干的颜色**。
- **底部弹层里的输入框：给内容夹高度没用，得按 `viewInsets` 把整块面板顶上去**（v0.11.7，独立审查抓的 Critical）。`showGlassSheet` 底下是 SDK 的 `_ModalBottomSheetLayout`，它把面板**钉在屏幕底边**（`getPositionForChild` = `size.height - child.height * animationValue`）—— 那个文件里**一个 `viewInsets` 都没有**。所以「弹层里长出输入框 ⟹ 软键盘盖住贴底那一行（通常是动作行）」这件事**不会自己好**：写 `maxHeight: 屏高 − viewInsets.bottom` 只让面板**变矮**，底边还在屏幕底，动作行照样在键盘下面（真量到：900 高的屏 + 320 键盘，`确定` 底边 **838**、键盘顶边 580 —— 而从「敲进去」到「按确定」正是这个面的主路径，等于整条断掉）。正确写法是 `Padding(padding: EdgeInsets.only(bottom: MediaQuery.viewInsetsOf(context).bottom), child: GlassPanel(...))`；键盘不弹时它是 0 高度，逐像素不变。**全 app 只有 `shift_color_picker.dart` 一个弹层**带输入框（其余三处带 `TextField` 的文件全走 `showGlassDialog`，弹出的是**居中弹窗**；时间 / 日期 / 月份 / 选项那四个件没有输入）—— 下一个往弹层里放 `TextField` 的人照它办。⚠️ **这条在测试里量不出「按不到」**：那儿的键盘只是一条 `viewInsets`、不是命中障碍物，`hitTestOnBinding` 照旧打得中那颗被盖住的按钮 —— 只能断言**几何**（「确定」的 rect 底边 ≤ 屏高 − `viewInsets.bottom`）。
- **可滚动内容的尾部要给悬浮控件让位 —— 用 `core/layout.dart` 的常量，别各写各的数。** `kNavCapsuleInset = 96`（只压着底部导航胶囊）、`kFloatingActionInset = 160`（胶囊 + 悬浮按钮/按钮条）、`kFloatingSaveInset = 92`（**编辑排班页**底部那颗「保存并重排闹钟」胶囊）。前两个数**都是量出来的**：`endFloat` 再上移 76、按钮 56 高，实测 FAB 与闹钟页那条按钮条的顶边**都落在距屏底 148**；96 那一档下最后一颗删除键的最低点在距底 115 → 压住 33px（用户 2026-10-01 的反馈）。第三个同样是量的（按钮条 80 高、顶边距屏底 64，两档视口一致），**但它必须叠系统栏**：那颗胶囊包在 `SafeArea` 里、会跟着手势条上移，所以调用点写 `MediaQuery.paddingOf(context).bottom + kFloatingSaveInset`（测试视口都没有系统栏，这类错只能靠算式堵）。**判断哪些页面需要**：只有「页面底部**且**有悬浮控件压着」的列表要 —— 四个 tab 页里待办（FAB）与闹钟（按钮条）需要，我的页 120 本来就够、日历页的信息卡早已按胶囊算过；**push 出来的整页**里只有编辑排班需要（它底部有那颗胶囊），排班管理 / 模板选择把按钮放在列表末尾、跟着内容滚，不需要。护栏是**几何 + 命中测试**（`recurring_screen_test` / `alarm_screen_test` / `schedule_editor_test` 各一组：滑到底后断言那一行在悬浮控件之上、且它中心真的打得中）—— 「被盖住」这类问题任何纯逻辑断言都照不出来。⚠️ 写这类用例时**夹具的条数必须真的撑破视口**：视口 1200 高时 12 条待办根本滚不动，那种用例是永远为真的空话。
- **「悬浮在正文之上」＝ `extendBody: true` + 那一层自己不画任何底色；`bottomNavigationBar` 只是层序在正文之上，它照样会把正文截断。** 编辑排班页原来就是 `bottomNavigationBar`，正文到它的上沿被**硬切**（探针实测卡片在距屏底 80 处齐刷刷断掉，下面一整片平色），用户读成「单独加了一层蒙板挡住」（2026-10-01 反馈）。修法与首页导航胶囊同一套：`extendBody: true` 让正文铺到屏幕底、从悬浮层下面穿过去，再补底部留白（见上面那条）。**判据是可断言的**：`ListView.bottom == 屏高`（不写 `extendBody` 时是「屏高 − 悬浮层高」）。
- **`GlassDialog` 的动作行必须是 `Align(centerRight)` 套 `Wrap`，两层缺一不可 —— 这是 v0.9.18→v0.9.19 一进一退换来的。** `Wrap` 负责**窄窗不溢出**（`Row` 在 200×400 下三颗按钮横溢 23px）；`Align` 负责**靠右**（`Wrap` 会收缩到内容宽度，而外层 Column 是 `crossAxisAlignment.start` —— 只有 `Wrap` 的话整行会被贴到左边，`WrapAlignment.end` 在「自己就是内容那么宽」时毫无作用）。**一处改错就是全 app 二十来个弹窗一起靠左**（用户 2026-10-01：「怎么好多按钮都跑到左边去了？」）。两条几何用例一起钉着（`test/glass_dialog_test.dart`：正常宽度下最后一颗贴面板内容右缘、窄窗下折行且不越界），**别为了靠右退回 `Row`**。量右缘时记得面板那 **1px 描边**（`panel.right - 1 - 20`）—— 第一版漏了它，差整 1.0，**别靠放宽公差糊过去**。

- **日历页在「系统字号放大」下的两条规则（v0.9.9 定）**：**网格是定尺的点阵，格子里的字一律归一到格子里**（靠 `FittedBox(scaleDown)`，日期 / 班次胶囊 / 农历 / 周标题 / 窄窗退路的纯文字五处都要有）；**真正按系统字号长的是底栏信息卡**（`info_card_metrics.dart` 用 `textScaler` 实测高度，会随字号变高、把网格挤矮）。三处容易再踩的细节：① 整格外面那层 `FittedBox` **救不了**格子里某一行 —— 外层给的约束是固定的 `contentW` 宽，那一行在**固定宽**下排好、`ellipsis` 已经烘进结果，之后再缩也变不回来（「缩小不能取消省略」）；② **不要按系统字号去长高 `_weekdayH`** —— 那个常量同时被 `_buildGrid` 六处命中测试算式用（`d.localPosition.dy - _weekdayH`），改成逐帧算的值漏一处就是「系统字号调大之后点哪一格都不对」，而且换来的高度也换不成更大的字；③ 极长的名字要**先截再缩**，不能只靠缩：`LunarInfo.cellLabel` 把节日名截到 3 字 + 省略号（`全民国防教育日` 7 个字交给 `FittedBox` 会缩到 0.46 倍约 6px —— **完整但没人看得见，比截断更糟**），信息卡仍用完整的 `shortLabel`；信息卡第一行「日期 + 今天 + N 项待办」三个元素都要紧、谁也丢不得，用 `Flexible + FittedBox`（紧凑卡那一支仍走省略号，那边窄到 200dp 缩下去没法看）。

  **中文字体为什么是 Noto**：等线（`Deng.ttf`）是 Windows 自带、不能随仓库分发；Noto Sans CJK 是 SIL OFL，可以。取的是 `NotoSansCJK-Regular.ttc`（19,484,784 B，10 个字面）的第 2 个面 = SC，全字面 16,437,340 B，再子集到 **GB2312 全部 6,763 字 ∪ 仓库里实际用到的 1,514 字 = 6,784 字**，加 `U+0020-007E,U+00A0-00FF,U+2000-206F,U+3000-303F,U+FF00-FFEF`，`--layout-features='*' --no-hinting`。**要重抽（改了文案、出现新字、渲成豆腐块时）**：
  ```bash
  pip install fonttools
  curl -L -o NotoSansCJK-Regular.ttc https://github.com/notofonts/noto-cjk/raw/main/Sans/OTC/NotoSansCJK-Regular.ttc
  python -m fontTools.ttLib.ttCollection  # 确认第 2 个面是 SC（0 JP / 1 KR / 2 SC / 3 TC / 4 HK / 5-9 Mono）
  python - <<'PY'
  import glob, io
  from fontTools.ttLib import TTCollection
  TTCollection('NotoSansCJK-Regular.ttc').fonts[2].save('NotoSansCJKsc-Regular.otf')
  chars = set()
  for pat in ('app/lib/**/*.dart', 'app/test/**/*.dart', 'app/tool/**/*.dart'):
      for p in glob.glob(pat, recursive=True):
          chars |= {c for c in io.open(p, encoding='utf-8', errors='ignore').read()
                    if '\u3000' <= c <= '\u9fff' or '\uff00' <= c <= '\uffef'}
  gb = set()
  for hi in range(0xB0, 0xF8):
      for lo in range(0xA1, 0xFF):
          try: gb.add(bytes([hi, lo]).decode('gb2312'))
          except Exception: pass
  io.open('cover.txt', 'w', encoding='utf-8').write(''.join(sorted(gb | chars)))
  PY
  python -m fontTools.subset NotoSansCJKsc-Regular.otf --text-file=cover.txt \
    --unicodes="U+0020-007E,U+00A0-00FF,U+2000-206F,U+3000-303F,U+FF00-FFEF" \
    --layout-features='*' --no-hinting --output-file=app/test/fonts/NotoSansSC-Regular.otf
  ```
  体积对照（同一份源、同样参数）：全字面 16,437,340 / U+4E00-9FFF 9,224,420 / 仅 GB2312 2,857,128 / 仅仓库字符 620,372 / **采用 2,858,516**。
  **换尺子的代价量过了**：Noto 的行盒比等线高约 1.16×，360×780 特大档的信息卡因此高 2dp、网格可用高度 316 → 314，而 `_weekdayH + 5 × _minCellH = 316` —— 正好多 2dp（探针实测 `maxScrollExtent == 2.0`）。修法不是放宽断言，是 `calendarCellHeight` 加一条 `_cellFitTolerance = 1.0`：**每行差额 ≤1dp 就让格子吃掉，差得更多仍守 `_minCellH` 并走外层滚动兜底**。换字体时用微软雅黑 / 黑体对照跑过（11 条全绿），只有 Noto 会触发 —— 说明这不是布局坏了，是字体的 ascent/descent 本来就不一样。
