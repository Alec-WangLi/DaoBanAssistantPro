> 从 `AGENTS.md` 的「最近改动」原样拆出（2026-11-05），条目 **新→旧**，正文一字未改。
> 完整版本号链（0.1.45 起，含 build 号）见 `version-history.md`；正式版归纳索引见 `releases.md`。

- **v0.8.12**（测试版 · 修「存完模板看不到」）：v0.8.11 上线当天用户反馈「我保存模板后，没看到呀」。真机复现清楚了：**模板一直存进去了** —— 先开过一次「新建排班」（那时还没有模板），之后在编辑器里存下的模板，回选择页看不到，**重启 App 后那几条全在**。根因是那一版把模板列表从 drift 查询流改成一次性读时漏了 `autoDispose`，第一次读到的空结果被缓存了一整个会话。修法：`FutureProvider.autoDispose` + 编辑器存完 `ref.invalidate`，另把存完的提示补成「已存为模板「X」—— 新建排班时可选」（用户存完的第一反应就是去找它）。回归测试「先开过选择页…存完再回来必须看得到」**已反向验证**（去掉 autoDispose 立刻变红）；真机上按同样的流程复现并验证（0.8.11 看不到 / 0.8.12 不重启也立刻出现）。教训写进了「关键决策与坑」那条第③点。

- **v0.8.11**（测试版 · 我的模板）：用户反馈「应该搞个自己输入模板然后其他班组直接套用的，不可能所有情况你都搞成固定模板输进去」。① **「我的模板」**：编辑器右上角「存为模板」把当前这套（**含还没保存的草稿**，取 `_draftSchedule()`）存进新表 `CustomTemplates`（schema 8→9，纯新增一张表），新建排班的选择页多一组「我的模板」排在最前，卡片与内置模板同一套配方（色条 + 标题 + 副标题 + 每天在岗数），分组标题旁的「管理」里可改名 / 删除。② 存储取舍与两个坑见「关键决策与坑」里那条（整块存一列、班组归一化、一次性读而非流）。③ 测试：`schedule_template_test.dart`（纯函数：归一化后**班组分工与原方案同构**、三个可空字段的往返、坏数据不炸）、`migration_v8_to_v9_test.dart`（老排班原样保留 + 新表能写能读）、`saved_template_test.dart`（存 → 出现在选择页 → 用它建方案时入参正确 → 改名 / 删除落到仓库且卡片跟着变）。④ 视觉工装加 `16_template_picker_mine`（`seedMyTemplates`）—— 那一组只在库里有模板时出现，不预置就拍不到。

- **v0.8.10**（测试版 · 五班三倒 10 天一轮 + 班组撞班）：用户反馈「五班三倒没有 10 天一轮的模式；用 5 天一轮改成 10 天的，别的班组会乱，同一天有两个班组上相同的班」。① **加模板** `five_crew_three_shift_10d`（白白中中休夜夜休休休，五班，错位按均分给 0/2/4/6/8）—— 模板库从 19 种变 **20 种**（README / PRODUCT_SPEC / 使用引导 / 酷安稿的计数同步改了；AGENTS 里 v0.6.0 那条历史条目保留 19 不动）。② **撞班检测 + 一键均分**：新增纯函数 `crewClashes`（扫一个完整周期，休息班不算撞、判等走 `identical`）与 `evenTeamOffsets`（均分规则，`keepIndex`/`keepOffset` 保住「我们班组」不动），编辑器「周期设置」卡末尾在检测到撞班时点名相撞的两个班组并给一个动作 —— 挂在那张卡而不是「班组设置」那张，是因为后者默认折叠、提示会跟着藏起来，而撞班的起因就是周期长度。③ 顺手把预览条里那份 `ShiftSchedule` 组装抽成 `_draftSchedule()`，撞班检查与预览共用一份。④ 守门测试：模板逐条反查均分规则 + 每个模板跑一遍撞班检测（模板错位是人手抄的）；`shift_rotation_test.dart` 用用户那套复刻（10 天周期 + 1 天错开 = 12 处撞班 / 9 天）钉住检测结果与均分后的结果；`schedule_editor_test.dart` 钉住提示出现 / 一键均分后消失 / 我组起始日不动。⑤ 视觉工装加 `15_editor_crew_clash`（`makeCrewClashCurrent` 把种子库换成撞班状态）—— 提示只在这个状态下画得出来。

- **v0.8.9**（测试版 · 零点班联动闹钟排错一天）：用户反馈问「夜班 24 点上班、设 23:00 的闹钟，是当天还是前一天？没看到有这个选项」—— 查下来是**真 bug**。`planShiftAlarms` 的算式是「班次那天 00:00 + 响铃分钟数」，于是 00:00 上班的夜班配 23:00 响铃被排到**班次当天** 23:00，那一刻这个班已经结束 15 小时；而内置 8 / 6 小时制模板的夜班恰恰就是这一档（`_n8` / `_n6` 都是 0:00 上班、23:00 响铃）—— 模板本身是照「上班前 1 小时」写的，只有这一条被算式算歪。原版 App 有这个开关（`isearly` = 提前一天，界面标 `(提前一天)`，见 `domain-logic-extract.md`），重写时没搬过来。修法是**规则**而不是开关（用户拍板不加开关）：`ShiftClass.alarmPreviousDay`（响铃钟点晚于上班钟点 → 那个钟点只可能是前一天晚上）+ `shiftAlarmFireAt` 顶层纯函数；上班时间没填时判不了，按当天。（加多闹钟那轮这个 getter 换成了 `alarmFallsOnPreviousDay(shift, alarm)`，并补上「钟点落在值班窗口内 → 当天」那一档，见「关键决策与坑」。）三处显示同步标「前一天」—— 班次编辑的钟点块（写成「前一天 23:00」）与它下面那行说明、闹钟列表行、日历信息卡的 `_alarmText`；`offset` 与原生 id 仍按班次那一天算。视觉工装新增 `12/13/14` 三条屏（`makeMidnightShiftCurrent` 把种子库换成零点班）—— 原种子库的夜班是 20:30 上班（当天），这三处**一处都拍不出来**。

- **v0.8.8**（测试版 · 三张固定卡取代五档自适应）：桌面小组件从「按尺寸分五档」重做成**三张各自注册、尺寸编译期定死的固定卡** —— 4×1 本周条 / 4×3 今日卡 / 4×5 整月，全部 `resizeMode="none"`（完整口径见「关键决策与坑」里那条小组件决策）。② 旧的 `WidgetTier` 与五档版式（七张布局 + 四个渲染函数）**删净**，`onAppWidgetOptionsChanged` 一并去掉；空表态改由三张卡**共用一张 `widget_empty`**（原先挂在紧凑列表的壳上）。③ requestCode 槽位基数从 32 提到 **64**（月历一格一码要用满 42 格）：`Root(n) = B + 64n`、`Cell(m, c) = B + 64m + 1 + c`、`widgetId` 溢出上限约 3350 万。④ 新增 `app/test/widget_fixed_cards_guard_test.dart` 钉住三处没有编译期保护的约定（月历 42 格 id、manifest 里四个 receiver、三份 info.xml 的 min 尺寸与 targetCell 同源）—— **它是删掉的五档阈值护栏的等价物**。⑤ **旧小组件会消失、需重新添加**（provider 类名换了，系统认不出旧实例）；月历要 42 格位图，**已真机验过**（三张卡在 400dp/480dpi 那台机上逐张出图核对过：版式、胶囊淡染配方、今天走主色、节假日标红；跨天/跨月是把系统时间拨到 10/01 与 11/15 验的 —— 本周条翻周、今日卡跟日期、整月整张换月且 5 行/6 行都铺满；零点是**自排闹钟准点触发**重渲染、不靠打开 App，跨天后今日卡的农历与其他班组按设计**留空降级**）。**未验的两条**：空白表的空表态、以及还没打开过 App 的占位态 —— 触发它们要清掉设备上真实的排班数据，没做。

- **小窗是分档的，别把「小窗」当成一个尺寸**（v0.8.3 定）：各机型小窗的**默认**尺寸是 **400×640**（`adb shell am start --windowingMode 5` 在这台小米上给的就是它），这一档要**优先保证**：网格 + 完整信息卡，什么都不少。**高 < 480dp（`AppLayout.isShort`）时才换档** —— 那时**不画网格、只显示今日信息卡**，因为那个尺寸下两者都想要的结果是两者都看不清（200×400 里网格只剩两三行还被压扁）。信息卡在这一档用「精简但有标记」的形态（日期 + 短农历 + 班次名与时间 + 「已调班」徽章），**被调过的日子仍然看得出来**。真机验证走 `adb shell am task resize <taskId> <l> <t> <r> <b>`（`--bounds` 这台机不认），尺寸只能从 `dumpsys` 的 `mCurrentConfig` 量（系统会把窗口放大 ~1.43 倍显示，肉眼估必然估大）。见记忆 `small-window-debug-recipe`。

- **v0.8.0**（正式稳定版 · 归纳 0.7.1 起的真机反馈修复：小米权限、锁屏安全、重启不丢）：把 0.7.1~0.7.5 五个测试版收口，其中三件是**只有接上真机 ADB 才可能查清的事**。① **小米「锁屏 / 后台弹不出响铃界面」的真因不是 OS 限制** —— 此前这里记的「小米/华为免解锁弹全屏受系统限制」是**错的**（当时没接真机，见「关键决策与坑」里已更正的那条）。真因是 MIUI 把**「后台弹出界面」**（系统英文界面里叫 `Open new windows while running in the background`）单独设成一项权限：不开时 `ActivityStarterImpl` 会**静默**拒绝从后台拉起 Activity（logcat 只有一行 `MIUILOG- Permission Denied Activity`），系统把它降级成 "invisible launch" —— Activity 起来了但不显示、连 `onNewIntent` 都不走，**通知那条 `fullScreenIntent` 的 PendingIntent 也一起被拒**，所以没有「靠通知兜底」这条路。表现就是闹钟只响、不弹。它与「显示悬浮窗」「锁屏显示」是**三件不同的事**：AOSP 层的后台启动豁免走 `SYSTEM_ALERT_WINDOW`（`BAL_ALLOW_SAW_PERMISSION`），MIUI 那层拦在它后面。跳转用 `miui.intent.action.APP_PERM_EDITOR` + `extra_pkgname`（实测解析到 `com.miui.permcenter.permissions.PermissionsEditorActivity`）。**这项权限读不到状态、也没法用 adb 授予**（MIUI 的 op 常量是 `OP_BACKGROUND_START_ACTIVITY`，但没进 `AppOpsManager` 的名字表，`appops set BACKGROUND_START_ACTIVITY` 报 Unknown operation string），所以权限页只做跳转引导、不假装能检测。真机实测两项都开之后：退到后台会自动拉回前台；锁屏会点亮屏幕并顶掉 keyguard（`mKeyguardOccluded=true`）。② **响铃结束后必须撤掉 `setShowWhenLocked`** —— 它是**只进不出**的：不显式关掉，这个 Activity 会一直能盖在锁屏上，用户关掉响铃、露出来的就是 App 主界面，**锁屏下能直接看到并操作**（真人反馈的隐患）。`MainActivity.exitLockScreenMode()` 在 `stopAlarm` 里调用（滑块关闭与「再睡一会」两条路都走它）；响铃界面另加 `PopScope(canPop: false)`，堵住「按返回退回主界面」这条同类入口。③ **热启动留下的 `pendingAlarmLabel` 会让响铃界面「诈尸」** —— `handleAlarmIntent` 原先**无条件**写暂存值，而清空只发生在 `getPendingAlarm` 里，Dart 每次引擎启动只调那一次。于是 App 界面销毁重建时，Dart 把这枚**陈旧的**值当成新闹钟读出来：又弹一次响铃界面，**而且没有声音**（根本没有闹钟在响）。修法是只有 `flutterChannel == null`（真冷启动）才暂存 —— 与紧随其后的 `todo_id` 段本来就是同一套写法，闹钟这条当年漏了（复现靠「排测试闹钟 → 关闭 → 按返回结束 Activity（进程不杀）→ 重开」，日志三行见提交信息）。④ **重启重排**：班次 / 自定义 / 待办联动闹钟 / 待办提醒重启后都不丢 —— `AlarmScheduler.schedule` 与 `scheduleQuiet` 排定时**各自同步落盘**一份清单（`AlarmStore` 里是两份独立清单，id 段不重叠、取消路径各走各的；存的是**排定参数**而不是「下次该响的时刻」，因为重复闹钟开机后要按 `nextDaily` / `nextWeekly` 重算，存时刻只会存出一条已经过期的记录），开机由 `BootReceiver` 读清单重排：重复的算下一次、一次性且还没到点的按原时刻排回、**关机期间错过的一次性闹钟与提醒直接丢掉、不补**（半夜的闹钟在早上开机时突然响、一次重启冒出几条「你几小时前该交体检报告」，都比不响更糟）。**每条取消路径都必须同步删**（`AlarmScheduler.cancel`、`cancelAllNativeAlarms` 里的
