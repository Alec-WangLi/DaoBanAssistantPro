→ **0.10.22(+146) 测试版**（**动画与流畅性第二轮：真正的瓶颈在光栅线程**）起点是 v0.10.21 真机测完之后的一句「功耗降了，但流畅性感觉还是没变 —— 编辑排班界面滑起来一阵一阵地顿」。**这一轮先在真机上把「卡在哪」量清楚**（一次性探针 `app/tool/probe/`，跑完即删）：屏幕**全程 120Hz ⇒ 帧预算只有 8.33ms**；**build（UI 线程）p50 只有 0.52ms** —— 上一轮做的正是 UI 线程（436 → 42 个 widget/帧），**那里已经没剩什么可优化**；而 **raster（光栅线程）p50 4.19ms、p90 13.10ms**、13.4% 的帧掉拍。**这就是「功耗降了、流畅没变」的原因：省下的是 CPU，掉的是 GPU 的帧。** 再往下量：把 `BackdropFilter` 整条摘掉（**填充配方一个字节不动**）raster p90 从 13.10 → **2.37ms**、掉拍 13.4% → ~3%；而**只留模糊（σ 仍 18）是 7.92、只留饱和度矩阵是 8.21** —— **贵的是那条 backdrop 渲染通道本身，不是滤镜算什么**（σ 调小、矩阵简化都不解决问题）。于是把「糊不糊」与「用哪支填充」拆开（`enableBlur` → `translucentFill` + 新的 `blurBackdrop`），**`GlassTile` 恒不挂 `BackdropFilter`**（全仓仍开着模糊的 8 个调用点全是它，所以一处收口）；`GlassBlur`（按钮 / 提示条 / 液态轨道 / 导航胶囊）一律不动。观感是**量过**的：同机同包连渲两遍噪声本底为 0，而去掉模糊之后全 app 除响铃时钟假差异外最大差异 **16/255**、占比 ≤0.07%，并排出图看不出区别 —— **这一条不是取舍，是白捡**。顺带收掉上一轮明确留下的：`appSettingsProvider` 收窄成 `select`（拨一下触觉开关不再重建整个 App）、`L10n` 的 `DateFormat` 按 (模式, 语言) 缓存、光晕暂停判据从「手指按着」改成「这一帧有没有东西在产出」（并带上换月）、`WidgetService.push` 加 in-flight 守卫、`AlarmStore` 内存镜像（不再反复解析整份清单；**合并落盘那一半被最终审查否掉了**，见下）、**响铃 15 分钟超时自停**（走与用户手动关闭完全相同的拆除路径）、小组件刷新默认退非精确。**数字**：测试 807 → **824**，工装 349；四个 tab 的 raster p90 全部落进 2.7ms 以内（日历 10.36 → **2.26**、闹钟 9.77 → **2.27**、待办 6.48 → **2.50**、我的 3.45 → **2.66**）、超预算的帧从 1~14.5% 降到 0~1.4%。⚠️ 两处**没做到**：编辑排班页的 raster p90 只到 **5.98ms**（spec 目标是 ≤4）—— 归因是**液态档那几件**（分段器 / 开关的玻璃轨道，用户开着液态玻璃），但**掉帧已经落到地板**（3.2% vs 2.8%，而地板 p90 只有 2.15ms ⇒ 剩下的掉拍不是 raster 造成的），再往下走只买到余量、买不到流畅度，**交用户拍板**；以及 `cancelAllNativeAlarms` 扫 ~1500 个 AlarmManager 取消、占掉一次重排约 600ms —— 不在本轮范围内。真机复测（编辑排班页滑动 + 响铃自停）通过。
