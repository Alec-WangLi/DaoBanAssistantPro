- **v0.13.5（测试版 · 修导入后重启）**
  真机验证 v0.13.4 的导出/导入时发现：点「立即重启」后 `Process.killProcess` 把进程杀掉，新 Activity 还没建起来，系统不会替我们拉起。Android 14+ 还会把「进程已死 + PendingIntent 拉起 Activity」判成后台启动并 `BAL_BLOCK`（logcat 原文 `Background activity launch blocked`），AlarmManager 也救不回来。最终做法：**不杀进程**，用 `FLAG_ACTIVITY_NEW_TASK | FLAG_ACTIVITY_CLEAR_TASK` 从当前前台 Activity 启一个新任务 —— 旧 Activity 销毁、旧 FlutterEngine 释放，新 Activity 建新引擎、Dart `main()` 再跑一遍，导入的库在打开数据库之前完成替换。整个过程都在前台，不受后台启动限制。
  同时，恢复 prefs 后把 `lastSeenVersion` 写成当前版本、`onboarded` 置 true —— 否则备份里的旧版本号会让导入后第一眼弹出「版本更新」。
  真机重验：导出 → 改主题色为粉 → 导入 → 立即重启 → App 自动重开、主题色恢复成备份里的青色、排班仍在。

- **v0.13.0（正式稳定版 · 归纳 0.12.1~0.13.0 十一个测试版）**：这一版把「重复待办」这条线收口，并刷新仓库门面。
  **① 小组件跟随系统深浅色**：三张卡（本周条 / 今日卡 / 整月）在 App 主题为「跟随系统」时，系统切深浅色会当场跟着变，App 进程不在也一样。做法是 API 31+ 文字走 `setColorInt` 日夜双值、背景走同名 `drawable-night`，由桌面重新应用 RemoteViews 时按当时的 `uiMode` 解析；API < 31 没有 `setColorInt`，仍走烤死路径（只翻背景不翻字比不翻更糟）。manifest 那条 `CONFIGURATION_CHANGED` 实测收不到（Android 8+ 隐式广播限制），已删；`MainActivity` 的运行时接收器保留作 App 活着时的兜底。真机（Redmi K90 Pro Max / Android 16 / HyperOS）把 App 强停后切深浅色，三张卡逐张截图验过、logcat 无本 App 日志。
  **② 重复待办行挂发生日**：跨午夜班次的行从「提醒落地日」改回「发生日（班次那天）」；提醒仍按 `alarmDayAnchor` 落在前一天 / 当天 / 次日；副标题写「班次名 · 次日 00:00」。旧版写在显示日的行与旧水位线在升级时**一次性**迁回 / 回退（prefs 键 `recurringRowDayMigratedV1`，覆盖归档行；候选不唯一时不动）。

  **④ 排班箭头去掉**：排班管理里每套方案的 `scheme-open-hint` 与编辑排班的值行箭头（`crew-*-chevron` / `my-cycle-start-chevron` / `monthly-day-chevron`）按用户 2026-11-09 的要求去掉；整行仍可点。规则层同步更新为「六处例外」。
