- **v0.13.15（测试版 · 修重复待办改起点 / 闹钟可诊断 / 日志瘦身）**
  **① 修「改『从这天起』不生效」**：2026-11-17 用户真机报「今天 11/17，我选的是 11/19 开始，它还是提醒」。把用户手机的备份导出来解包看 sqlite，证据是「系列 `start_date` = 11/17、它那条行 = 11/19」—— 编辑弹窗里改日期**只挪了当前那一条**，系列的起点纹丝不动，而提醒（`upcomingFireTimes`）是按系列起点算的。根因在 `_EventFields.commit` 编辑分支的 `startDate: s.startDate`：那句是 v0.9.14 防「改周期时把起点拽到今天、导致 `occurrenceOnOrBefore` 回退对齐失效」的，顺带把「用户主动改起点」也吞了。改法是**按「用户是否真的动过日期行」分叉**（`dateChanged`）：动过才写回 `start_date`，并把未完成行挪到「新起点之后的第一次」（规则无解则删掉那条幽灵行）；没动过保持原行为，v0.9.14 那条回归护栏照旧。
  **② 闹钟「偶尔不响」补证据链**：报障是三星 One UI 8.5 / Android 16，没有日志可查 —— `AlarmReceiver.onReceive` 那行从前是 `info`（只进 Logcat，不落盘，与 v0.13.12 同一个坑）。现在把链路三个关键点都改成 `diagnostic`：收到闹钟、`AlarmRingService` 前台通知建好（并把 `startForeground` 包进 try/catch，Android 14+ 的 FGS 校验失败从此留痕）、`AlarmSound` 真的开始播放；`BootReceiver` 的重排结果也落盘。于是「没收到（系统取消）」「收到了服务没起来（后台限制）」「起来了没声音（音源）」三种能从日志里分开。`AlarmLog.deviceState` 补 `device=厂商/型号`、`ignoreBatteryOpt`、`notifications`。
  **③ 三星机型指引**：「我的 → 权限 → 后台与开机」在三星机型上多一行「休眠应用（三星）」，跳到设备维护的电池页 —— 进了「睡眠应用 / 深度休眠应用」的 App 会被系统**连闹钟一起取消**，正是「几天偶尔漏一次」的典型成因。判定走 `ComponentName` 解析（`com.samsung.android.lool` / `com.samsung.android.sm` 两个都试），解析不到就不显示。
  **④ 日志瘦身**：冷启动那条振动能力探针（v0.13.10 排查遗留）改为只进 Logcat，只有「没有振动器」这种真问题还落盘 —— 用户 2026-11-17 明确要求把早先那轮排查的残留清掉。
  **⑤ 数字**：新增 3 条用例（改起点生效 / 不动日期行不改起点 / 新建选未来日期），单测 1353 → **1356**；`flutter analyze` 0 issue；版本 `0.13.14+201` → **`0.13.15+202`**。

- **v0.13.13（测试版 · 修「系统铃声选了不生效」）**
  v0.13.12 发出去后，报障用户反馈「还是选不上铃声」，并贴来日志：`AlarmSound: 自选铃声用不了，回落到内置铃声: content://media/external/audio/media/12837?title=Go%20Time&canonical=1`（11-14 与 11-15 两次响铃各一条）。
  **根因换了一条**：这不是文件选择器的问题（那条 v0.13.12 已修）。他把自己的 mp3「Go Time」设成了**系统铃声**，于是它出现在 App 的「系统铃声」列表里（`RingtoneManager` 按 `TYPE_ALL` 列）；选中时旧代码把这个 `content://media/...` **原样存进 prefs**。响铃那一刻由前台服务去读 —— 没有媒体读取权限 / 那条媒体已不在媒体库时打不开，`AlarmSound` 只能静默回落内置铃声。**失败发生在半夜、没有界面能报错**，所以他一直以为「没选上」。
  **改法**：① 选系统铃声也**复制进私有目录**（新增通道 `importRingtone`，复用 `copyRingtoneIntoPrivateDir`），失败则当场提示并**保留原设置**（不再存一个永远不会响的值）；② 启动时迁移一次旧值：`content://` → 尝试复制，读不到就删键退回内置，两种情况都写日志；③ **诊断落盘**：`ringtone pick:` 从 `info` 改成 `diagnostic`（`info` 只进 Logcat，上次报障就是因为这行不落盘，贴来的日志里完全没有 pick 记录）；④ `AlarmSound.tryCreate` 的 catch 以前整个吞掉，现在把 `scheme://authority + 异常类型 + 消息` 写进日志 —— 下一次能直接看出是没权限、文件没了还是格式不支持。
  **验证边界**：报障机不在手上，真机复测靠下一版日志（`AlarmSound: 音源打不开` 那行会给出确切原因）。本机（同一套 AOSP DocumentsUI）复测了「从文件中选择」的完整路径。单测 1317 → **1318**。

- **v0.13.11（测试版 · 修 HarmonyOS 3.0 冷启动闪退）**
  用户 2026-11-11 反馈：荣耀 10（COL-AL10）与畅享 20 Pro（DVC-AN20）装上 v0.13.10 后**一开就闪退**，v0.13.9 正常。
  **根因**：v0.13.10 新增的 `Haptics.logCapabilities()` 在 `configureFlutterEngine`（冷启动必经之路）里同步执行，无条件调用 `Vibrator.areEffectsSupported(int...)` —— 那是 **API 30（Android 11）** 才有的公共 API（`api-versions.xml` 的 `since` 写着 30；API 26~29 上只有一个返回 `boolean[]` 的隐藏版本，签名对不上）。两台机器都是 HarmonyOS 3.0，底子 Android 10（API 29），于是抛 `NoSuchMethodError`；它属于 `Error`，整个文件写的都是 `catch (Exception)`，接不住 → 未捕获异常冒到主线程 → 白屏后退出。v0.13.9 的启动路径没有这个调用，所以正常。
  **修法**：① 门槛逐条按 `api-versions.xml` 校准 —— `areEffectsSupported` / `areAllEffectsSupported` / `areAllPrimitivesSupported` / `startComposition` / `VibrationEffect.Composition` 都是 30（v0.13.10 把原语门槛写成了 31，反而漏掉了 API 30 这一段），`PRIMITIVE_THUD` 31，`createPredefined` 29；② 低于门槛一律不调，`logCapabilities` 在 API 30 以下只记「未知」；③ **所有 `catch` 从 `Exception` 改成 `Throwable`**（`play` 入口也整段兜住），缺 API 的 `Error` 从此不会再冒到主线程；④ 顺手补上 Android 8 / 9 的路径：那两版没有 `createPredefined`，原来点一下就会抛同样的 `NoSuchMethodError`，现在改发 20ms 单次。
  **验证边界**：本机是 API 34，复现不了「API 29 上崩」；两台真机由反馈用户装 v0.13.11 验。单测 1294 不变（没动 Dart）。

- **v0.13.5（测试版 · 修导入后重启）**
  真机验证 v0.13.4 的导出/导入时发现：点「立即重启」后 `Process.killProcess` 把进程杀掉，新 Activity 还没建起来，系统不会替我们拉起。Android 14+ 还会把「进程已死 + PendingIntent 拉起 Activity」判成后台启动并 `BAL_BLOCK`（logcat 原文 `Background activity launch blocked`），AlarmManager 也救不回来。最终做法：**不杀进程**，用 `FLAG_ACTIVITY_NEW_TASK | FLAG_ACTIVITY_CLEAR_TASK` 从当前前台 Activity 启一个新任务 —— 旧 Activity 销毁、旧 FlutterEngine 释放，新 Activity 建新引擎、Dart `main()` 再跑一遍，导入的库在打开数据库之前完成替换。整个过程都在前台，不受后台启动限制。
  同时，恢复 prefs 后把 `lastSeenVersion` 写成当前版本、`onboarded` 置 true —— 否则备份里的旧版本号会让导入后第一眼弹出「版本更新」。
  真机重验：导出 → 改主题色为粉 → 导入 → 立即重启 → App 自动重开、主题色恢复成备份里的青色、排班仍在。
